Procedural Graphs: Self-Evolving Execution Structures for LLM Agents

📰 Latest · 2026-09-13 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-13

Source: arxiv · 2026-09-08
Link: https://arxiv.org/abs/2609.09153

A drop-in procedural-memory layer for agents: encode 'what to do next' as a directed (procedure, relation, procedure) graph, localize the agent on it each step, and let a validation-gated refiner rewrite the topology from failed-vs-successful trajectories — first or joint-first in 21 of 24 model-benchmark settings without touching model weights.

Executive summary

The Procedural Graph (PG) is a directed, attributed graph whose nodes abstract tools/skills/reasoning steps and whose edges carry condition/guidance/pitfalls attributes, making admissible action transitions explicit instead of implicit in a growing ReAct log. At inference the graph is frozen: the system locates the agent's most recent procedure as a node, extracts its 2-hop outgoing neighborhood, and a guidance LLM turns that subgraph plus the last 3 trajectory steps into step-level guidance appended to the solver prompt. Offline, a closed loop rolls out training tasks, has an LLM refiner contrast high- and low-scoring traces to propose Add/Delete edits, runs structural validation and a held-out validation gate, and keeps rejected candidates as negative evidence.

Topology: what the graph actually is

A PG is a directed attributed graph of triplets (procedure, relation, procedure); an edge asserts that a node is admissible after another node under a relation. Nodes abstract a tool function, a skill, an internal reasoning step, or a task status.

  • Edge attribute schema: condition, guidance, pitfalls
  • Worked example edge: (cash_flow_forecast, LEADS_TO, fund_raising_request) with a runway-below-buffer condition
  • The graph can be initialized from an expert prior or from a minimal skeleton

Retrieval at inference: locate, extract, generate

Rather than top-k similarity retrieval over isolated attribute snippets — which can return guidance for 'submit' while omitting the preceding 'check_answer' verification — PG retrieves a connected neighborhood so the solver sees the action together with its procedural prerequisites.

  • h=2 hop outgoing neighborhood, trajectory window w=3, fallback to the full graph when node matching fails
  • The guidance LLM names the immediate goal plus errors to avoid; the solver still chooses its own action
  • Guidance model and refiner always share the solver's LLM; greedy decoding throughout

Self-evolution loop and its verifier grounding

Each round starts from the retained graph. The refiner identifies repeated error loops in failures and shortcuts in successes and emits Add/Delete edits; attribute revision is delete-then-re-add. Candidates pass two gates.

  • Structural gate: rejects malformed edits, invalid node/relation types, missing edge endpoints; requires a directed path from every node to a zero-out-degree terminal node
  • Tool-catalog membership of action node names is only a refiner-prompt requirement, NOT enforced by the validator
  • Validation gate: accepted iff mean validation score >= the cached score of the retained graph (ties accepted)
  • Rejection memory feeds rejected candidates back to the refiner as negative evidence

Results across benchmarks and models

Seven benchmarks and four LLMs, all sharing an identical ReAct solver and the same training trajectories as the baselines (MemoryBank, RAP, ExpeL, AutoGuide, AWM, KnowAgent).

  • 19 wins, 2 ties, 3 losses against the strongest per-setting baseline (sign test p = 4.3e-4)
  • Largest margins: BFCL v3 67.00% vs 58.00%; GDPval 78.78 vs 71.37; tau-bench 80.00% vs 73.04%
  • HotpotQA is the weak case: -0.90 to +1.30 points
  • PG beats every baseline under all four LLMs on GDPval and BFCL v3

Long-horizon behavior and construction-strategy ablation

EnterpriseArena runs up to 132 monthly financial decisions with three undisclosed crises and a 1-6 month capital delivery delay; PG's mechanism is anticipatory fundraising, not simply more tool calls.

  • Survival: 44.0% -> 58.0% (Claude Sonnet 4.6), 6.0% -> 34.0% (Gemini 3.1 Pro), 26.0% -> 40.0% (Grok 4.1 Fast)
  • Gemini 3.5 Flash tool calls per month drop 18.94 -> 12.53 while score improves
  • Capital raised: $0.00M (Flash baseline) vs $9.39M (PG Flash) and $30.11M (PG Grok 4.1 Fast)
  • Validation survival 0% -> 45% -> 80% -> 90%; returned graph 85.0% test survival vs 0.0% baseline (Fisher exact p = 2.6e-8)

Efficiency: localization is the load-bearing choice

An ablation on Gemini 3.5 Flash separates how much graph the agent sees from how it is consumed. Full-graph generative guidance is actively harmful on embodied execution.

  • Localized generative beats the best alternative by +2.0 (MultiChallenge), +6.8 (GDPval), +9.0 (ALFWorld) points
  • Localization cuts tokens vs full-graph generative by 70.9% (ALFWorld), 18.1% (GDPval), 14.8% (MultiChallenge)
  • Solver steps fall 28.20 -> 18.57 (GDPval), yet total tokens stay 33.4% above the no-graph baseline
  • Appendix D.1 reports a 45.7% reduction in parsing failures

Key findings

  • PG ranks first or joint first in 21 of 24 model-benchmark settings (sign test p = 4.3e-4).
  • Localization is what makes the graph help: subgraph+generative beats full-graph generative by +9.0 points on ALFWorld (81.53 vs 54.48) with 70.9% fewer tokens; full-graph generative is worse than no graph at all (54.48 vs 72.58).
  • Self-evolution from scratch beats hand-crafted graphs on HotpotQA (66.30 EM / 78.79 F1).
  • The loop repairs a harmful prior: an expert graph dropped MultiChallenge from 87.50% to 58.93%, and iterative evolution recovered it to 92.86%.
  • On EnterpriseArena the returned graph reached 85.0% test survival vs the baseline's 0.0% (Fisher exact p = 2.6e-8).
  • Guidance buys steps, not tokens: GDPval solver steps fell 28.20 -> 18.57 while total tokens stayed 33.4% above baseline.

Notable quotes

PG ranks first or joint first in 21 of 24 model–benchmark settings.
Guidance uses the localized neighborhood when matching succeeds and the full graph otherwise, together with a recent trajectory window.
The gate retains candidates whose measured validation score matches or exceeds the cached score of the current graph.
The remaining checks require valid edge endpoints and a directed path from every node to a terminal node, defined by zero out-degree.

Limitations

  • Generative guidance adds an LLM call per decision step; total tokens stay 33.4-55.4% above the no-graph baseline even when steps drop.
  • The EnterpriseArena search uses only 20 episodes per split, so accept/reject decisions turn on one or two episodes.
  • Gains are uneven: HotpotQA margins range from -0.90 to +1.30 points, and PG loses to ExpeL on ALFWorld under Grok 4.1 Fast.

Open questions

  • Do learned procedural graphs transfer across solvers and tool interfaces, or are they overfitted to the LLM that generated them?
  • How should a verifier ground node names against a live tool schema, given the structural validator does not check tool-catalog membership?
  • With edits limited to Add/Delete and the gate accepting on ties, how much of the search is drift versus genuine improvement?
