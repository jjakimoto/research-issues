Progressive Agent Skill Generation via Reinforcement Learning (Skill-alpha)

📰 Latest · 2026-08-04
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-04

Source: arXiv cs.LG (CUHK / LIGHTSPEED) · 2026-08-03
Link: https://arxiv.org/abs/2608.01678

Skills get a real training signal for the first time: a 'rollback reward' re-runs an anchored query under the skill before and after each edit, so the editor is rewarded only when the edit actually improved worker behavior — and removing that reward collapses performance back to SFT-only levels.

Executive summary

Skill-alpha trains a skill-editing policy (not the worker) with GRPO over a five-action edit space (Create, Update, Merge, Prune, Noop) on a single evolving SKILL.md artifact. The credit-assignment problem — a skill has no intrinsic correctness label — is solved by a rollback reward: for each edit, the same anchored query is answered under the pre-edit and post-edit skill, and reward is 1 only if the edited version scores higher. It unifies document-to-skill and experience-to-skill generation in one learned editor and beats eight baselines on CL-Bench, SpreadsheetBench and tau2-bench. Notably, on CL-Bench every competing skill-generation baseline scores *below* having no skill at all.

The problem: skills have no label

LLM agents are augmented with reusable procedural modules injected into the worker's context, but building them automatically relies on hand-designed heuristics that must be re-specialized per evidence type. A skill's worth shows up only indirectly in downstream agent behavior, making it an execution-grounded credit-assignment problem.

  • The trainable object is the skill-editing policy; the worker policy is fixed.
  • Skill construction is sequential over T evidence units, each step producing an edit action applied to the current artifact.
  • Documents and execution traces are handled by the same editor, unifying two previously separate pipelines.

The rollback reward

Each edit step is paired with an anchored query drawn from the same evidence source plus a benchmark-specific verifier. The worker answers that query under the pre-edit skill (control) and post-edit skill (edited); reward is 1 for a non-Noop edit if the edited score exceeds the control, and 1 for Noop only if no other sampled valid edit beat the control.

  • Anchors are drawn from unsuccessful or partially successful trajectories (score < 1) and excluded from that state's evidence; no test query is ever used as an anchor.
  • Deterministic quality gates reject malformed schemas, missing targets, duplicate headings, empty post-edit skills, disguised create/merge, and Noop on an empty skill — reward 0 without benchmark evaluation.
  • Verifiers: a GPT-5.5 rubric judge for CL-Bench, direct environment feedback for SpreadsheetBench and tau2-bench.

Training setup

Base model is instruction-tuned Qwen3-8B, warm-started by SFT on 6,481 filtered examples synthesized by DeepSeek-V4-Pro, then GRPO with group size 8, actor LR 5e-7, temperature 1.0, entropy coefficient 0.001, KL regularization disabled in practice, and a 40,960-token model length.

  • RL data: 2,048 local editing states (768 CL-Bench, 512 SpreadsheetBench, 256 per tau2 domain).
  • SFT action mix: Create 33.24%, Noop 24.83%, Update 19.10%, Prune 14.87%, Merge 7.96%.
  • RL worker is always GPT-4o; Claude-Sonnet-4.5 is the transfer worker at evaluation.

What the ablations say

Removing the rollback reward drops results to roughly SFT-only levels across all three benchmarks, with a Noop-dominated flat-reward policy. Merge and Prune matter most on workflow tasks (a 16.66-point tau2 drop), while evidence ordering barely matters compared to evidence batch size.

  • Skills often hurt: on CL-Bench with GPT-4o, all five baselines (7.01, 7.11, 6.37, 7.07) fall below the 8.57 no-skill average; only Skill-alpha (10.38) exceeds it.
  • Gains are larger under GPT-4o — the backbone that generated trajectories and computed rewards — than under the Claude-Sonnet-4.5 transfer worker.
  • Batch granularity swings tau2 from 47.50 (1 evidence unit) to 55.83 (4 units) to 48.33 (8 units).

Key findings

  • The rollback reward is the load-bearing component: removing it drops results to 3.68 / 17.00 / 46.67, essentially back to SFT-only (3.46 / 15.50 / 44.17), with a Noop-dominated flat-reward policy.
  • On CL-Bench with GPT-4o, every skill-generation baseline scores below the 8.57 no-skill baseline; only Skill-alpha (10.38) beats doing nothing.
  • The largest margin is in the experience setting: tau2 average 55.83 versus 49.17 for the best baseline (SkillPro), and SpreadsheetBench 18.00 to 27.50.
  • Merge and Prune matter most for workflow tasks — dropping them costs 16.66 points on tau2 (55.83 to 39.17), a bigger hit than dropping Noop.
  • Evidence granularity beats evidence ordering: shuffling or reversing moves tau2 only within 51.67-57.50, but batch size swings it 47.50 (1 unit) to 55.83 (4 units) to 48.33 (8 units).
  • Gains are noticeably larger under GPT-4o — the reward-computing backbone — than under the Claude-Sonnet-4.5 transfer worker, and Skill-alpha is not best in every column.

Notable quotes

We use a rollback reward to provide supervision for these edit decisions.
The remaining challenge is edit-level reward assignment.
The resulting checkpoint is then used to initialize GRPO.
The effect of order is visible but not decisive.

Limitations

  • The reward/verifier interface stays benchmark-dependent — each benchmark needs its own rubric or environment hook — and the skill representation is text-only Markdown.
  • The reward is a coarse binary win indicator: ties and degradations both score 0, so a single comparison is a noisy sample of the win probability rather than a signed estimate of improvement.
  • Gains transfer imperfectly: results under Claude-Sonnet-4.5 are markedly smaller than under GPT-4o, the backbone used to generate trajectories and compute rewards.

Open questions

  • Can a general, non-benchmark-specific verifier supply the rollback signal, removing the per-benchmark rubric requirement?
  • Would repeated comparisons (variance reduction) or a signed improvement estimate beat the binary win indicator?
  • Do longer-horizon training signals beat single-step local rollback comparisons for skills whose value only appears many tasks later?
