    RSIAgent: Autonomous Exploration for Recursive Self-improvement in New Environments

    ← Go backDeltaSelect: Affordable A/B Testing for Coding AgentsNextSoK: Trading Agents or Market Crashers? Dissecting… →
    📰 Latest · 2026-09-18 Full Article

    Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
    Date: 2026-09-18

    Source: huggingface-daily-papers · 2026-09-14
    Link: https://arxiv.org/abs/2609.15364

    A training-free curriculum/actor/verifier loop that explores a new software environment on its own, distills execution-grounded lessons into a frozen memory, and lifts open-source models (GLM-5.3 + Kimi-K3) to 78.98 partial on OSWorld 2.0 and 84.82 on Agents' Last Exam — above GPT-6 Astra — with no weight updates. A concrete blueprint for the memory half of an autonomous research system, including the exact information boundaries that keep the verifier honest.

    Executive summary

    RSIAgent (Aether AI / UCSD / UIC, 49 pages) is a training-free multi-agent framework for recursive self-improvement in unfamiliar digital environments. Three roles — a curriculum agent that decides what to explore, an actor agent that executes code-as-policy programs and owns memory updates, and an isolated verifier agent grounded in environment feedback — run a broad-then-deep exploration schedule (BRS: parallel waves of diverse practice projects; DRS: sequential, escalating target-conditioned practice). The accumulated memory is frozen (file-tree hash recorded) and reused at test time with curriculum and writeback disabled. On OSWorld 2.0 (82 offline tasks) partial rises 71.97 to 78.98 and binary 37.80 to 42.68; on ALE Near-term (67 tasks) partial 83.75 to 84.82 and binary 49.25 to 50.75.

    Topology: curriculum / actor / verifier with hard information boundaries

    Three roles run in separate contexts and the boundaries are the design, not an implementation detail. The actor sees the task, the environment, execution feedback and the persistent memory, and emits programs plus (post-verification) memory updates and a 'learning diagnosis'. The verifier sees only task requirements and the candidate environment — actor-private memory, reasoning and execution logs are hidden — and emits a verdict with no durable memory authority. The curriculum agent sees the target query, completed outcomes, actor learning diagnoses and a disposable copy of memory; it emits practice instructions and continue/stop decisions but never grades candidates or edits canonical memory.

    • Actor = GLM-5.3 by default; verifier and curriculum = Kimi-K3 in two separate persistent contexts
    • Action space is code-as-policy: complete Python or Bash programs; extra primitives look (visual evidence), ask (user channel), done (read-only checks)
    • Curriculum context persists within an exploration lineage; verifier context persists across candidate revisions within one target attempt but not across projects
    • One stall-triggered role switch is permitted on the target harness when budget remains

    Verifier grounding: execution-grounded, checkpoint-protected, three-valued

    Verification is deliberately not LLM-as-judge-over-the-actor's-story. The verifier inspects the candidate artifact and environment directly — execution results, interface states, observable evidence — using reset-and-replay or checkpoint restoration so its own probes cannot mutate the submitted artifact. Practice projects get exactly one grounded PASS/FAIL with no same-project repair cycle; target attempts additionally allow UNVERIFIED, which requests more evidence rather than counting as either a success or a failure example. The official benchmark evaluator is invoked only after the actor-verifier loop closes.

    • Reference evaluator uses GPT-5.4 where model-based grading is required; the user simulator uses GPT-4o. Both are outside all agent contexts.
    • The paper's own failure analysis flags the verifier as the weak link: local PASS can be granted despite unsupported field values or rubric discrepancies, and that mistake then seeds memory.

    Memory construction: experience-owned, sequentially committed, no schema

    Memory is a collection of actor-authored files with no required schema, file count, or length. The actor that produced an experience is the only writer for it: after a grounded verdict its existing context receives the full verifier report and runs distillation (procedures, constraints, failure lessons) then reconciliation (check against older entries, revise contradictions, qualify unsupported conclusions). Only completed learning updates are promoted to the canonical memory bank; work-phase edits are discarded.

    • BRS decouples parallel acquisition from ordered commit: every project in a wave starts from the same immutable pre-wave snapshot and cannot see siblings; once all verdicts land, actor contexts resume one at a time in curriculum-authored order
    • The next wave is chosen only after commits finish, so the curriculum reacts to what was actually retained, not just what was verified
    • Failed projects can contribute evidence without being recorded as verified successes

    Exploration schedule, stopping, and budgets

    BRS is a parallel breadth phase with a nominal budget of eight projects and up to four concurrent; the budget is checked only between complete waves, so realized project count can exceed eight. DRS is sequential and target-conditioned: attempt the target with BRS memory, get a grounded outcome, consolidate, then let the curriculum agent choose escalating practice; after practice the target is retried in a reset environment. Under the default curriculum_review policy a target PASS alone does not end DRS — only a curriculum decision that further practice is not worthwhile does.

    • Execution safeguards bound runs, not rounds: OSWorld reference target actor gets a 500-iteration limit and a 36,000-second watchdog per run; practice/curriculum configs get 2,000 iterations and 86,400 seconds; each target script call is capped at 600 seconds
    • Sampling: temperature/top-p pinned; 65,536-token response limit per primary model call
    • Frozen-memory eval records the memory file-tree hash, copies it in, disables curriculum decisions and host writeback, and checks memory integrity
    • Unresolved verification and infrastructure failures block phase advancement rather than being labeled convergence

    Results, ablation, and generalization to game development

    RSI improves both benchmarks and the two-stage ordering matters: broad-only beats baseline on all four ablation tasks, while deep-only from empty memory actually falls below baseline on two. Per-task RSI curves over steps 0-8 show discrete jumps rather than smooth gains. On 40 GameCraft-Bench tasks RSIAgent improves overall quality for every base generator, whereas the Play2Code baseline degrades an already-strong Codex+GPT-5.5 game (52.77 to 51.05).

    • Reporting is explicitly not matched-protocol: the OSWorld RSI row replaces baselines with 41 non-diagnostic RSI results; ALE combines 19 RSI scores with 48 retained baselines
    • T082 had a setup failure with no valid official score and is counted as zero in both OSWorld aggregates
    • Game setup: GLM-5.3-Flash as development actor+verifier, Qwen3.8-27B as playtester and final evaluator, <=15 improvement rounds, <=26 tool calls per actor round

    Key findings

    • OSWorld 2.0 partial rises 71.97 to 78.98 and binary 37.80 to 42.68 with RSI; ALE partial 83.75 to 84.82 and binary 49.25 to 50.75 — all without touching model weights.
    • RSIAgent exceeds GPT-6 Astra's partial by 6.38 points on OSWorld and 2.56 on ALE, but loses on ALE binary (50.75 vs 52.24), so the advantage is graded progress, not full-task completion.
    • Stage ablation on four tasks: full RSI 74.54% mean vs 65.52% broad-only vs 56.50% deep-only; deep-only from empty memory falls BELOW baseline on two tasks — breadth must precede depth.
    • Budgets are per-run, not per-round: 500 actor iterations + 36,000s watchdog on the OSWorld target; 2,000 iterations + 86,400s for practice/curriculum; 600s per target-script call; 65,536-token response cap.
    • BRS parallelism is bounded at 4 concurrent projects against a nominal 8-project budget checked only between complete waves.
    • Aggregates are partly inherited, not fully re-run: the OSWorld RSI row contains 41 actual RSI results with the rest retaining baselines; ALE is 19 RSI + 48 baseline scores.
    • Three named failure mechanisms — insufficiently targeted exploration, incomplete verification, unreliable memory consolidation — compound, letting an unverified interpretation become a reusable rule.

    Notable quotes

    The verifier agent is isolated from the actor agent’s private reasoning and memory, which helps reduce correlated errors during evaluation.
    Every project in a wave begins with the same immutable pre-wave memory snapshot and cannot observe sibling work or outcomes.
    In the audited cases, the verifier agent returned PASS despite unsupported field values or artifact discrepancies under the official rubric.
    Full RSI reaches a mean score of 74.54%, compared with 65.52% for broad-only exploration and 56.50% for deep-only exploration.

    Limitations

    • Recursive self-improvement requires substantial extra test-time exploration and practice; the paper reports iteration/watchdog caps but no dollar or token cost accounting for a full lineage.
    • The model-based verifier can issue incorrect PASS judgments that propagate into later exploration and memory updates — the authors' own audits show accepted mistakes becoming reusable rules.
    • Cross-system comparisons are not matched-protocol, the RSI aggregate rows mix fresh RSI scores with retained baselines, and the experiments do not isolate every component's contribution.

    Open questions

    • How should the curriculum agent be steered to challenge uncertain knowledge rather than merely diversify practice, given that untested areas left bad rules resident in memory?
    • Can verification be made complete against a requirement checklist — rather than 'an output was produced' — without access to the official rubric?
    • Does memory that preserves the conditions and uncertainty of each experience transfer to non-desktop domains such as AI-for-science tooling and long-horizon games?
