    Agora: Git as Shared Memory for Collective AutoResearch

    📰 Latest · 2026-09-21 Full Article
    Read full article →View on GitHub

    Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
    Date: 2026-09-21

    Source: arxiv · 2026-09-16
    Link: https://arxiv.org/abs/2609.18094

    NVIDIA turns the research record itself into the coordination layer: every claim is an immutable Git commit in an append-only DAG, and 13 unmanaged coding-agent sessions used only that shared graph to drive a weight-transfer benchmark from 3.39 to 1.899 bpb over ~12 days with one human intervention. If you are building an autonomous researcher, the lesson is that the durable shared state, not the individual agent, was the binding constraint.

    Executive summary

    Agora is a coordination substrate for many independent research agents: each contribution (result, insight, hypothesis, verification, report) is an immutable Git commit whose parent edges mean 'builds on', with a derived SQLite index exposing the frontier, neglected branches, and verification status. There is no planner, no shared conversation, filesystem, or runtime — the Git history is the only state passed between workers. The authors report the first sustained run: 13 coding-agent sessions (Claude Opus 4.7 via Claude Code, GPT-5.5 via Codex) published 1,703 contributions over 11 days 19 hours on a no-training weight-transfer task, reaching 1.899044 bpb from a 3.3923 random baseline (62% of the gap to a trained GPT-2 124M), with 165 independent reproductions and zero failed verifications. The paper is explicit that the run is not a controlled experiment and proposes a matched four-arm evaluation to settle whether shared research state actually improves discovery per unit of compute.

    System topology: no generator/verifier/reviser pipeline — a market of peers around a DAG

    Agora deliberately does not prescribe an end-to-end researcher. There is no orchestrator, no role graph, no assigned tasks. Every participant runs the same loop autonomously: call `analyze`, pick a parent node, fetch and check out that exact commit, make ONE change, evaluate, commit everything needed to reproduce, publish with description + metric, then post any insight/hypothesis/verification, and analyze again. Roles are expressed as commit tags rather than as agents.

    • Reserved contribution tags: setup, result, insight, hypothesis, report, verification, endorsed, wip — each with a scoring weight and a key rule.
    • `verification` must name exactly one target and can never be one's own work; `endorsed` and `wip` are excluded from fitness/score propagation.
    • Storage is Git (canonical, content-addressed, append-only); SQLite is a rebuildable derived index; prototype is a Go service + CLI (15 command groups) + Next.js UI + 26 HTTP routes.
    • Two publication paths: light (server makes the commit) and heavy (local commit, Git bundle upload, server validates).
    • Participants share no filesystem, model, conversation, or manager — only the graph.

    Search structure: diversity-aware UCB with explicit exploit/explore slots

    The authors argue a leaderboard is 'a good exploitation signal and a poor map'. `analyze` therefore returns many views at once: metric leaders, most-built-on nodes, leaves, promising-but-underexplored results, unverified results, contested verifications, open hypotheses, recent activity, tags, contributors. Once embedding coverage suffices, single-link semantic clustering over descriptions adds cluster statistics and a frontier of promising nodes in small clusters.

    • Clustering uses a cosine threshold by default and caps pairwise analysis at the 5,000 most recent contributions.
    • Candidates ranked by a diversity-aware UCB (quality percentile + follow-on counts − near-duplicate penalty); the exploration constant grows when the metric distribution bunches near its best.
    • Three presented slots: exploit (refine leaders), explore known (extend promising work in a thin cluster), explore novel (untouched nodes in tiny clusters).
    • The paper states the split matters more than the exact score — it makes monoculture visible.

    Verifier grounding: execution-grounded, not LLM-as-judge

    Quality is never a vote. Fitness is an evidence score: the weighted count of what OTHER accounts built on a node, with self-citation excluded. The ground truth for the task is a deterministic Python evaluator, not a model judge.

    • Evaluator: seeds all RNGs with 42, runs the submitted transfer(model, config), scores 200 FineWeb-Edu texts in non-overlapping 512-token chunks under the GPT-2 tokenizer, reporting summed next-token loss / UTF-8 byte count (bits per byte).
    • Cheat-proofing is mechanical: the FineWeb-Edu loader raises an error if called from inside transfer(); rules forbid pretraining, fine-tuning, and editing the evaluator or target config.
    • Determinism: two runs of the same code on the same hardware are bit-identical; across GPU types scores can differ in the third decimal place.
    • Human audit at three levels — recomputing every statistic from the exported contribution stream, checking the best score algebraically, and reading the winning commit's 83-module import chain to confirm no gradient step. The authors did NOT rerun the winning method.
    • Explicit caveat: 'The score is not a truth signal.' A verdict without artifacts is 'a coordination hint rather than strong validation evidence.'

    The run: reliability, throughput, and where the gains came from

    Task: initialize a frozen 14-layer attention-SSM hybrid (hidden size 672, 7 heads, untied embeddings, 119,572,320 params) from 141 open-weight donors (534 GB, 32 families) with no training data and no gradient updates. Workers: 5 on A100 nodes from April 27, 8 on H100 nodes from April 28; each container got one 80 GB GPU, one Agora credential, and a one-line headless prompt pointing at a two-page brief.

    • 1,703 contributions in 11 days 19 hours (~170/day at full staffing): 1,124 scored results, 284 insights, 203 hypotheses, 165 verifications, 1 report; 233 results set a new best; 53 explicitly tagged negative results.
    • Cost/latency signals: evaluation takes a few seconds; building the six-donor transition matrix takes ~5 minutes on an H100 and hours on CPU. No dollar cost per run is reported anywhere in the paper.
    • Failure/intervention rate: exactly ONE mid-run human action (May 2 deployment of clustering + diversity views); no task assignment, no contribution review, no steering of individual sessions. 165 verifications, none reporting a failure.
    • Emergent behavior nobody asked for: from April 28 onward 400+ descriptions declare a prediction band before the result.
    • Graph shape at cutoff: 1,703 nodes, 1,894 edges, 149 multi-parent nodes, one component holding 98.9% of nodes; the winner's ancestry is 145 commits across 15 of 17 accounts.

    Coordination pathologies the trace exposes

    The authors read the same trace as evidence of the mechanism's weaknesses. The graph is heavily exploitation-biased: a narrow spine of successive leaders surrounded by short, quickly-abandoned branches. A shared leaderboard did not stop duplicate work.

    • Fast exploitation then stall: the first 18 scored contributions account for ~98% of the total bpb reduction; the remaining 1,106 found the next 0.03.
    • Parallel rediscovery: 696 pairs of different accounts posted identical scores, with large fractions within one hour of each other.
    • Five-day monoculture: more than 1/3 of all activity sat in a single semantic cluster and the leaderboard stalled — the community left the basin within a day of being shown the diversity map, and the first sub-1.90 result came the next morning.
    • Community-level diagnosis emerged: agents converged on a shared explanation that the evaluator is globally linear and the target's sublayers are underused (the agents' claim, not the authors').

    The winning recipe (two stages, all sparse deterministic edits)

    Stage A builds the initialization from what donors PREDICT rather than from their parameters: six GPT-2-vocabulary donors are queried on every vocabulary token under 28 single-token contexts; their next-token log-softmaxes are blended (0.725 weight on GPT-2 small) into a context-averaged bigram table, whose column mean is split off as a unigram anchor and whose centered remainder is factorized by randomized SVD into the input embedding and output head, with all sublayers zeroed. Stage B re-enables sublayers with sparse deterministic edits on 96-dimensional bands of the hidden state.

    • Every attention layer becomes a uniform causal mean-pool over one band, written back at a small scale.
    • Layer 0's SwiGLU receives SVD-projected slices of GPT-2 small's first MLP at scale 0.009.
    • SSM blocks disable the selective path, reducing to gated depthwise causal convolution over one band.
    • Each constant was introduced as a single change on the then-current best and kept only because the evaluator improved — hill-climbing on the dev evaluator, not a controlled ablation.
    • Documented negative results others cited: doubling the prefix set to 48, flattening the singular-value spectrum, transplanting native Mamba blocks, copying GPT-2's embedding matrix directly.

    Key findings

    • 13 unmanaged agent sessions produced 1,703 contributions in 11 days 19 hours (~170/day), driving a frozen 119.6M attention-SSM hybrid from 3.3923 bpb random init to 1.899044 bpb — 62% of the gap to a trained GPT-2 124M — with no training data and no gradient updates.
    • Diminishing returns are extreme: the first 18 scored contributions delivered ~98% of the total reduction; the remaining 1,106 scored results bought only ~0.03 bpb.
    • 165 verification contributions covered 95 distinct targets, each by a non-author, and NONE reported a failure; same-hardware reproductions are bit-identical.
    • The winner's ancestry spans 145 commits by 15 of 17 accounts, with 115 of 144 parent edges crossing account boundaries — no single worker assembled the recipe.
    • Exactly one mid-run human intervention (deploying clustering + diversity-aware UCB after more than 1/3 of activity concentrated in one semantic cluster) broke a five-day monoculture within a day.
    • Duplicate search persisted despite shared state: 696 same-score pairs from different accounts, many within an hour of each other.

    Notable quotes

    The Git history is the only state: workers read and write it, and nothing else passes between them.
    A leaderboard is a good exploitation signal and a poor map.
    We did not assign tasks, review or approve contributions, or steer individual sessions.
    We take from this that the coordination layer, not the individual agent, was the binding constraint.

    Limitations

    • No causal claim: the authors never ran the same models and compute without Agora, with a flat log, or with a central planner, so the benefit of shared research state is unmeasured — Appendix C proposes the matched comparison instead of reporting it.
    • Every component was selected on the same 200-text development evaluator, so the trustworthy quantity is the 3.39 -> ~1.90 improvement, not the final decimals; the last recorded change moved the score by less than cross-hardware variation.
    • Single task, single community run (n=1), and the run's own diagnosis is that the graph is heavily exploitation-biased — plus the community only escaped its basin after a human deployed a new view.

    Open questions

    • Does a contribution DAG actually improve discovery per unit of compute versus a flat chronological log or a central planner, or does it merely file the same parallel waste more neatly?
    • Can diversity-aware attention allocation prevent monoculture autonomously, without a human noticing the concentration and shipping a new view mid-run?
    • Is the 1.90 bpb plateau a genuine hard local optimum of no-gradient donor-behavior transfer or an artifact of the community's exploitation bias?
