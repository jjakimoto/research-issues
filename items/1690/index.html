    AutoGym: Blueprint-First Generation of Verifiable Agent Gyms

    ← Go backWeVisDoc: From Coverage to Capability for Robust End-to-End…NextVibeMemBench: Evaluating Memory Systems for Coding Agents on… →

    Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
    Date: 2026-09-22

    Source: arxiv · 2026-09-18
    Link: https://arxiv.org/abs/2609.22592

    AutoGym inverts synthetic environment generation: it writes a solution blueprint — valid solution space, environment requirements, verification criteria — before materializing the environment, so solvability and deterministic verifiability are construction constraints rather than post-hoc LLM-judge checks. It produces complete RL gyms at $2-8 and 15.6 min per task versus $500-1000 and 1-1.5 hours for expert authoring, with 80-92% of candidates surviving repair.

    Executive summary

    AutoGym generates complete agent gyms (task + executable environment + verifier) from a minimal domain seed or from prior model failure trajectories. Its central move is blueprint-first ordering: a blueprint fixes the solution path, answer-relevant entities, obfuscation, distractors and verification criteria before the environment is materialized, after which ground truth is computed by executing the blueprint's derivation against the real materialized environment. Explicit generation parameters steer difficulty, and an active curriculum loop reweights those parameters from measured rollout failures. On a productivity gym, the mid-to-hard configuration puts 39% of tasks in the hard band for Claude Opus 4.6 versus 4% for the Agent World Model baseline, at roughly $100-200 per 50-task batch.

    System topology: five stages, blueprint before world

    The pipeline runs generation inputs -> blueprint initialization -> blueprint construction -> maze materialization -> ground truth/verification/repair, with an outer active-curriculum loop. Inputs are a domain seed and a tool specification defining the action space; prior trajectories are optional. Generation used Claude Sonnet 4.6; the substrate is a relational store behind tool wrappers.

    • Blueprint initialization samples scenario, persona and the generation parameters BEFORE any task content exists
    • Blueprint construction fixes solution space, dependency structure, obfuscation and distractors; a reconciliation check runs before materialization
    • Maze materialization instantiates every withheld fact inside the environment so it is recoverable by interaction
    • Construction is substrate-independent - the same ordering is claimed to apply to stateful/service-backed environments

    How verifiability is enforced

    Three mechanisms replace post-hoc LLM adjudication: an answerability invariant (task plus accessible environment must jointly contain enough information); ground truth computed by executing the blueprint's derivation against the materialized environment; and a verifier derived from that ground truth checking deterministic outcomes programmatically.

    • Repair loop: a missing resource, unreachable criterion or inconsistent derivation triggers repair and re-materialization
    • Agent failures on otherwise valid gyms explicitly do NOT trigger repair - capability failure is separated from evaluation defect
    • The worked procurement verifier asserts an exact rate (81.25% +/- 1.0), the correct policy (POL-027 at 90.0%, not POL-089's 85.0%), and four distractor-resilience conditions including paginating past the first 50 of 96 rows
    • Open-ended components are scored only against blueprint-defined evidence; full elimination of LLM adjudication for free-form tasks remains unsolved
    • A reconciliation rule requires distractors to preserve at least one valid route to success

    Difficulty control and active curriculum

    Difficulty is a set of dials decoupled from the domain: topology tier, interaction depth, capability axes, an obfuscation gradient (0.8 in the running example) and distractor composition. The curriculum loop evaluates the target model over multiple rollouts, separates genuine failure patterns from evaluation defects, then raises weights on dimensions the model clears and relaxes those it fails, with bounded updates to damp oscillation.

    • C1 and C2 differ only in topology tier weights, obfuscation gradient and distractor budgets - same domain, same 7-tool interface
    • Prompt templates enforce that the question leaks no tool names, field names, thresholds, formulas or data-source hints
    • In the worked example the loop responded to two observed failures by upweighting implicit-criteria and raising the competing-threshold and pagination-boundary distractor budget

    Results: difficulty spread and cross-model discrimination

    On the productivity gym (7 tools), the Agent World Model baseline is 90% easy for Claude Opus 4.6 while a human expert-authored suite is 21.5% hard. AutoGym C1 yields 10/34.7/55.3 hard/medium/easy and C2 yields 39/10/51. Running the same C2 gym on gpt-oss-120b moves 70% of tasks into the hard band.

    • Eight independent rollouts per task; a rollout succeeds only on verifier score 1
    • Evaluated agents see only the user-facing task and environment - blueprint, ground truth and verifier criteria are hidden
    • All 10 tasks outside Opus's easy band on the temporal gym are also hard for gpt-oss-120b, plus 9 more hard for gpt-oss-120b alone
    • An 8B model trained with GRPO for 500 steps on a 600-task instruction-following gym showed consistent reward improvement

    Rejection rates, certification and cost

    Yield after three repair iterations: 297/350 (84.9%) for C1, 280/350 (80.0%) for C2, 92/100 (92%) for the temporal gym, and 86% across a six-domain 600-task suite generated in under ten hours. Repair visibly removes fake difficulty. The AWM baseline needed manual review and retained only 217 of 300 tasks.

    • Every retained task also passed human inspection for reachability under persona access scope, non-blocking distractors and verifier-semantics match
    • Per-task: $2-5 mid-tier / $3-8 frontier and 15.6 min, versus $500-1000 and 1-1.5 hours for expert authoring
    • Per 50-task gym at 20-way parallelism: $100-150 mid-tier / $150-200 frontier in 54 minutes, versus $25K-$50K over 2-4 weeks
    • Independent seven-dimension certification scored the productivity gym highest on scope compliance (92.7) and groundedness (91.4), lowest on interface realism (78.0) and diversity (80.0)

    Key findings

    • Blueprint-first ordering plus three repair iterations retained 297/350 (84.9%) C1 and 280/350 (80.0%) C2 productivity tasks, 92/100 (92%) temporal tasks, and 86% across a six-domain 600-task suite; the AWM baseline retained only 217/300 and required manual review.
    • Repair strips cosmetic difficulty: C2 dropped from 57% hard before repair to 39% after, with easy rising from 30% to 51%.
    • Parameter steering moved the hard band from 10.0% (C1) to 39.0% (C2) for Claude Opus 4.6 while holding domain and the 7-tool interface fixed.
    • The same C2 gym separates models: 61% medium-or-easy for Claude Opus 4.6 versus 30% for gpt-oss-120b (70% hard).
    • Cost: $2-5 (mid-tier) to $3-8 (frontier) and 15.6 min per task, or $100-200 per 50-task batch at 20-way parallelism in 54 minutes.
    • Certification exposes the weak spot of synthetic worlds: interface realism 78.0 and environment realism 86.0 on the productivity gym.

    Limitations

    • Interface realism (78.0) and environment realism (86.0) are the weakest certification dimensions, caused by the tool-mocking layer's departures from deployed APIs and unnaturally integrated distractors.
    • Open-ended tasks still rely partly on LLM-based semantic judgment.
    • Downstream training evidence is thin - a single 8B model over 500 GRPO steps - and the live cloud-emulator substrate has no empirical evaluation.

    Open questions

    • Can LLM adjudication be eliminated entirely for free-form tasks, or is process-quality trajectory scoring the practical ceiling?
    • Does the measured difficulty/discrimination behavior survive on a live, service-backed substrate?
    • Does training on AutoGym-generated gyms transfer to held-out human-authored benchmarks at scale?
