DarwinX: Evolving Agent Harnesses Through Natural Selection

📰 Latest · 2026-08-15
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-15

Source: arXiv (cs.AI) — Salesforce AI Research · 2026-07-31
Link: https://arxiv.org/abs/2608.07545

Freezes the model and evolves only the harness — prompts, skills, tools, control flow — under a preserve-and-extend admission contract, reporting roughly 17 points of average gain across four agent benchmarks. The most useful number for practitioners is the honest one: the in-loop proxy score saturated at 1.000 while held-out pass@1 was 68.3%, a 31.7-point overfitting gap the population (not the best lineage) absorbed.

Executive summary

DarwinX is an evolutionary procedure that edits an agent's harness — a skill layer (prompts, memory, distilled knowledge) and a code layer (tools, control flow, agent loop) — while the base model stays frozen in every matched comparison. Children are admitted only if net per-task gain is positive and bounded regression stays under a threshold, verified by a reasoned verifier agent reading trial evidence, then re-tested at higher fidelity with a preservation probe. Across Terminal-Bench 2.1, TerminalWorld, WebArena-Infinity and a SWE-bench Verified transfer, the evolved harness beats its own base by 7.7 to 49.5 points depending on benchmark. The paper is unusually candid about what evolution does not buy: a 31.7-point proxy/held-out gap, statistically indecisive margins on 41 held-out tasks, and every recombination merge reverted on one benchmark.

What is actually evolved (and what is not)

Only the harness is editable, in two layers. Model weights are never touched, and the agent (Salesforce's proprietary "Monet") is compared as "Monet (DarwinX)" versus "Monet (base)" on a frozen backbone. Each generation asks a proposer for one additive edit targeting a fragile or failing task while preserving solved ones; edits may touch prompts, skills, tools, control flow, or source code.

  • Skill layer: prompts, memory, distilled knowledge. Code layer: tools, control flow, agent loop.
  • Fitness is the per-task solve rate under the benchmark's own verifier (avg@k) — no gold solutions, no hand-picked winners.
  • Admission rule: net gain g(c) = sum of per-task deltas must be positive AND bounded regression R(c) = sum of negative deltas must be at most delta.
  • Deliberately "two-speed": permissive about trying an edit, strict about trusting it.

Population, archive, recombination

Every scored variant is archived as a first-class node in a tree storing snapshot, edit delta, per-task scores, trial evidence and distilled lessons. Children are classified by solved-set relation to the parent: improvers and neutral children remain inheritance-eligible; stepping stones and score-trading variants contribute only lessons. Merging combines complementary parents from a common ancestor and is kept only if the merged solved-set is a superset of the union of the parents'.

  • Parent sampling mixes exploitation of the highest cumulative-gain confirmed node with a broadening term over the population.
  • Ranking uses cumulative lineage gain because variants are screened on different task subsets and raw scores are not comparable.
  • Three learning signal types, all converted to harness edits: failure-derived (summarize failed trajectories), teacher-derived (distill a reference solver on "walls" with no successful rollout), self-derived (contrast passing vs failing rollouts).
  • A failure-mode classifier labels each trial (timeout-setup, wrong-output, tool-error) into shared memory read by both proposer and verifier.

Measurement discipline

Binary avg@k is used throughout; agent timeouts at the declared budget count as real failures, and infrastructure failures are separated per protocol. Screening runs at avg@3 on rotating subsets, confirmation at avg@5 on the full suite. The authors treat the repeated measurement as deliberate overhead, since a single lucky rollout can masquerade as a capability gain.

  • RQ1 Terminal-Bench 2.1: frozen GPT-5.5, 89 tasks. RQ2 TerminalWorld: frozen Opus 4.8, 94 training / 41 disjoint held-out, single-attempt pass@1.
  • RQ3 WebArena-Infinity: frozen GPT-5.5, 300 synthetic intents (LLM judge) for evolution, deterministic pass@1 on 1,260 real tasks.
  • RQ4: the Terminal-Bench harness run unchanged on 500 SWE-bench Verified issues — transfer is measured in one direction only.

Validity auditing, not just scores

WebArena-Infinity results are reported both raw and audit-clean, with a two-stage detector plus an independent Opus 4.8 judge. Evolution did not just raise the score; it collapsed the invalid-success rate, with evaluation-plane, privileged-host and privilege-escalation exploit classes vanishing entirely and only raw-state mutations in one application remaining.

  • Total invalid trajectories fell 293 to 17; confirmed-invalid share 23.5% to 1.4%.
  • Separate Terminal-Bench reward-hacking audit: 370 rewarded trajectories, 2 flagged, 1 false positive, 1 confirmed task-level shortcut (reading an answer from a task README); removal changes 1 of 445 trials.
  • Strictest diagnostic (all task-budget timeouts counted as capability failures) still leaves roughly 82%, over 6 points above the 75.5% base.

What the evolved skills turned out to be

The Terminal-Bench skill-bundle diff added seven skills, all from one family: derive an acceptance contract and check it before finalizing, verify the graded artifact (output file, format, values) and iterate fix-and-recheck, ground outputs in real tool execution, and repair against security and contract checks. Because skills were co-selected, the authors present this as composition, not per-skill causal effect.

  • Per-cluster Terminal-Bench gains land on the weakest clusters: ML and scientific computing 60.1 to 74.9, data/database 83.9 to 97.8; security is flat (85 to 84).
  • Preservation on 88 paired tasks: 36 improve, 43 unchanged, 9 regress.
  • On 6 newly solved tasks the evolved harness spends 22 turns and 380K tokens versus 11 turns and 89K; on 69 tasks both solve it is 13 versus 12 turns.

Key findings

  • Terminal-Bench 2.1: +7.7 over the same-model base (75.5 to 83.2) and +5.2 over Terminus-2 on the same backbone, with the model frozen throughout.
  • The in-loop TerminalWorld proxy went 0.505 to 1.000 while held-out pass@1 reached only 68.3% — a 31.7-point gap; four specialists solved 24/25/26/27 held-out tasks and the merged harness reached 28.
  • WebArena-Infinity audit-clean pass@1 rose 43.5 to 93.0 (+49.5 pp) while confirmed-invalid successes fell from 23.5% to 1.4%.
  • Cross-benchmark transfer: the Terminal-Bench harness scored 421/500 (84.2%) on SWE-bench Verified, +3.4 over an 80.8% fix-skill reference — a far smaller gain than in-domain.
  • On the WebArena evolution run the gate kept 26 iterations and reverted 36, and every single merge was reverted; gains came from one short accepted lineage.

Notable quotes

The gain comes from a better harness that knows when to keep working, not from a larger model or a uniformly bigger budget.
Local wins therefore matter only when they survive the same measurement regime used for final selection.
All signals are translated into candidate harness edits; none update model weights.
Selection therefore runs over a population rather than a single line of descent.

Limitations

  • The in-loop screening score saturated while held-out performance did not: the best proxy-fitter was not the best generalizer, and the margin over Claude Code on 41 held-out tasks is not statistically decisive (McNemar p = 1.0; matched-Opus comparison p = 0.45, one solve = 2.4 points).
  • No causal attribution — archive, parent selector, merge operator and inference effort are never independently randomized, so the reported skill bundle explains composition, not per-skill effect; recombination in particular was reverted on every WebArena merge.
  • Base-model sensitivity is large: the same procedure on GPT-5.5 gave 56.1% on TerminalWorld, below Terminus-2's 61.0%, so the headline uses Opus 4.8; public leaderboard rows use different models and effort settings and are context, not controlled comparison.

Open questions

  • Separate the contributions of the archive, the parent selector and the merge operator under matched compute — does recombination beat plain single-lineage mutation at all?
  • Can an in-loop signal be built for SWE-bench Verified that scores test resolution rather than trajectory completion, enabling in-domain evolution and reverse-direction transfer?
  • Does the frozen-model framing survive co-evolving harness selection with weight updates, and does a harness remain a durable asset across base-model generations?
