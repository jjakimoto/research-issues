Loreley: Repository-Scale Program Evolution with Quality-Diversity Search

📰 Latest · 2026-08-24 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-24

Source: arxiv · 2026-08-20
Link: https://arxiv.org/abs/2608.19703

A matched, statistically powered test finds that keeping a quality-diversity archive of whole-repository states did NOT beat plain sequential best-of editing after 48 jobs on a real codebase — a rare, well-instrumented negative result for anyone tempted to bolt archive/stepping-stone machinery onto an autonomous coding loop before validating it.

Executive summary

Loreley evolves a real Git repository by keeping a Quality-Diversity archive of whole repository states — indexed by a PCA-reduced embedding of the repo — rather than following only a single best lineage. Candidates are Git commits built in isolated worktrees and scored by a project-supplied evaluator; archived non-incumbent states can later serve as parents or as prompt-only 'inspiration'. On a matched Zstandard benchmark (7 paired blocks, 48 jobs per policy per block, 1,008 jobs total), QD's final holdout compression gain was statistically indistinguishable from both a sequential best-of-N champion baseline and independent-root restarts — even though lineage evidence shows the archive was genuinely exercised.

Why repository-scale QD search

The premise is that the coding-agent gains that matter are not isolated function-level tweaks but edits that must coexist with a whole repository's existing structure.

  • Real speedups are repository changes that interact with existing types, tests, build rules, and public interfaces.
  • The authors split the hoped-for benefit into an engagement condition (are non-incumbent states retained and reused?) and an efficacy condition (does that reuse produce a better final candidate?).

Archive design and behaviour descriptors

Each candidate is a Git commit in an isolated worktree; the repository's eligible files are embedded and a PCA projection of that embedding is the MAP-Elites behaviour descriptor.

  • 1,536-dim repository embeddings reduced to 3 whitened PCA coordinates (refit every 4 artifact-unique states), indexing a 4x4x4 = 64-cell MAP-Elites grid.
  • Each cell keeps a bounded Pareto front (capacity 8) using epsilon-dominance (epsilon = 0.003), then crowding distance on overflow; cell and within-cell member are both sampled uniformly.
  • Archived states can be supplied as prompt-only 'inspiration' without changing lineage.
  • Blob-level embedding caching keyed by experiment and Git blob SHA.

Experimental setup and compute budget

Three policies are matched head-to-head on a single real project (Zstandard) under an identical job budget, with pre-registered statistics.

  • Policies: Loreley QD, Sequential Champion, Independent Root, over seven paired blocks on one Linux ARM64 host (128 logical CPUs, 245 GiB RAM).
  • 48 physical jobs per policy per block (1,008 attempted, 948 succeeded). Root commit c604f825; planning model gpt-5.6-sol, coding model gpt-5.6-luna.
  • Validation checkpoints every 8 jobs (8/16/24/32/40/48) picked up to 10 finalists each; the winner was scored against a holdout hidden from the agent.
  • Statistics: 20,000-resample BCa bootstrap CIs, an exact sign-flip test over 128 assignments, and Holm correction.

Results: a precise null at the 48-job endpoint

At the full budget Sequential Champion had the best observed mean and median gain, QD sat in between, and neither pairwise contrast against QD reached significance after correction.

  • QD vs Independent Root: +0.320 pp (BCa 95% CI -0.082 to +0.686; Holm-adjusted p = .375).
  • QD vs Sequential Champion: -0.135 pp (BCa 95% CI -0.556 to +0.161; Holm-adjusted p = .547) — both intervals span zero.
  • Leave-one-block-out sensitivity moves the QD-vs-Sequential estimate from -0.226% to +0.020%: the sign is not robust to which block is held out.
  • A secondary, uncorrected combined-throughput metric showed QD -0.531% vs Sequential and +0.367% vs Independent (nominal p = .047), not treated as confirmatory.

Mechanism engaged, but no endpoint payoff

Lineage tracing shows the archive was genuinely used, yet the engagement did not translate into a better selected endpoint, and the authors flag reasons the null may be a horizon or measurement artifact.

  • 4 of 7 final QD winners trace to a non-incumbent primary-parent ancestor (6 of 7 counting inspiration edges); of 67 lineage nodes, 49 were non-incumbents later on an outgoing edge.
  • Three capability case studies outside the matched comparison found large single-run gains: python-pathspec +25.140%, markdown-it-py +6.750%, a Zstandard revision +1.234% (holdout +1.173%), all at generation 4.
  • Descriptor stability caveat: raw repository embeddings were near-collinear (median pairwise cosine distance 3.22e-6), and 22 of 51 admitted candidates (43.1%) would land in a different archive cell under an end-of-run PCA refit.
  • Scope: one repository, one model pair, one host, seven blocks, throughput-only objective, no component ablation.

Key findings

  • At the 48-job endpoint, mean holdout gains were Independent Root +0.502%, Loreley QD +0.824%, Sequential Champion +0.960%; both QD contrasts' confidence intervals span zero after Holm correction.
  • 948 of 1,008 attempted jobs (7 blocks x 3 policies x 48 jobs) completed successfully.
  • The archive mechanism was demonstrably used — 4 of 7 QD winners (6 of 7 counting inspiration edges) trace to a non-incumbent ancestor, and 49 of 67 lineage nodes were reused non-incumbents — yet no endpoint advantage appeared.
  • Separate capability runs found large one-off gains under the same system (python-pathspec +25.140%, markdown-it-py +6.750%), all at generation 4.
  • QD was substantially cheaper and faster than either baseline ($140.05 / 32.00 host-hours vs $192.54 / 85.68 h and $185.30 / 92.25 h; $517.89 total).
  • The PCA behaviour descriptor is unstable: raw repo embeddings were near-collinear (median pairwise cosine distance 3.22e-6) and 43.1% of candidates would be reassigned under a refit.

Notable quotes

They are repository changes that interact with existing types, tests, build rules, and public interfaces.
Inspiration supplies evidence from another lineage; it does not change the Git parent of the new commit.
A commit vector is the uniform mean over all eligible file vectors.
The present data cannot distinguish an insufficient horizon from an ineffective descriptor, archive, or sampling rule.

Limitations

  • Single repository (Zstandard), one model pair, one host, seven paired blocks — limited power, so the null does not rule out a smaller or slower-emerging effect.
  • No component ablation isolates the descriptor, the Pareto-front retention rule, or the inspiration mechanism; only the whole QD policy was compared.
  • The behaviour descriptor is shown to be unstable, so archive coverage is not established as a meaningful diversity signal.

Open questions

  • Would a horizon beyond 48 jobs let the demonstrated stepping-stone reuse eventually translate into a measurable endpoint advantage?
  • Does the null generalise to a second repository or domain, or is it specific to the Zstandard optimisation landscape?
  • Would ablating individual archive components reveal which, if any, is responsible for the lack of observed benefit?
