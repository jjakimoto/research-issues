    Analyzing and Mitigating Cost-Inefficient Behaviors in Coding Agents

    📰 Latest · 2026-09-28 Full Article
    Read full article →View on GitHub

    Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
    Date: 2026-09-28

    Source: arxiv · 2026-09-25
    Link: https://arxiv.org/abs/2609.30725

    Three wasteful habits (re-reading code already seen, regenerating near-duplicate scripts, and rerunning the same tests without a new patch) show up in 79-98% of SWE-bench tasks and cost up to 22.75% of spend. Seven hand-written rules placed in the system prompt cut cost by 7.88-41.73% in six of eight settings. Adding a code-graph MCP retrieval tool made cost worse, by up to 28.14%.

    Executive summary

    The authors (Purdue) analyze 1,200 trajectories from Claude Code (Sonnet 4.6 main agent, Haiku 4.5 subagents) and Mini-SWE-Agent (Sonnet 4.6, MiniMax-M3, Qwen-3.5 Plus) on 300 SWE-bench Verified tasks. They find three recurring cost-inefficient behaviors: subsumed retrieval, similar script generation, and test re-execution. They then compare three fixes on 200 held-out Verified tasks plus 100 SWE-bench Pro tasks, over more than 10k trajectories, with noise floors taken from triplicated baselines. The fixes are CodeGraph structure-aware retrieval, LLM-synthesized skills (Trace2Skill-style), and a set of seven developer-written skills. Only the developer-written skills cut cost consistently: -7.88% to -41.73%, robust in 6 of 8 settings, with Pass@1 mostly within noise. CodeGraph never produced a robust saving and robustly increased cost in 4 of 8 settings.

    Problem

    Coding-agent token spend is growing fast, and more spend does not reliably buy better performance. Earlier cost work (context compression, routing, runtime supervision) does not show which specific recurring agent behaviors waste money, why they happen, or whether targeted fixes remove them. In the paper's motivating example (Claude Code on django-13158), three such behaviors account for 17.25% of task cost even though the task passes.

    • RQ1: What cost-inefficient behavior patterns occur in coding agents?
    • RQ2: Does structure-aware retrieval (CodeGraph) reduce those behaviors and end-to-end cost?
    • RQ3: How do agent-synthesized skills (SynSkills) compare with developer-designed skills (DevSkills)?

    Study design

    There are two frameworks and four configurations. Claude Code (CC) is CLI v2.1.169, with S46 as the main model and H45 for subagents. Mini-SWE-Agent (MSA) is v2.3.0 at temperature 0 with a 250-step limit, run with S46, MM3, or Q35+. Per-task cost caps are $3 on Verified and $5 on Pro. The 500 Verified tasks are split by creation date within each repository: the earliest 300 are for analysis and the other 200 are held out. Pro-100 is a stratified sample over all 11 SWE-bench Pro repositories, weighted toward costlier tasks. Every step gets one of 18 action labels, assigned by rules plus a GPT-5.1 fallback that handled 7.26% of steps. Behavior cost is attributed per flagged action from its input, output and cache tokens at model prices.

    • Detectors: SubRetrv means a retrieval of at least 5 lines fully covered by an earlier retrieval. SimScrpt means a script of at least 5 lines with line-level Jaccard similarity of at least 0.60 to an earlier script. ReTest means the same test ID run again inside one inter-patch window, keeping only the last run.
    • Metrics: Pass@1, task cost, cost-of-pass (CoP), and per-task behavior counts.
    • Noise control: all 8 baselines were run 3 times, and 9 approach cells were replicated. An effect counts as 'robust' at one-sided p<0.05, and single-run cells must clear |delta| >= 1.90 s.
    • Behavior-count changes are reported only as mechanistic evidence. They are noisier than cost (average CV 15.68%, up to 44.47%).

    The three cost-inefficient behaviors

    The three behaviors map to the retrieval, scripting, and validation phases. SubRetrv clusters early in a trajectory, ReTest mid-to-late, and SimScrpt is spread throughout. Their causes depend on the agent architecture.

    • Subsumed retrieval (the most common): in CC, 50.15% of cases are cross-agent. Subagents return summaries rather than code, so the main agent reads the same region again. In MSA the causes are low-feedback shell edits such as sed -i failing silently (patch-adjacent, 17.96-26.47%), locate-then-zoom reads because cat gives no line numbers (within-sequence), and long debugging loops (long-distance, 52.40% for MM3). Overall, 11.05-18.10% of all retrieved lines are re-reads.
    • Similar script generation: 5.91-9.98x more frequent in MSA than in CC. CC's built-in rule 'NEVER create files unless they're absolutely necessary' limits it to throwaway python -c probes; CC creates 0.21 draft files per task against 2.72-7.07 for MSA. MSA also regenerates file-based patch and test scripts such as /tmp/patch.py, patch2.py and patch3.py.
    • Test re-execution: caused by not knowing the repository's test runner (for example, eight failed 'python -m django test' runs before finding tests/runtests.py), by rerunning to recover truncated or filtered output, and by stalled progress (MSA S46 reran a suite 22 times without a new patch until it ran out of budget). CC has no built-in rule against this, and here it shows no clear advantage (2.09 runs per task).

    Mitigation results

    Effectiveness rises from CodeGraph to SynSkills to DevSkills. Gains are larger for MSA, because CC's system prompt and tools already suppress several of these behaviors. Gains are also larger on Verified-200 than on Pro-100, which partly reflects that the skills were derived from Verified trajectories. Task-cost changes are bigger than the directly attributed behavior cost: the fitted slope is 2.83 on Verified and 1.33 on Pro. Two reasons are given: a shorter trajectory means less cache-reading of earlier context in later calls, and each prevented action avoids the follow-up reasoning it would have triggered.

    • CodeGraph with CC cuts SubRetrv by more than 75% but raises cost (+8.30% Verified, a robust +12.19% on Pro). Each CodeGraph query returns 8.2-16.6x more tokens than an ordinary read, and Haiku subagent calls dropped to zero. The same token volume therefore moved to Sonnet, which costs 3x as much per token.
    • CodeGraph with MSA: agents often used it on top of ordinary retrieval rather than instead of it. That added 5.65-6.75 calls per task, 9.11-29.29% more tokens, and robust cost increases of 8.39-28.14%.
    • SynSkills are 23-41 configuration-specific operational rules. They gave robust cost cuts in 3 of 8 settings (-8.86% to -22.32%), with no robust regressions. Once the one-time synthesis cost is spread over 300 tasks, the gains mostly disappear: MSA S46 goes from -22.32% to -2.70%.
    • DevSkills are 7 shared rules: Hypothesis-Before-Read; Reuse Context; Targeted Patch Only; Understand the Test Harness; Capture Test Output, Filter, Don't Rerun; Persist Artifacts, Version Only With Intent; Break Loops. They gave robust cost cuts in 6 of 8 settings, with only one small Pass@1 drop (-1.50 pp, CC on Verified).

    Practical implications for agent builders

    A short set of general, trace-agnostic behavioral rules in the system prompt is the cheapest and most reliable fix the authors tested. Adding a retrieval tool is not automatically cheaper: you need to measure how much output it returns, whether it replaces or adds to existing reads, and whether it changes which model does the work.

    • Tell the agent to redirect full test output to a file and filter that file, and to rerun tests only after the source has changed.
    • Keep one persistent repro or patch script and edit it in place. Ban numbered variants such as repro2.py or fix_v3.py, and use inline scripts only for one-off probes.
    • Require the agent to say what it expects to find before each read, to reuse what is already in context, and to justify any re-read. Mind the subagent-summary gap that causes cross-agent re-reads.
    • Check the repository's test runner (docs, CI config, runtests.py) before running tests, and treat import or loader errors as harness errors rather than patch failures.
    • When actions stop producing new evidence, take one materially different step, or submit the best patch so far rather than running out of budget.
    • Judge a new tool (for example an MCP code-graph) by end-to-end cost and CoP with repeated runs, not by retrieval-count reductions alone.

    Key findings

    • Together the three behaviors appear in 79.00-98.00% of tasks and account for 6.86-22.75% of task cost. Claude Code has the least waste (6.86%) and MSA with Qwen-3.5 Plus the most (22.75%).
    • Subsumed retrieval is the most common behavior: 64.33-92.33% of tasks and up to 11.41% of cost. In Claude Code, 50.15% of it comes from the main agent re-reading code its subagents had already read, because subagents return summaries rather than code.
    • CodeGraph produced no robust cost reduction in any of the 8 settings and robust increases of 8.39-28.14% in four. With Claude Code it cut SubRetrv by more than 75%, but its verbose output and the loss of cheap Haiku subagent calls pushed cost up (+12.19% on Pro).
    • The seven developer-designed skills robustly cut cost in 6 of 8 settings (-7.88% to -41.73%; MSA S46: -41.73% on Verified, -33.00% on Pro). The largest per-behavior reductions were 64.89% for SubRetrv, 88.91% for SimScrpt and 38.57% for ReTest.
    • LLM-synthesized skills (23-41 trace-specific rules) topped out at -22.32% and were robust in only 3 of 8 settings. Counting their synthesis cost ($4.27-$37.59 per configuration), only one robust saving remains (-9.65%, MSA MM3 on Pro).
    • Task-cost savings are larger than the directly attributed behavior savings (fitted slope 2.83 on Verified, 1.33 on Pro). Removing an inefficient action also removes the later cache reads of the extra context and the follow-up reasoning it would have triggered.

    Notable quotes

    CC offloads exploration to subagents, which return summaries rather than the retrieved code.
    For MSA, cost rises because agents use CodeGraph additively, stacking CodeGraph queries and their verbose feedback on top of ordinary retrieval rather than replacing it.
    Preventing an inefficient action shortens the trajectory, reducing repeated cache-reading of earlier context in later LLM calls.
    In contrast, DevSkills cover the same cases with one principle: persist and reuse artifacts rather than regenerate similar variants.

    Limitations

    • Budget limited the coverage: four agent configurations, SWE-bench Verified and 100 Pro tasks, one structure-aware tool (CodeGraph v0.9.9, which could not run on 13 Pro tasks), and prompt-preloaded skills only. 15 of the 24 approach cells were run once, and their robustness relies on noise floors transferred from the baselines.
    • Detectors (rule-based plus LLM action labels) may misclassify steps; SubRetrv detection ignores code clones beyond whitespace differences. Behavior-count changes are too noisy for robustness verdicts.
    • Cost counts LLM inference only, not wall-clock time or hardware. Pass@1 may miss regressions that still pass the tests. The DevSkills were written by the authors from their own RQ1 findings, so they may transfer less well to other settings.

    Open questions

    • Can cross-agent re-reads be removed at the framework level, for example by having subagents return exact code spans or share a read cache, without losing the compact main context that delegation provides?
    • Would structure-aware retrieval pay off if its responses were terse and it replaced existing retrieval, or if tool use were routed so that work still goes to the cheaper subagent model?
    • Do the seven DevSkills keep their savings on longer-horizon, interactive tasks, on other agents such as Codex or Cursor, and when loaded on demand rather than preloaded into the system prompt?
