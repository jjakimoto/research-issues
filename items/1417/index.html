Agent Workflow Memory

📚 Foundations · 2026-09-10 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-10

Theme: Procedural memory and learned skills for self-improving agents
These systems turn successful interaction traces into reusable procedural knowledge without updating model weights. Agent Workflow Memory stores adaptable textual routines, while SkillWeaver discovers, practices, and debugs executable APIs; both improve transfer but make verifier quality and skill lifecycle management central concerns.
Source: arxiv
Link: https://arxiv.org/abs/2409.07429

Introduces a memory mechanism that abstracts successful trajectories into reusable workflows, enabling agents to accumulate procedural knowledge and improve across tasks online or offline.

Executive summary

Agent Workflow Memory (AWM) converts agent trajectories into abstract, reusable subroutines and adds them to textual memory, either offline from demonstrations or online from evaluator-approved test-time experiences. With GPT-4, AWM reaches 35.5 task success on WebArena versus 23.5 for BrowserGym and raises Mind2Web cross-task step success from MindAct's 36.2 to 45.1. Its transfer results support reusable workflow memory, while its ablations expose risks from incorrect induction, over-guidance, noisy context, and rigid macro-actions.

Problem and workflow representation

Conventional agents solve tasks independently and do not accumulate reusable procedural knowledge. AWM represents each workflow as a natural-language goal plus a sequence of steps containing an environment-state description, reasoning, and an executable action; example-specific values are replaced with variables so the routine can transfer.

  • The base agent retains primitive actions such as CLICK and TYPE.
  • The induction module extracts common subroutines from one or more completed experiences.
  • Induced workflows are inserted into the agent's prompt-based memory to guide later action generation.

Offline and online induction

The LM-based inducer is prompted to find non-overlapping, frequently reused subroutines rather than preserve whole task trajectories. Offline AWM mines workflows from training examples before inference, whereas online AWM processes test queries sequentially, uses a learned binary evaluator to identify apparently successful trajectories, and appends workflows induced from those trajectories.

  • Offline AWM uses a fixed workflow memory for every test example.
  • Online AWM requires no annotated training examples and updates memory after each evaluator-approved experience.
  • The online design enables adaptation to the test distribution but can also store workflows derived from incorrectly judged trajectories.

Benchmark results and generalization

On WebArena, AWM obtains 35.5 total task success and averages 5.9 steps, compared with 23.5 total success for BrowserGym and 7.9 steps for BrowserGym ax-tree. On Mind2Web cross-task evaluation, GPT-4 offline AWM reaches 45.1 step success and 4.8 task success versus MindAct's 36.2 and 2.0. AWM also retains gains when WebArena examples come from non-overlapping templates and when Mind2Web tests move to unseen websites or domains.

  • WebArena cross-template success is 33.2 for AWM, 20.5 for BrowserGym ax-tree, and 32.1 for human-workflow SteP.
  • Mind2Web online AWM reaches 35.5 cross-domain step success versus 18.6 for MindAct.
  • The WebArena learning curve rises rapidly over roughly the first 40 streamed examples.

Representation ablations

Rule-based and LM-induced workflows are nearly tied on WebArena, but abstract LM-induced subroutines perform better on Mind2Web. Code and natural-language workflow formats produce similar results, while adding filtered HTML to natural-language state descriptions makes performance worse, partly because the filtered HTML misses every correct element 47% of the time.

  • WebArena success is 35.6 with rule-based induction and 35.5 with LM-based induction; LM workflows require 5.9 rather than 6.3 steps.
  • Mind2Web step success is 45.1 for LM induction and 43.4 for rule-based induction.
  • Natural-language state descriptions score 34.6 step success; filtered HTML alone scores 33.8, and combining both scores 32.9.

Workflow memory versus workflow actions

The paper also compiles workflows into callable high-level actions. This raises Mind2Web step success from 45.1 to 46.4 but lowers task success from 4.8 to 3.6, and agents invoke the new workflow actions in only 18.5% of tasks. Fixed action sequences can fail when intermediate states introduce dynamic choices, such as selecting an airport from a popup.

  • Textual memory lets the model selectively adapt a workflow to the current state.
  • Macro-actions execute predetermined primitive-action sequences without observing intermediate states.
  • The authors propose real-time state access and dynamic execution loops as promising remedies.

Key findings

  • Abstract workflow memory substantially improves web-agent success without requiring human-engineered, site-specific procedures.
  • Online induction supports supervision-free adaptation and produces its largest Mind2Web advantage under cross-domain shift.
  • Cross-template WebArena results show that the gains are not limited to memorizing repeated benchmark templates.
  • Abstract LM-induced subroutines outperform concrete rule-derived trajectories on Mind2Web, although both are competitive on WebArena.
  • Memory augmentation is more robust than blindly executing workflows as fixed macro-actions in dynamic environments.

Notable quotes

Each workflow represents a goal with a common routine extracted from available action trajectories, which allows it to effectively capture the most essential and reusable skills agents need to acquire to successfully solve increasingly complex tasks.
While following the workflows generally results in more successful task trajectories, agents still encounter some challenges in identifying places to diverge from the workflow guidelines.
Overall, we do not find substantial performance variance between workflows represented in text and code formats, indicating that both forms can bring effective augmentations to agent memory.
Interestingly, using both NL and filtered HTML leads to worse results.

Limitations

  • The experiments cover text-based web navigation on WebArena and Mind2Web with GPT-3.5-turbo or GPT-4, leaving multimodal, non-web, and genuinely long-lived agents untested.
  • Online AWM depends on a learned binary evaluator; the paper notes that incorrect predicted trajectories can produce harmful workflows.
  • Workflow guidance can bias actions, while compiled workflow actions lack intermediate-state flexibility and are used in only 18.5% of tasks.

Open questions

  • How should an agent retrieve, consolidate, prune, or invalidate workflows as its memory grows and procedures conflict?
  • Can workflows become closed-loop policies with real-time state access and dynamic execution rather than fixed action sequences?
  • How can uncertainty, provenance, negative feedback, and stronger verification prevent evaluator errors from accumulating in self-improving workflow memory?
