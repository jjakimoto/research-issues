    Context Language Models

    Link: https://arxiv.org/abs/2609.37725

    The paper replaces hard-coded compaction harnesses by mirroring the model's live context to a file that the model edits freely with Bash. Zero-shot, this beats Codex-style summarization on BrowseComp-Plus (+11.4% relative, 21.5% fewer FLOPs) and on 12-hour EdgeBench (44.6 vs 42.3 at 59% less compute). It counts the extra re-prefill cost that mid-context edits cause, and adds Suffix Cache Reuse to SGLang to cut that cost.

    Executive summary

    Context Language Models (CLMs) let the model control its own context instead of only appending to it. The live context is mirrored into a file the model can rewrite with ordinary Bash, and edits sync into the next LLM call. Applied zero-shot to Qwen3.6-27B, Claude 4.6 Sonnet and GPT-5.6-Sol, CLMs match or beat summarization, MEM1, ACM, RLM and OpenEvolve on terminal coding, deep research, math optimization, 12-hour repo optimization and a 24-hour six-agent swarm. They usually use fewer FLOPs under a metric that charges for re-prefill. Context management can be steered by prompt, evolved as skills, or trained with stepwise GRPO.

    Problem: fixed context-management harnesses

    Prior work either compacts at a threshold the harness picks or gives the model a fixed menu of context tools. On ContextBench (four synthetic tasks at a 32K limit), summary compaction loses or hallucinates information, and no existing method scores perfectly.

    CLM design: context as a file

    The live context is mirrored to a file whose path is given in the system prompt. The model edits it with Bash or Python, and changes sync to the server. If the model makes no edits, tokens are appended as usual, which keeps the prefix cache valid.

    • Behaviors that emerged: an orchestration scoreboard maintained through 163 in-place edits while the context stayed at 6-8K tokens, and a self-written compact_turns() helper called 37 times.
    • Multi-agent: subagents start and stop as the model creates and deletes context files.

    Zero-shot results

    With Qwen3.6-27B at 32K, CLM reaches 59.4% on BrowseComp-Plus, 11.4% relative above Codex-style summary, with 21.5% fewer FLOPs. On TerminalBench 2.1 it matches the baseline at 70% of its FLOPs. On TBLite it scores 73.7% vs 67.0%. On four math-optimization problems with Claude 4.6 Sonnet, it has the best score on all four.

    Long-horizon and multi-agent

    On EdgeBench-10 (12 hours, best of 3 seeds), CLM scores 44.6 using 179 PFLOPs, against 42.3 and 437 PFLOPs for summarization. With Claude 4.6 Sonnet it is 51.0 vs 42.3. In Software World, a six-agent GPT-5.6-Sol CLM swarm achieves 65% more speedup on held-out downstream packages than a summary swarm at the same USD spend.

    Learning context management

    An evolved skill raises held-out KV Store accuracy from 38.3% to 74.2%. Stepwise GRPO, with an efficiency bonus applied only to successful rollouts, lifts Qwen3.5-9B CLM from 28.8% to 42.5% on BrowseComp-Plus. That ties the equally trained summary harness (42.1%) at 1.34 vs 2.19 PFLOPs per question.

    Compute accounting and Suffix Cache Reuse

    Mid-context edits break prefix caching. For a 20K-token turn, an edit at the start costs 7.7x as much as a plain append. Suffix Cache Reuse (SCR) relocates the spans that survive an edit, re-rotates their RoPE keys and re-prefills only the new tokens. It matches standard SGLang accuracy at 65.0% of its FLOPs.

    • Most of SCR's extra reuse (5.3 of 7.8 points) comes from reasoning tokens that chat templates strip, not from model edits.

    Key findings

    • Zero-shot, CLM scores 59.4% on BrowseComp-Plus, +11.4% relative to Codex-style summary, with 21.5% fewer FLOPs.
    • On EdgeBench-10, CLM scores 44.6 at 179 PFLOPs vs 42.3 at 437 PFLOPs for summary.
    • A six-agent CLM swarm achieves 65% more speedup on held-out packages than a summary swarm at the same spend.
    • After RL, CLM essentially ties the trained summary harness (42.5% vs 42.1%) while using 39% fewer FLOPs.
    • Suffix Cache Reuse matches SGLang accuracy at 65.0% of its FLOPs.

    Notable quotes

    This shows that a general agent with direct context control can outperform a specialized evolutionary workflow with less fixed orchestration.
    Outcome rewards provide only weak supervision for context editing, as successful trajectories can contain inefficient edits and failed trajectories useful ones.
    Before training, CLM with Qwen3.5-9B underperforms the summary harness by six points due to the smaller model’s limited context-management capabilities.
    Editable context can become another channel through which prompt injections or self-generated instructions persist across turns.

    Limitations

    • The comparison is not fully symmetric: CLM gets a budget reminder and can roll back an over-budget request, which the baselines cannot.
    • Several long-horizon results are thin: math uses single runs, EdgeBench reports best of 3 seeds, and Software World is one swarm comparison.
    • The benefit depends on model capability, and SCR reuses stale KV states, so it only approximates a full re-prefill.

    Open questions

    • How sensitive are CLM results to the harness configuration, given that Appendix F and Table 2 report different pre-RL scores for the 9B model?
    • How can a model-editable context be protected against injected instructions that persist across turns?
