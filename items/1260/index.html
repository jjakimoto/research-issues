Where the Verifier Fails: A Category-Level Audit of Reward Signals in RLVR

📰 Latest · 2026-09-02 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-02

Source: arxiv · 2026-09-01
Link: https://arxiv.org/abs/2609.01354

RLVR rewards and benchmark accuracy both come from a rule-based grader that nobody audits, and this paper shows the grader itself varies by 41 points across four widely used implementations on identical inputs — with 93% of one grader's failures caused by trailing whitespace and punctuation, not LaTeX grammar.

Executive summary

The paper points metamorphic testing at the RLVR verifier instead of the model: it generates certified-equivalent rewrites of gold answers (meaning-preserving by construction, so any rejection is a provable false negative) and certified meaning-changing rewrites (so any acceptance is a provable false positive), then measures 307,420 verdicts across four widely used rule-based verifiers. The result is a per-category decomposition of the verifier error budget that the published aggregate (~94% self-validation, blamed on LaTeX parsing) hides. Self-validation ranges 53.8%-95.2% on identical inputs; whitespace and punctuation account for 93.0% of in-contract failures for the default math-verify LaTeX configuration; and a reference SymPy cascade accepts off-by-one wrong answers as a deterministic step function of answer magnitude.

The gap: aggregates say how much error, not what shape

RLVR is the dominant post-training recipe for mathematical reasoning precisely because the reward needs no human annotation: an automatic verifier turns free text into a binary signal. The same verifiers also produce the accuracy numbers reported on MATH and GSM8K. The most concrete published reliability figure is that a standard evaluation harness validates its own ground truth at roughly 94%, with the residual attributed to LaTeX parsing failures. The paper's argument is that this aggregate is unusable: noise-correction methods need error rates as parameters, and systematic-error analysis needs the pattern of error, not its magnitude.

  • Prior work (Huang et al. 2026) already shows rule-based checkers and model-based judges fail in opposite directions — brittle parsing versus reward hacking.
  • Cai et al. 2025 model the verifier as a stochastic channel with asymmetric rates; Egashira et al. 2026 link systematic verifier error to delay, plateau and collapse.
  • The published ~94% figure tells a practitioner that ~6% of correct answers are lost somewhere, but not where. This paper supplies the decomposition, with Wilson intervals on every cell.

Method: metamorphic testing aimed at the grader, not the model

Given a gold answer g and a transformation T that preserves mathematical meaning by construction, the pair (g, T(g)) has a known correct verdict, so any verifier rejecting it commits a CERTIFIED false negative — no human adjudication, no trusted arbiter, no appeal to a stronger model. The dual construction certifies false positives. Because ground truth comes from the construction rather than labelling, the procedure scales combinatorially and runs entirely on CPU.

  • 43 transformations across 14 strata, partitioned into three classes: certified-equiv (rejection = false negative), contract-dep (boxing, units, text wrappers — reported as specification ambiguity, never scored as a defect), and adversarial (acceptance = false positive).
  • A contract matrix records which strata each verifier CLAIMS to handle, so a normalizer that never advertised answer extraction is not scored as defective for rejecting a boxed answer.
  • Data: 4,990 unique gold answers from GSM8K, MATH (all seven subjects) and Big-Math, plus 2,000 synthetic answers — synthesis was needed because set and interval notation appears in only 0.1% of corpus answers.
  • Execution: an Azure ML parallel pipeline on five CPU nodes; each verification runs in an isolated subprocess with a five-second per-item budget; crashes and timeouts are recorded as distinct verdict classes.

Verifier grounding: what is actually checking the answer

This is an audit of RULE-BASED, string-and-symbolic verifiers — the grounding is substring extraction plus normalisation plus an equivalence test. There is no code execution sandbox, no formal proof checker, and no LLM-as-judge anywhere in the audited set; the strongest grounding present is SymPy symbolic comparison sitting behind a numeric tolerance. That matters because the core claim is that this supposedly 'verifiable' grounding is a program with design decisions, not a mathematical oracle.

  • mv-latex: Hugging Face math-verify (v0.9.0) with LaTeX extraction — the library default.
  • mv-expr: the same math-verify library restricted to plain-expression extraction (a CONFIGURATION change, not a different library).
  • strip-string: the DeepSeek-Math lineage string normalizer (Shao et al. 2024) — pure string hygiene, no symbolic layer.
  • sympy-cascade: a reference three-level cascade — exact string match, then numeric comparison with relative tolerance 1e-4, then symbolic equivalence via SymPy. That 1e-4 tolerance is the exact source of the scale-dependent false positive below.
  • The ANTLR4 runtime is pinned to 4.13.2 because verifier behaviour differs across runtimes — i.e. the reward signal depends on a parser dependency version.

Coverage: rejection is not the same failure as execution failure

A verifier can return False on a correct answer, or fail to return a verdict at all (parse exception, timeout, crash). Conflating these is a reporting error with real consequences: a verifier that crashes on every input in a stratum would otherwise be credited with a false-positive rate of 0.0%, which reads as 'correctly rejected'. The paper defines an evaluated denominator n_eval = n_True + n_False and coverage = n_eval / n, reports both rates, and prints n/a (never 0) for zero-coverage cells. Overall in-contract coverage is 96.5%.

  • sympy-cascade and strip-string have comparable aggregate residuals (12.7% vs 4.8%) from DISJOINT causes.
  • sympy-cascade returns a verdict on only 87.3% of inputs but is correct on 100% of those it judges — its entire residual is parse failure, not equivalence error.
  • strip-string judges everything and errs by rejecting.
  • Every failure in the sympy-cascade rows of the error-mass table is a parse exception rather than a rejected answer.

Results: a 41-point spread, a whitespace-dominated budget, and a magnitude threshold

Self-validation on identical certified-equivalent inputs ranges from 53.8% (mv-expr) to 95.2% (strip-string) — a 41.3-point spread, with the published ~94% figure near the TOP of the range rather than at its centre. Two configurations of the SAME library differ by 26 points and disagree on 49.9% of individual pairs. The residual is string hygiene, not grammar: whitespace and punctuation account for 93.0% of in-contract failures for mv-latex and 74.1% for mv-expr at n=15,704.

  • Representative rejected pairs are as trivial as a fraction versus the same fraction with a trailing period, or with a trailing newline.
  • Aggregate off-by-one false-positive rate 16.0%, 95% CI [14.1, 18.1], n=1,287 — the deterministic magnitude threshold is invisible in that aggregate.
  • Cross-paper comparability: acceptance on boxed answers ranges 0.0%-75.1% and on scientific notation 0.0%-100.0% across configurations — not defects, but undocumented contract differences.
  • Robustness (corpus-only, excluding all synthetic golds): 57.5% (mv-expr), 84.1% (mv-latex), 87.8% (strip-string), 88.3% (sympy-cascade) — ordering and magnitude preserved.
  • Pairwise disagreement on certified-equivalent pairs: 49.9% (mv-expr vs mv-latex), 48.0% (mv-expr vs strip-string), 53.4% (mv-expr vs sympy-cascade), and only 0.4% (strip-string vs sympy-cascade).

Why it matters for RLVR

If the verifier rejects a correct answer the policy is penalised for behaviour it should be rewarded for; if it accepts an incorrect one the policy is rewarded for being wrong. A magnitude threshold is 'maximally systematic' in the sense of Egashira et al. (2026) — the regime shown to drive plateaus or collapse — and is completely invisible in any aggregate rate. The paper positions its numbers as a LOWER BOUND on the ~38% false-negative rates reported on real model outputs.

  • Because 93% of the error budget is whitespace and punctuation, the fix is largely trivial normalisation work rather than the difficult LaTeX grammar work the prior attribution implied.
  • A reported benchmark accuracy is a function of the verifier configuration, which is almost never stated; the recommendation is to report verifier identity, version, extraction configuration and runtime alongside any accuracy, plus coverage.
  • Released artifacts: transform suite, contract matrix, and per-sample verdict records (github.com/ethxin0011/verifier-error-budget).

Key findings

  • Across 307,420 verdicts from four rule-based verifiers on identical certified-equivalent inputs, self-validation ranges from 53.8% (math-verify plain-expression) to 95.2% (DeepSeek-Math strip-string) — a 41.3-point spread; the widely cited ~94% figure describes one implementation, not the task.
  • Two configurations of the SAME library differ by 26 points and disagree on 49.9% of individual certified-equivalent pairs, so any reported benchmark accuracy is a function of an almost-never-reported verifier configuration.
  • The residual is string hygiene, not grammar: whitespace and punctuation account for 93.0% of in-contract failures for mv-latex and 74.1% for mv-expr; at n=15,704 the whitespace false-negative rate is 37.2% [36.5, 38.0] for mv-latex and 50.0% [49.2, 50.8] for mv-expr.
  • Coverage separates opposite defects hidden by similar aggregates: sympy-cascade (12.7% residual) returns a verdict on only 87.3% of inputs but is correct on 100% of those it judges, whereas strip-string (4.8% residual) judges everything and errs by rejecting. Overall in-contract coverage is 96.5%.
  • A certified FALSE-POSITIVE mechanism: the reference SymPy cascade accepts off-by-one wrong answers 0% of the time below magnitude 10^4 and 100% at or above, because its 1e-4 relative tolerance is scale-invariant. The aggregate off-by-one FP rate of 16.0% (95% CI [14.1, 18.1], n=1,287) conceals the threshold entirely.
  • Contract differences make cross-paper accuracy incomparable: acceptance on boxed answers spans 0.0%-75.1% and on scientific notation 0.0%-100.0% across implementations. A corpus-only robustness check preserves ordering: 57.5% / 84.1% / 87.8% / 88.3%.

Limitations

  • Verifier-level, not model-level: the paper does not estimate the effect on any model's benchmark score, and runs no training runs to measure downstream RLVR impact.
  • Open rule-based implementations only — no closed frontier systems, no LLM-as-judge, no execution-based or formal-proof verifiers are audited; the measurement isolates only the formatting/equivalence component and is therefore a lower bound on reported real-output false-negative rates near 38%.
  • 2,000 of the 4,990 golds are synthetic, and the contract assignments separating defects from specification ambiguity are an explicit judgement call, published so they can be contested.

Open questions

  • What is the actual downstream RLVR effect — how much does a 41-point verifier spread or a magnitude-triggered false-positive threshold change final policy quality, given no training runs were performed here?
  • Do the same category-level failure modes appear in the other verifier groundings — LLM-as-judge, code execution harnesses, and formal proof checkers — where this certified-transform protocol has not yet been applied?
  • If whitespace and punctuation really are 93% of the error budget, does hardening normalisation close the gap, or does fixing it merely expose a next tier of equivalence failures (sets, delimiters, unreduced fractions)?
