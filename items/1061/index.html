StateM: Reaching 95.3% Raw Accuracy, or a $15 Frontier Run, on Terminal-Bench 2.1 via Harness Scaling

📰 Latest · 2026-08-24 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-24

Source: huggingface-daily-papers · 2026-08-15
Link: https://arxiv.org/abs/2608.15089

StateM argues that a large slice of long-horizon agent failure is harness failure, not model failure, and backs it with a YAML state-machine runtime (durable state, phase-local context, checked transitions, versioned runbooks) that lifts a fixed Codex+GPT-5.5 from 83.1% to 92.1% on Terminal-Bench 2.1 and adapts DeepSeek-V4-Flash to 88.09% for ~$15 of final-run API spend. The headline 95.3% is a raw, pre-adjudication number from an unmerged leaderboard PR with nine trajectories flagged for possible reward hacking — and the paper says so itself.

Executive summary

StateM is an 'agent-native' control layer for long-running CLI agents: a versioned YAML runbook of phase-level states, valid transitions, in/out hooks, and before_transfer checks that the agent operates through its normal shell action space and a human can inspect and edit. The authors call systematically improving this layer 'harness scaling' and test it in four regimes: fixed-model lift, frozen transfer across GPT generations, adapted transfer across providers, and held-out task generalization on BusinessBench. Headline results are 92.1% for GPT-5.5 xhigh + StateM (vs an 83.1% published reference), 95.28% raw for GPT-5.6 Sol xhigh with the frozen profile, and an adapted DeepSeek-V4-Flash system at 88.09% whose final-score evidence cost $15.20. The paper is unusually forthcoming about its own caveats.

Problem: the model can do every step and the run still fails

Long-horizon failure is framed as an execution problem rather than a capability problem: the agent deviates from its plan, loses track of mutable state, skips a check, repeats an unproductive action, or stops before the deliverable is verifiably complete. Two operational hypotheses motivate the design, explicitly labelled as operational rather than claims about transformer attention: control-signal dilution (a compact plan buried under a growing trace) and mutable-state ambiguity (current state must be reconstructed from an append-only history instead of read from an authoritative record).

  • Epistemic gap: the needed knowledge or method is not available at the decision point.
  • Procedural-memory gap (across runs): the agent correctly diagnoses a failure but never reactivates that lesson when the risk recurs.
  • Procedural-compliance gap (within a run): the correct procedure is active but is not completed or followed.
  • Corresponding control points: state-local in_hooks, versioned practices, and checked transitions.

The harness design: states as context-and-contract boundaries

A runbook is formally (S, s0, S_T, E, Phi): phase-level states, an initial state, terminal states, permitted transitions, and a per-state spec holding the phase prompt, entry/exit hooks, transfer checks and state-local artifact references. Each state is both a context boundary (entering refreshes instructions and durable progress) and a contract boundary (leaving requires before_transfer checks to pass). The runtime is deliberately separated from the control profile — which is why the authors say the Terminal-Bench numbers evaluate the combination, not the state-machine abstraction alone.

  • goto protocol: verify the edge exists, evaluate before_transfer checks, run out_hook persistence, evaluate edge guards, commit state and append to history only if all pre-commit steps succeed, then create the target entry and run its in_hook.
  • On failure the run stays in the source state and records the unmet condition; 'checked, logged, and recoverable', explicitly NOT transactional — hook side effects cannot be rolled back.
  • Checks are graded by evidentiary strength: command/predicate (host-evaluated, reproducible) > manual > checklist/message (self-attestation) > llm_review (semantic judgement, not deterministic verification).
  • Per-run state is stored outside the model context, so an agent can resume after restart or compaction.
  • Stop-hook integration for Codex and Claude Code returns the current phase and unmet obligations, reducing premature termination.
  • Shared ownership is bounded: an agent may register stricter run-local checks, but weakening user-owned invariants should require a privileged policy decision — 'YAML editability alone does not provide this security boundary'.

Evaluation setup and what 'harness scaling' means operationally

Terminal-Bench 2.1 has 89 tasks; a full evaluation is 5 trials per task = 445 trials, with trial-level success rate as the primary metric. All runs use Codex-based agents over GPT-5.5 xhigh, GPT-5.6 Sol xhigh, GPT-5.6 Luna and DeepSeek-V4-Flash. 'Harness scaling' operationally means a failure-driven optimization loop: run the profile, classify failures (missing context / invalid transition / weak check / premature handoff / ineffective recovery), propose runbook changes, regression-test, ship a new runbook version — model weights never change.

  • Profile developed with GPT-5.5, then FROZEN for the GPT-5.6 evaluations: no prompt, state, routing, check-catalog or repair-policy revision using target-model outcomes.
  • Stated adaptation boundary: may use the visible task spec, workspace artifacts, public docs and observable execution feedback — but not hidden tests, verifier implementations, public solutions, or task identifiers as routing keys.
  • The GPT-5.6 Sol submission used statem-Codex 0.144.1; the 83.1% GPT-5.5 reference used Codex 0.125.0 — conceded as 'a model-matched public reference rather than a newly rerun, agent-version-matched A/B control'.
  • Cost accounting splits adaptation expenditure from final-evaluation expenditure, and submission-reported model cost from realized out-of-pocket API charges.

Results: a quality frontier, a cost frontier, and a transfer hierarchy

Fixed-model lift: GPT-5.5 xhigh + StateM reaches 92.1% vs the 83.1% published reference (+9.0), solving 88/89 tasks at least once. Frozen cross-generation transfer: the same profile on GPT-5.6 Sol xhigh records 95.28% raw (424/445) vs an 84.9% reference, with 89/89 coverage, and raises GPT-5.6 Luna from 76.7% to 85.4%. Cross-provider transfer breaks: the frozen GPT profile applied to DeepSeek-V4-Flash moves 82.7% to 82.0% — a regression. Only after $37.02 of provider-specific adaptation does DeepSeek reach 88.09%.

  • Under the reference harness, GPT-5.5 -> GPT-5.6 Sol is only a 1.8-point shift; StateM's deltas are +9.0 and +10.4 — the harness moved the score more than the model generation did.
  • The $15 figure precisely: $15.20 in realized DeepSeek API charges for the final-score evidence only. Adaptation cost $37.02; total recorded DeepSeek spend $52.22.
  • The 88.8% 'match' is a descriptive aggregate: 88.09% is the standard-timeout full-suite number; 88.76% replaces five standard-timeout gpt2-codegolf trials with extended-timeout trials.
  • Table 3 attributes task-level jumps to specific controls but states the association 'is not a component ablation'.
  • Operational endurance: one profile-development run ran 22 hours across context refresh/compaction and stop-hook continuation.

Task-side generalization on BusinessBench: gains follow mechanism match

BusinessBench has 477 eligible instances across seven families; StateM treats 405 across six (the protocol abstains entirely on attendance-payroll, presented as evidence that 'no harness' can be the correct control decision). Aggregate frozen gains are small (+0.55 macro, +1.34 micro), while two mechanism-matched families gain +10.04. Two families regress, and the diagnosis is that the control was bound to the wrong execution boundary rather than that there was too little control.

  • Budget Approval 62.91% -> 75.12% (+12.21); Machine Operating 90.79% -> 100.00% (+9.21).
  • Negative transfer: RefactorBench 80.56% -> 77.78%; WooCommerce Stock 92.59% -> 88.89%.
  • Post-evaluation reruns fixed both by re-binding control to the right invariant: RefactorBench -> 79.17%; WooCommerce -> 90.12%.
  • WebArena has almost no signal: 3 non-tied A/B outcomes across 25 instances. WebTest is saturated at ~99.75%.
  • One stochastic trajectory per arm and unequal family sizes — flagged by the paper itself.

Honesty flags an agent-harness builder should carry away

The paper self-discloses most of its own weak points, which is to its credit, but the disclosures materially change how the headline numbers should be read. The 95.3% is not a leaderboard-confirmed result, the $15 and the 88.8% do not come from the same evaluation, and no experiment isolates the state machine from the benchmark-adapted procedural content in the runbook.

  • 95.28% is raw, pre-adjudication, from submission PR #142, which 'remains open and has not been merged into the leaderboard' (status as of August 11, 2026).
  • The authors agree four rewarded trajectories should not count (94.38%); zeroing all nine flagged for possible reward hacking gives 93.26%.
  • The $15.20 covers only the DeepSeek final-score evidence; the whole campaign was $52.22, and the GPT-side comparison ignores the authors' own Codex Pro plan usage.
  • The $574.68 comparator submission itself scored 83.37% raw / 76.18% adjudicated — the cost-vs-quality point splices two sources.
  • Section 3.1 states the results 'evaluate the combined runtime and an evolved, benchmark-adapted control profile'.
  • Section 4.7 documents evaluator leakage: the hyper-agent introduced default target-frame precision values after observing benchmark behavior, and the DNA insertion profile reproduced the verifier's left-most-valid-boundary convention absent from the task description.

Key findings

  • Holding weights fixed, the harness alone moved Terminal-Bench 2.1 by +9.0 points (83.1% -> 92.1% on GPT-5.5 xhigh), while the reference GPT-5.5 -> GPT-5.6 Sol model-generation shift was only +1.8 points.
  • The runbook developed on GPT-5.5 transferred to GPT-5.6 with zero control-logic changes: 95.28% raw (424/445, 89/89 coverage) on Sol xhigh and 76.7% -> 85.4% on the cheaper Luna tier.
  • Exact-profile transfer broke at the provider boundary: the frozen GPT profile made DeepSeek-V4-Flash slightly WORSE (82.7% -> 82.0%); $37.02 of provider-specific adaptation was needed to reach 88.09%.
  • The '$15' is $15.20 of realized DeepSeek API charges for the final evaluation only; the full campaign cost $52.22, and the 88.8% parity claim uses a descriptive aggregate that swaps in extended-timeout trials.
  • The 95.3% headline is raw and pre-adjudication on an open, unmerged submission PR; the authors report 94.38% after conceding four rewarded trajectories and 93.26% if all nine flagged trajectories are zeroed.
  • Task-side generalization is modest in aggregate (+0.55 macro / +1.34 micro on frozen held-out BusinessBench) and concentrated where control matches an explicit execution boundary (+10.04), with two families regressing when control was bound to the wrong boundary.
  • Check strength is made explicit: command/predicate checks give reproducible host-side evidence, while checklist, message and llm_review checks remain self-attestation or non-deterministic judgement.

Notable quotes

We call the systematic improvement of this surrounding control layer harness scaling.
Holding model weights fixed isolates the contribution of the harness.
StateM provides control points, not a correctness oracle.
Negative transfer identifies the wrong boundary.
The design rule is direct: experience must be filtered before it becomes memory.

Limitations

  • No ablation isolates the runtime from the runbook: the paper states the Terminal-Bench results 'evaluate the combined runtime and an evolved, benchmark-adapted control profile', and the control attributions are explicitly 'not a component ablation'.
  • Comparisons are not apples-to-apples: reference rows are published submissions rather than agent-version-matched A/B reruns, the 95.28% is an unmerged pre-adjudication PR score with nine flagged trajectories, and the cost and score comparators come from different evaluations.
  • Failure-driven optimization can bake evaluator conventions into the harness — documented for both target-frame precision defaults and the DNA verifier's insertion convention.
  • Scope caveats on the runtime: transitions are checked and logged but not transactional, recovery only restores what was persisted, YAML editability is not a security boundary, and stop hooks increase persistence without guaranteeing termination.
  • BusinessBench evidence is thin per instance: one stochastic trajectory per arm, unequal family sizes, and only three non-tied A/B outcomes on WebArena.

Open questions

  • How much of the gain survives an ablation that keeps the StateM runtime but strips benchmark-derived procedural content from the runbook, and an agent-version-matched A/B rerun of the baseline?
  • Does PR #142 get adjudicated and merged, and where does the score land between 93.26% and 95.28%?
  • Can the $37 cross-provider adaptation loop be automated and re-run cheaply per model release, or does each provider boundary need fresh human-supplied golden rules?
  • What is the right policy language for deciding which runbook parts an agent may modify at runtime, given YAML editability provides no security boundary?
