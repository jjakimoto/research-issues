    Grouped Value Attention: Efficient KV Caching via On-Demand Key Reconstruction

    Date: 2026-09-16

    Source: huggingface-daily-papers · 2026-09-15
    Link: https://arxiv.org/abs/2609.13285

    GVA drops the key stream from the KV cache entirely — keys are reconstructed from cached grouped values by a per-head linear map that folds into the query at decode — cutting persistent cache scalars ~45-47% versus matched GQA while landing within 0.01 points of GQA's average accuracy at 350M params.

    Executive summary

    FrontiersMind proposes Grouped Value Attention (GVA), which caches only grouped values and reconstructs each query head's content key as K_h = V_g(h) M_h with a learned per-head linear map. Because M_h is fixed at inference it can be absorbed into the query, so the decode path never materializes content keys; a small shared decoupled-RoPE key slice (d_r = 16 or 24) preserves position without restoring a key cache. Trained from scratch at 350M params on 30B FineWeb-Edu tokens, the d_r=16 variant averages 44.35% across five zero-shot benchmarks versus 44.36 for GQA and 43.88 for MLA, at roughly half the cache. The paper reports representation-level cache counts only — no measured throughput, peak memory, or batch-capacity numbers.

    The idea: keys are a linear function of values

    GVA is built on GQA grouping (H query heads share G value heads) and changes only the key path. The authors first tried the crudest cut, K = V, and found the training loss never recovered. They then kept a dedicated value and reconstructed a content key per query head with a learned map, so the cache holds G value streams but yields H distinct content-key streams.

    • K_h = V_g(h) M_h, one map per query head; no independent key projection exists.
    • Recovers head-specific key diversity that GQA loses (GQA has G distinct keys, GVA has H) with a smaller cache.
    • Reconstructed keys are constrained to be linear transforms of their grouped values, not free projections.
    • Shared-KV (K=V) was shipped as an open model, Lumma-0.6B-Base, but is explicitly a failed first cut.

    Absorption at decode

    The content score q_h k_{j,h}^T = (q_h M_h^T) v_{j,g(h)}^T, so a single transformed query computed once per token and head scores directly against the value cache. The identity is exact, and in the fused formulation no temporary key tensor is stored.

    • Absorption is what makes a value-only cache sufficient — content attention reads only V.
    • Standard RoPE breaks it: the relative rotation sits between the query and M^T and varies with the cached position.
    • Algorithm 1 gives the full decode step; line 10 is annotated '{absorb; do not form K^nope}'.

    Decoupled RoPE keeps position without a key cache

    Following DeepSeek MLA, each query/key head is split into an unrotated content slice of width d_n and a rotated positional slice of width d_r, with the positional key shared across heads. The score is the sum of an absorbable content term and a term against the cached, already-rotated positional key; nothing learned sits between the two rotations, so relative position is preserved.

    • Because the positional key is shared it costs d_r scalars per token, not G·d_r.
    • Score scaling uses the full width d_qk = d_n + d_r.
    • Variants without decoupled RoPE cannot use the absorbed decode path.

    Cache accounting

    Per layer and sequence, GQA stores N = 2 T G d_h; GVA with decoupled RoPE stores N = T G d_h + T d_r, giving the ratio 1/2 + d_r/(2 G d_h). For the widths used, the second term is a few percent, so GVA roughly halves the GQA cache — about 47% saved at d_r=16 and 45% at d_r=24.

    • MLA for comparison caches T(d_c + d_r); GVA has no extra latent projection on the cache path.
    • GVA's persistent content state is the value itself, preserving a direct value path rather than a joint latent.
    • These are representation-level scalar counts, explicitly not measured serving memory.

    Initialization is load-bearing

    Because K = VM is a projection of a projection, default initialization of M left keys far below queries in scale, producing nearly uniform attention and wasting early training. The authors initialize each map with sigma_M = sigma_Q / (sigma_V sqrt(d_in)), so K starts at approximately the query RMS.

    • d_in is the value width (the fan-in of M), not the content width.
    • Query RMSNorm is optional; the variance-fixed row stays competitive without it.
    • Positional and content scales must be assessed separately.
    • Scale matching mainly improves early loss rather than the final average.

    Experimental setup

    Decoder-only Transformers trained from scratch at 350M parameters on a 30B-token sample of FineWeb-Edu, with identical data order, token budget, optimizer, context length and query-head count across GQA, MLA and all GVA variants. ZClip was used to mitigate gradient spikes. Evaluation is zero-shot on HellaSwag, WinoGrande, OpenBookQA, ARC-Easy and ARC-Challenge, three seeds each.

    • Variants: GVA baseline, scale-matched + Q-norm, variance-fixed (default), and GVA + decoupled RoPE with d_r in {16, 24}.
    • The paper cautions that small differences should not be read as significant without assessing seed variability.

    Key findings

    • GVA + decoupled RoPE with d_r=16 averages 44.35% across five zero-shot tasks, 0.01 points below GQA's 44.36 and above MLA's 43.88; d_r=24 gives 44.29.
    • The strongest GVA row is scale-matched with query RMSNorm at 44.41 average, slightly above GQA, with the best ARC-Challenge score (29.35 vs GQA's 29.09).
    • Cache ratio is 1/2 + d_r/(2 G d_h): about 47% saved at d_r=16 and 45% at d_r=24.
    • GVA caches G value streams yet produces H distinct content-key streams, versus GQA's G — more key diversity at less than half the cache.
    • The naive K=V shared-KV design halves the cache but its loss stays above GQA for the whole displayed run, motivating the learned reconstruction map.
    • Initialization with sigma_M = sigma_Q/(sigma_V sqrt(d_in)) fixes an early-training pathology; even the unmatched GVA baseline reaches 43.91 average.

    Limitations

    • The 45-47% figure is a representation-level count of the intended decode state, not measured peak serving memory; throughput and batch capacity are not reported, with kernels only 'currently testing'.
    • A single scale (~350M params), a single data mix (30B FineWeb-Edu tokens) and three seeds; no sweep of RoPE width, longer contexts, or model scale.
    • DRoPE d_r=24 is behind GQA on average, and the runs do not isolate positional-width versus content-width allocation effects.

    Open questions

    • Do the custom decoding kernels actually convert the ~2x smaller cache into measured decode-throughput and peak-memory wins?
    • Does the linear value-to-key constraint hold up at larger scale and at long context?
    • What is the right positional width, and does GVA compose with KV quantization?
