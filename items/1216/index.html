ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL

📰 Latest · 2026-08-31 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-31

Source: arxiv · 2026-08-28
Link: https://arxiv.org/abs/2608.28476

ContextPilot trains long-horizon agents to plan, store memories, retrieve evidence, and compress their own working context. Its snapshot-level RL improves accuracy across long-context QA and deep-search benchmarks while stabilizing BrowseComp working context near 8K–10K tokens instead of allowing it to approach 30K.

Executive summary

ContextPilot treats context management as a learned sequence of agent actions rather than passive truncation or summarization. It expands the toolset with planning, structured long-term memory, and recoverable context offloading, then uses context- and entropy-aware partial rollouts to spend exploration on consequential edits. Fine-grained credit assignment evaluates intermediate snapshots using terminal branches that share them, producing gains across three long-context QA backbones and two deep-search backbones while keeping active context compact.

Expanded context-management tools

The framework organizes tools into perception and planning, retrieval, memory management, and context offloading. New operations include planning, batch chunk reading, structured event memory, memory updates and retrieval, message compression, and foldHistory, which replaces history with searchable keywords and a summary.

  • memorize extracts entities, timestamps, event episodes, and relationships; readMemory retrieves an item and its neighbors.
  • summarizeContext replaces a message with a summary, while compressContext uses a lightweight compression model.
  • foldHistory discards historical messages but builds a searchable index, making offloading recoverable.
  • Context-editing operations define trajectory-snapshot boundaries during RL.

Harness-generated supervision

A rule-based harness scaffolds a teacher model while producing SFT trajectories. It can require inspection of retrieved chunks and temporarily restrict an over-budget context to cleanup tools. The scaffolding is removed from final examples so the student must learn the behavior.

  • Long-context SFT contains 2,987 accepted NovelQA trajectories with 50,691 snapshots and 81 NarrativeQA trajectories with 778 snapshots.
  • RL uses 488 LongBench-v2 questions and 1,000 sampled OpenSeeker-v1 questions.
  • The long-context bases are Qwen3-8B, Qwen3-14B, and Gemma4-E4B-it; deep-search bases are WebSailor-7B and WebExplorer-8B.

Context-aware partial rollout

ContextPilot scores editing actions using relative context-length change and entropy change from the initial query state. Under a fixed snapshot budget, it first performs complete rollouts, ranks edits by sensitivity, and branches from the most sensitive decisions.

  • Each trajectory is limited to at most eight snapshots.
  • Training gathers N=128 snapshots per query, starting with eight full rollouts that produce at most M=64 snapshots.
  • Sensitivity weights are α=1 and β=1.
  • Using initial entropy as the reference targets globally consequential uncertainty changes.

Snapshot-level credit assignment

Terminal rewards combine answer correctness, format validity, invalid-tool penalties, and context-length penalties. An intermediate snapshot receives the mean reward of every terminal trajectory for which it is a prefix. Snapshots for the same query are standardized as one advantage group and optimized with GRPO.

  • The penalty covers malformed or premature tool calls, such as readMemory before memory exists.
  • Branch-derived rewards can distinguish a useful edit inside a failed trajectory from an inefficient edit preceding a correct answer.
  • The theoretical appendix argues that the estimator reduces conditional reward variance relative to trajectory-level assignment.

Performance and efficiency

ContextPilot-RL leads comparable-size systems across the reported long-context QA evaluations and improves both deep-search agents. The 8B RL model averages 69.40 across four long-context benchmarks versus 65.85 for StateLM-8B-RL. On BrowseComp trajectories of at least 15 turns, unmanaged WebExplorer approaches 30K input tokens while ContextPilot stabilizes near 8K–10K per turn.

  • ContextPilot-8B-RL gains 3.62 average points over its SFT model.
  • Its BrowseComp+ score increases from 48.84 to 54.18.
  • Across two deep-search backbones, ContextPilot exceeds SUPO by an average of 1.51 points.
  • RL shifts tool use away from retrieval-heavy behavior toward planning, memory, and offloading.

Key findings

  • ContextPilot-8B-RL averages 69.40 across four benchmarks, 3.55 points above StateLM-8B-RL.
  • ContextPilot improves both tested deep-search backbones over SUPO.
  • Working context stabilizes around 8K–10K tokens per turn on long BrowseComp trajectories, versus nearly 30K for unmanaged WebExplorer.
  • The complete toolset raises Qwen3.5-397B-A17B BrowseComp+ from 63.49% to 80.96%.
  • Fine-grained credit adds 0.83, 1.31, 2.87, and 3.10 points over context-aware rollout on the four long-context benchmarks.

Limitations

  • The toolset may not cover all context-editing demands.
  • Computational constraints prevented extensive training-hyperparameter searches.
  • Evaluation is concentrated on long-context QA and deep search; transfer to coding and GUI agents remains untested.

Open questions

  • Does snapshot-level credit retain its advantage in coding or GUI environments with less text-like state?
  • How much gain comes from tool semantics versus demonstrations and RL allocation when inference cost is controlled?
  • Can learned sensitivity scoring replace the fixed α=1, β=1 combination?
