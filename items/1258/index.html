Agentic Empirical Asset Pricing: Methodological Foundations

📰 Latest · 2026-09-02 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-02

Source: arxiv · 2026-09-01
Link: https://arxiv.org/abs/2609.00731

The first paper to argue that LLM-agent factor-discovery systems must be backtested as PROCESSES, not just as the factor sets they happen to emit — supplying a 9-check validation gate, a rolling re-execution protocol, and a matched-budget head-to-head against five re-implemented baselines showing no single metric ranks the systems consistently.

Executive summary

Pan, Ding and Giesecke (Stanford AFT Lab, Nanjing University, HPI) define Agentic Empirical Asset Pricing (AEAP) as systems where LLM agents autonomously close a hypothesis-formalization-evaluation loop over asset-pricing data. Their central claim is that every existing AEAP evaluation backtests only the output (a factor set or a trade), never the discovery system that produced it, so a lucky in-sample window, a leaking gate, and a well-calibrated gate are indistinguishable from the reported Sharpe. They contribute a three-axis output standard (productivity, performance, novelty, plus a spanning test), a rolling 'backtest-the-system' protocol, and SEADS, a reference architecture evaluated against five re-implemented baselines on two US equity panels at a matched 300-candidate budget. The headline result is deliberately deflationary.

Problem: output backtests cannot score a discovery process

AEAP lacks a shared vocabulary AND a shared evaluation discipline, and the second gap hides a specific failure mode. Classical backtesting has one discipline (use only information available at the decision date), but when the researcher is itself a model that discipline binds two nested loops: an inner discovery cycle and an outer loop that re-runs it across historical dates.

  • P1 point-in-time data: no feature observable only after decision date t enters the inner loop.
  • P2 point-in-time process: the outer loop actually exists — the inner loop is re-executable and scoreable at each historical date, not run once. This is the principle NO surveyed system satisfies.
  • P3 out-of-sample-only results: headline numbers come from a split neither loop ever touched.
  • AEAP is defined narrowly: LLM agents must autonomously execute at least one full hypothesis-formalization-evaluation cycle with no human in any step. This excludes ML return predictors (Gu/Kelly/Xiu, Kozak) and LLM copilots; AlphaForge is included as a non-agentic comparison baseline only.
  • Five building blocks: hypothesis generation, formalization into a checkable artifact, execution against data, an evaluation gate, memory/iteration — mapped onto planning, action, tool use, critic, memory.

SEADS architecture and its 9-check validation gate

One Planner call per round emits one structured seed per slot (explore/exploit type, theme, variables, mechanism, complexity tier; explore is 70% of slots by default); each seed is expanded by its own Proposer instance with a context scoped only to prior attempts sharing an underlying variable. Everything downstream is deterministic except the LLM roles.

  • Look-ahead firewall: a deterministic AST walk enforcing 7 rule classes — forbidden return-column reads, dynamic access (getattr/eval/exec/.query), negative .shift/.diff/.pct_change, .rolling(center=True), .rank() not scoped to groupby('date'), groupby('permno').transform over full history, and full-panel/expanding aggregates — plus a taxonomy whitelist and a sandboxed namespace exposing only statically-read columns.
  • Gate order (sequential AND, short-circuit): 0a duplicate fingerprint, 0b self-collapse (corr >= 0.95 with a plain rank of a declared input), 1 coverage >= 0.5, 2 Rank-IC t >= max(3.0, live Bonferroni bound over cumulative candidate count), 3 out-of-decade regime consistency, 4 novelty max corr < 0.7, 5 partial-IC t >= 1.0 vs top-5 controls, 6 Fama-MacBeth t >= 1.0, 7 deterministic sign alignment across Rank-IC, partial-IC and FM beta.
  • Novelty is checked against an explicit EXTERNAL reference set chosen per panel, not against the run's own candidates (which would be circular).
  • Self-evolution mutates near-passes back through the identical gate; feedback names the exact failure stage rather than a scalar fitness.
  • All roles call GPT-5.2 with no tool use or web access; temperatures are per role (Planner/Proposer 0.7, self-evolve 0.5, implementation/reflector 0.2, alignment checker 0.1).

Evaluation standard: three jointly-necessary axes plus a spanning test

A pool of discovered factors is scored on productivity (admissions out of the shared 300-candidate budget), performance (mean per-factor OOS Sharpe), and novelty (max correlation against the union of the system's other admits and the panel reference set). None substitutes for another: performance without novelty rewards redundant repackaging; performance without productivity rewards finding one good signal by any means; novelty without performance rewards noise.

  • Panel A: JKP global characteristics, US subset, ex-microcap — 1,936,944 stock-months, 21,052 stocks, 1925-2025, ~400 taxonomy-declared characteristics.
  • Panel B: CRSP/Compustat base features — 87 primitive accounting/market variables, 1,213,574 stock-months, 5,907 stocks, 1975-2024. Novelty is checked against the external 45-characteristic panel of Bryzgalova et al. (2025), not against Panel B's own raw inputs.
  • In-sample 2010-2019 for both; OOS to Dec 2025 (n~71 months) for A and Nov 2024 (n~59) for B. Every system gets the same 300-candidate budget, the same LLM backbone, and is scored by identical external code, not by SEADS's gate.
  • Baselines are re-implemented rather than cited: AlphaForge and QuantaAlpha verified against released source, RD-Agent(Q) against the official package, AlphaAgent and Beyond Prompting reconstructed from paper text (the latter releases no code).

Results: rankings disagree, and rolling re-discovery is where the gain is

On the static matched-budget comparison (5 replicates), three rankings disagree and the winner shifts by panel. Beyond Prompting leads productivity on both panels and Panel A performance, while SEADS leads Panel B performance and novelty on both. The rolling comparison (Panel A, 3 replicates, annual repropose with 4-month combinator refit, admits jointly regressed with the full raw ~400-characteristic panel) is the stronger evidence.

  • All five discovery systems clear the no-discovery floor by a wide margin: mean rolling Sharpe 0.82-0.96 vs 0.62 for 'Raw 400 only' (the deterministic, LLM-free refit of the raw panel).
  • SEADS nominally leads rolling at 0.96 +/- 0.04 but is NOT reliably distinguishable from Beyond Prompting (0.91 +/- 0.02) or QuantaAlpha (0.90 +/- 0.02).
  • SEADS's static arm — identical starting library, never re-discovering — reaches only 0.71 +/- 0.05, closer to the no-discovery floor than to any rolling system: the advantage comes from repropose, not from the initial library.
  • The authors caveat that this compares each system's BEST rolling configuration, so the gap still confounds algorithm, gate and reconstruction fidelity.
  • Ablations: self-evolution is the single most load-bearing mechanism (removing it drops admits 14.0 -> 7.8 and Sharpe 0.25 -> 0.08). Removing the Planner inflates admissions ~3x (37.2) while Sharpe collapses to 0.10.

Leakage and evaluation discipline (what a quant should actually check)

The OOS split is excluded from every gate decision in code; the validation engine is a pure function of the candidate series, the in-sample window and a threshold dictionary that never reads the OOS split. Firewall, statistical checks, fingerprinting and the sign backstop are deterministic and seed-independent; only the LLM roles are stochastic. Thresholds were fixed ex-ante.

  • The firewall audit produced a concrete number on a competitor: in one matched-budget run RD-Agent(Q)'s native evaluator admitted 57 candidates, of which the firewall flagged 18 (31.6%) for temporal look-ahead or cross-stock rank pooling.
  • Backbone leakage is acknowledged as soft, not absent: a single current model (GPT-5.2) is used at every historical decision date, so knowledge of which factor families worked could bias proposals — more so across the rolling protocol. A release-dated backbone (GPT-4o-mini, Oct 2023) would leave only ~25 clean OOS months.
  • The rolling in-sample window is fixed-length (10 years) and sliding, not expanding.
  • Reported Sharpe is gross of costs; a 50bps-per-side round-trip adjustment scaled by realized monthly rank turnover exists only as a diagnostic.
  • 83.8% of SEADS's admits are multiplicative/gated interactions vs 21.1% for RD-Agent(Q) and 14.5% for Beyond Prompting, which instead admit mostly additive spreads — and a flat two-characteristic spread is exactly spanned by a linear combinator that already holds both inputs.

Key findings

  • No single metric ranks the six systems consistently and the winner shifts by panel: Beyond Prompting leads productivity on both panels (96.4/85.0) and Panel A performance (0.41 Sharpe), while SEADS leads Panel B performance (0.16) and novelty on both panels (0.65/0.46).
  • Re-executing the discovery loop is where the value is: all five discovery systems beat the no-discovery floor in rolling Panel A (0.82-0.96 vs 0.62 Sharpe), but SEADS's own static arm with an identical starting library reaches only 0.71 +/- 0.05. The 0.96 lead over Beyond Prompting (0.91) is explicitly not statistically distinguishable.
  • Self-evolution is the most load-bearing mechanism in the ablation battery: removing it cuts admits from 14.0 to 7.8 and Sharpe by 68% (0.25 -> 0.08). Removing the Planner produces the inverse pathology — 37.2 admits with Sharpe collapsing to 0.10.
  • Applying SEADS's AST look-ahead firewall to a competitor as a post-hoc audit flagged 18 of RD-Agent(Q)'s 57 natively-admitted candidates (31.6%) for temporal look-ahead or cross-stock rank pooling.
  • Combining admitted factors typically degrades them: 14 of 15 replicates fall below the diagonal in mean per-factor OOS Sharpe vs combined-portfolio OOS Sharpe — the gate certifies marginal in-sample signal, not joint out-of-sample contribution alongside later admits.
  • Systems admit structurally different formulas: Beyond Prompting's admitted set is one idea restated many times (mean pairwise |rho| = 0.281, effective independent count 3.46 of 94 nominal admits, vs SEADS's 0.167-0.229 and 3.51-4.49 of 10-18 admits).

Notable quotes

None of this is visible from backtesting the output alone—it requires backtesting the system that produced it, re-run under the information constraints a real deployment would face.
Self-evolution is the single most load-bearing mechanism: removing it shrinks the admitted set itself (7.8 vs. 14.0 admits) and cuts Sharpe by 68% (0.08 vs. 0.25), the largest drop in the battery.
Reported Sharpe is gross of trading costs: we model neither transaction costs nor turnover, so frequent reranking or more complex formulas could erode realized performance disproportionately, a gap no number reported here reflects.
Small samples: admitted-factor counts run in the tens per replicate, OOS windows 59–71 months, so most cross-system differences are not reliably distinguishable.

Limitations

  • Statistical power is thin and the authors say so: admits number in the tens per replicate, OOS windows are 59-71 months, and replicate counts (5 static, 3 rolling) were set by API budget, so most cross-system differences — including SEADS's nominal rolling lead — are not reliably distinguishable. All Sharpes are gross of transaction costs.
  • Backbone leakage is soft but real: a single current model (GPT-5.2) is used at every historical decision date rather than a release-dated model per date, so the rolling protocol — the paper's headline methodological contribution — is the arm most exposed to the model already knowing which factor families worked.
  • Baselines are the authors' own re-implementations: AlphaAgent and Beyond Prompting are reconstructions from paper text (Beyond Prompting releases no code), AlphaAgent's regularization weights were substituted, and for QuantaAlpha the authors ported the paper's stated admission rule over the weaker one in its released code.

Open questions

  • Independent admission does not compose: 14 of 15 replicates lose Sharpe when admits are combined, so what gate criterion would certify joint, non-monotone out-of-sample contribution rather than marginal in-sample signal?
  • Should the live Bonferroni correction on the Rank-IC bar count each self-evolution mutation as a separate trial, or discount correlated attempts from the same parent? This sets how strict the strictest gate actually is.
  • Does the rolling 'backtest-the-system' protocol survive a chronologically-consistent, release-dated backbone, and does the P1-P3 discipline generalize beyond factor discovery to the trading-policy and structural-estimation objectives the paper only sketches?
