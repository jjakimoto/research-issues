FunBO: Discovering Acquisition Functions for Bayesian Optimization with FunSearch

📚 Foundations · 2026-09-01
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-01

Theme: Executable search loops for autonomous scientific discovery
The AI Scientist automates a broad research lifecycle, while FunBO narrows the problem to executable program search under a measurable objective. Their contrast is instructive: broad autonomy produces papers cheaply but remains vulnerable to scientific and implementation errors, whereas tightly scoped executable fitness yields stronger evidence at substantial evaluation cost and with significant search variance.
Source: arxiv
Link: https://arxiv.org/abs/2406.04824

FunBO is a concrete executable search loop in which an LLM evolves acquisition-function code and full Bayesian-optimization runs supply deterministic fitness feedback.

Executive summary

Aglietti et al. formulate acquisition-function design as program discovery: an LLM iteratively edits executable acquisition-function code, while complete Bayesian-optimization loops score each candidate and an island-model database retains useful programs. The resulting FunBO acquisition functions are inspectable and directly deployable, and experiments report competitive or superior behavior across out-of-distribution benchmarks, within-class transfer, hyperparameter optimization, and five-shot adaptation. The work is foundational for autonomous discovery systems because it closes the loop from code generation through empirical evaluation to evolutionary selection.

Problem and contribution

Bayesian optimization depends critically on an acquisition function that balances exploration and exploitation, yet standard functions such as expected improvement, upper confidence bound, and probability of improvement vary substantially across objectives, while learned alternatives often generalize poorly outside their training distribution. FunBO reframes acquisition-function design as algorithm discovery and searches directly over executable Python implementations, making the discovered policies inspectable and usable without a learned-policy runtime.

  • The initial program has the functional form of expected improvement but exposes the union of inputs used by expected improvement, upper confidence bound, and probability of improvement.
  • The method can search for general-purpose functions across unrelated objectives, functions specialized to a related class, or few-shot adaptations to a particular target.
  • The output is code rather than an opaque neural acquisition policy.

Executable evolutionary search loop

At each iteration, FunBO samples two previously evaluated acquisition functions from an island-model program database, orders them by score, and asks the LLM to produce an improved version of the better program. Generated functions are checked for compilation and numerical output, evaluated, clustered with similarly performing programs, and fed back into subsequent prompts; higher-scoring and shorter programs are favored. The reported runs used a 48-hour search budget, 12 sampled programs per generation, and 10 database islands.

  • The search couples LLM code mutation with FunSearch's population-based program database.
  • Candidates in the top 20th percentile on training performance are considered for final validation selection.
  • A separate validation set selects among high-performing candidates when validation objectives are available.

Fitness signal and experimental controls

Candidate fitness is measured by running a complete Bayesian-optimization loop for every training objective. Its two-term score rewards both proximity to the known global optimum and reaching that optimum in fewer trials; candidates that do not converge receive no trial-efficiency reward. Comparisons hold fixed the Gaussian-process settings, Sobol-grid acquisition maximization, trial budget, and initial design so that measured differences isolate the acquisition function.

  • Most experiments use 30 Bayesian-optimization trials; the HPO and Gaussian-process experiments use 20 for faster candidate evaluation.
  • The implementation used five Codey instances and 100 CPU evaluators per LLM instance.
  • Normalized average simple regret is the test metric, with regret normalized to [0,1] before averaging across differently scaled objectives.

Generalization and adaptation results

For cross-class discovery, FunBO trained on Ackley, Levy, and Schwefel, validated on Rosenbrock, and tested on nine functions spanning one to six dimensions. The discovered expression combines expected-improvement and upper-confidence-bound behavior: all compared functions converge on the smooth Styblinski–Tang example in fewer than 25 trials, whereas on the multimodal Weierstrass example the displayed FunBO trajectory reaches the global optimum while expected improvement and upper confidence bound become stuck. Within-class experiments use 25 transformed instances per benchmark and 100 held-out instances; the discovered functions are close to or better than standard and MetaBO acquisition functions. FunBO also outperforms all compared acquisition functions on the AdaBoost HPO task, leads on four-dimensional Gaussian-process samples, and its five-example Ackley adaptation outperforms standard functions and FSAF over 100 test instances.

  • The cross-class function is also evaluated on 50 scaled-and-translated instances of each test function.
  • For SVM HPO, FunBO performs similarly to general-purpose or meta-learned acquisition functions rather than dominating them.
  • On three-dimensional Gaussian-process samples it matches expected improvement and outperforms MetaBO; on four-dimensional samples it outperforms all compared functions.
  • The paper presents full source code for every discovered acquisition function, enabling inspection of the strategies found by evolution.

Significance for autonomous discovery

FunBO demonstrates a general architecture for autonomous scientific and algorithmic discovery: define a typed executable artifact, generate mutations with an LLM, reject invalid artifacts, measure valid artifacts in a real task loop, and retain improvements through evolutionary selection. Its strongest evidence is not merely that an LLM emits plausible code, but that generated programs are repeatedly executed and selected using downstream optimization performance. The paper also exposes the central systems tradeoff: stronger empirical evaluation makes the loop trustworthy but computationally expensive and noisy.

  • The discovered artifact can have value independently of the LLM process that produced it.
  • Interpretability comes from the compact acquisition-function code, although understanding pathological or brittle expressions still requires additional analysis.
  • The design is directly relevant to autonomous research systems that improve algorithms through executable experiments.

Key findings

  • Executable full-loop evaluation lets an LLM search acquisition-function code using actual downstream Bayesian-optimization performance rather than textual plausibility.
  • The cross-class acquisition function blends expected-improvement and upper-confidence-bound behavior and generalizes across benchmark families and dimensions.
  • Function-class-specific searches match or outperform standard and meta-learned acquisition functions on synthetic, HPO, and Gaussian-process tasks.
  • A function initialized from GP-based discovery can be adapted with only five Ackley examples and outperform FSAF and standard baselines.
  • The method produces concise code artifacts that can be inspected and deployed independently of the discovery machinery.

Limitations

  • Running a full Bayesian-optimization loop for every sampled program and every training objective creates substantial evaluation overhead, limiting scalability to larger objective sets and problems such as multi-objective optimization.
  • Experiments require many LLM samples, so total cost depends heavily on the model and whether evaluation is distributed.
  • Result quality has high variance from both LLM sampling and evolutionary randomness; cross-function-class success required multiple FunBO runs.
  • The fitness metric uses a known true optimum and captures only terminal distance plus trials-to-optimum, not the full convergence trajectory.

Open questions

  • Can a fitness metric that represents the entire convergence path improve reliability and reduce dependence on known global optima?
  • How well does executable acquisition-function search extend to constrained, noisy, multi-objective, or non-Gaussian-process Bayesian optimization?
  • Can search cost and run-to-run variance be reduced without losing the benefits of full downstream evaluation?
  • What theoretical, safety, and robustness properties do the generated acquisition functions have, and which are stable enough to join standard Bayesian-optimization libraries?
