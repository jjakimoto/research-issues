Praxist: From Experimental Artifacts to Solution Lineages

📰 Latest · 2026-08-27 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-27

Source: arxiv · 2026-08-26
Link: https://arxiv.org/abs/2608.25955

Praxist replaces the score-ranked solution tree most autonomous-R&D agents inherit with a typed, lane-structured evidence graph, so each generation of parallel agents inherits validated mechanisms, open claims and known failure modes rather than raw transcripts — reaching 60/75 MLE-bench medals (49 gold) at about 1/12 the model spend of a Claude Code + Opus 4.8 sweep. It is the clearest published blueprint yet for the inheritance layer an autonomous researcher needs, though the headline comparison swaps the base model too.

Executive summary

Praxist (Sapient Intelligence et al.) argues that autonomous R&D agents fail at long horizons because campaign state is kept as an untyped search tree over artifacts, so campaigns re-learn the same lessons. It restructures a campaign as a generational Artifact to Finding to Frontier to Agenda to Lineage loop: a cohort of C parallel peer agents each build a reproducible artifact under a pre-registered design contract, an external task-owned evaluator scores it, outcomes are interpreted into typed findings, and an LLM 'PI panel' plus a Chair promotes findings into four inheritance lanes and issues the next generation's agenda. On all 75 MLE-bench tasks it records 60 medals (80.0%) with 49 gold versus 55 (73.3%) and 34 gold for a locally run Claude Code + Opus 4.8 baseline, at US$3,054 versus US$38,370 model spend. Code, project page and full per-generation run archives are released.

Problem: campaigns store events, not reusable evidence

The framing is that recent autonomous R&D systems already couple generation to automated evaluation but preserve campaign state as a score-ranked search tree over candidate solutions. Because tree nodes are compositional (data choices, algorithms, hyper-parameters, tricks, diagnostics all bundled together), artifact-level search can prune a component before its value shows up in combination. The authors borrow assembly theory as the alternative primitive: characterise complex objects by the formation histories that build them from reusable substructures, so each retained element is amortised over later constructions. They name the required capability 'evidence inheritance'.

  • Section 1: 'Most preserve campaign state as a search tree over candidate solutions... artifact-level search can prune components before their utility becomes visible.'
  • Section 2.1 contrasts Praxist with 'evolving program databases, solution trees' which 'inherit an untyped object'.
  • Stated contribution: evidence must be 'selectively retained and recombined rather than merely stored'.

Topology: a generational cohort loop, not a tree search

A campaign is a state-transition process over generations. The inherited state is S_g = (Frontier, Agenda, Gems, Lineage). Per generation: Allocate, (parallel) Build, Eval, Interpret, pool findings, PI memos, Promote, Chair, optional Compress, Record. A generation is 'the synchronization boundary at which peer-level evidence becomes shared research state'; peers run concurrently and 'coordinate only through published evidence, never by editing shared state directly'. The generator/reviser loop exists but is local: within a generation a peer iterates internally against its own evaluated findings before the boundary. Two allocation gates precede construction: the Deep Innovation Gate (a read-only pre-artifact gate forcing a peer to fix a testable mechanism and intervention before any code is written) and Quantified Diversity (a cohort-level rule spreading contracts across distinct design cells).

  • MLE-bench campaign used cohort C = 12 peers per task, top-4 promoted per generation, max 20 generations; defaults are G = 8, C = 5, per-peer safety cap 5 hours.
  • The design contract fixes mechanism family, intervention surface, parent lineage, evidence signature, validation/ablation hook, and forbidden changes.
  • Inheritance is deliberately partial: 'a peer receives only the frontier entries, Gems, and parent lineage relevant to its assigned direction, the PI panel receives generation-level evidence, and the Chair receives the panel's memos'.

The typed evidence graph and what is inherited

A finding is the tuple (intervention, outcome, evidence, type, maturity, action). Type is positive / negative / diagnostic / uncertain / procedural; maturity is inherited from the artifact's evidence stage; action is reuse / validate / avoid / diagnose / preserve / archive. Findings are promoted onto a frontier partitioned into four lanes: confirmed, candidate, diagnostic, validation. Lanes are task-declared, not hard-coded — the trading campaign instead used 'confirmed alpha', 'alpha incubator', 'benchmark floor', 'diagnostic control'. The Chair labels each direction continue / stop / validate / explore and attaches a per-peer contract.

  • Failures are first-class: negative and diagnostic findings are inherited as constraints so later generations do not rediscover them.
  • Gems (durable compressed lessons) are off by default — only the trading campaign enabled them.
  • The lineage is honestly described as materialised 'as several correlated ledgers that share identifiers... rather than as one object graph', and the shipped code files findings under a different task-facing enum than the paper's typology.

Verifier grounding: execution-grounded scoring, LLM-judged synthesis

The scoring layer is strictly execution-grounded and external — the task's own metric, 'never the agent's self-assessment' (MLE-bench's official grading harness against the private leaderboard). No formal verification. Crucially, Eval returns not just a score but a validity state and an ordered evidence stage (smoke, scout, full scored evaluation, replications), and promotion gates out smoke/scout-stage evidence so a lucky preliminary score cannot become a parent. The synthesis layer above it is LLM-as-judge by design: a panel of PI roles (Builder, Skeptic, Portfolio, plus External-validity in high-stakes mode) write independent memos through an evidence-freeze, parallel-memo, anonymised-cross-review protocol, and a Chair arbitrates.

  • Anti-gaming rule: evidence stage is deliberately decoupled from score, and maturity inherits the stage so confidence tracks how thoroughly a result was evaluated.
  • The MLE-bench run needed a separate integrity adjudication: submissions SHA-256-verified against the run journal, contaminated lineages excluded outright, 90,423 attempts rejected across the campaign.
  • That adjudication changed the result: on 9 of 75 tasks the whole lineage behind the best attempt was excluded and a clean actor's submission substituted, lowering the medal on 4 of those 9.

Results and cost

On all 75 MLE-bench tasks Praxist records 60 medals / 80.0% with 49 gold versus 55 / 73.3% with 34 gold for a locally run Claude Code + Opus 4.8 sweep on the same H100 pool and same harness, winning every complexity tier. But the paper is candid that the win is threshold-side, not score-side: on the 70 tasks where both arms score, the baseline has the better raw score on 36 and Praxist on 33 (one tie). Four case studies extend beyond MLE-bench: a rocket-landing controller reaching 100% on a frozen protocol from a 4.03% starting artifact; a trading policy at 53% walk-forward CAGR vs 23% for a paired equal-weight baseline; a SLAM scheduler cutting visual-path processing time 72.4% at unchanged trajectory accuracy; and a tokamak controller with 3.4% higher aggregate survival, though that baseline keeps the edge on the benchmark's original full-horizon metric.

  • Execution ledger: 272 completed generations across the campaign, tasks completing between one and nine; 54 tasks ended on an external stop and 21 hit the task wall limit; about 1,157.5 summed task-run hours.
  • Budget ceilings: 6 GPU-h per experiment, up to 8 single-GPU experiments in flight per task, 24 h wall cap on 70 tasks and 36 h on 5.
  • Token volume behind the US$3,054: 110.9B cache-hit input, 4.6B cache-miss input, 1.1B output, partly served by a cheaper flash model.
  • Code released at github.com/sapientinc/praxist plus an archive of full per-generation run records.

Significance for building an autonomous researcher

This is the most concrete published specification of the inheritance layer between an evaluator and the next attempt: not memory, not a transcript, not a leaderboard, but typed claims carrying a validation status and an operational role. Three design moves are directly transplantable: decouple evidence stage from score so cheap-but-lucky results cannot become parents; force a read-only pre-registration gate before any code is written, which is what lets post-hoc finding extraction compare intent against outcome; keep negatives and diagnostics as first-class inheritable constraints. The cost result is real but must be read carefully.

  • The ~1/12 claim is 1/12 of the Claude Code + Opus 4.8 MODEL SPEND on the same 75-task suite; GPU cost is excluded from both arms and both ran on the same shared H100 pool.
  • The authors scope it themselves: 'Cost figures provide resource context only; medals in Tables 2 and 3 are determined by task scores and MLE-bench thresholds rather than cost.'
  • Forward directions they name: inheritance across campaigns, extension to slower/noisier evaluators, and human-AI collaboration through lineages.

Key findings

  • 60 medals (80.0%) on all 75 MLE-bench tasks with 49 gold, vs 55 (73.3%) and 34 gold for a locally run Claude Code + Opus 4.8 sweep under the same grading harness and H100 pool; Praxist wins every complexity tier (90.9/81.6/60.0 vs 81.8/76.3/53.3).
  • The ~1/12 cost figure is model spend on that sweep: ~US$3,054 vs US$38,370. GPU cost is excluded and the two arms run different base models, so it is not a scaffold-isolated efficiency claim.
  • The advantage is medal-grade, not raw score: on the 70 tasks both arms scored, the baseline had the better raw score on 36 and Praxist on 33, with one tie. Praxist's edge is landing on the right side of leaderboard thresholds plus scoring on the 5 tasks the baseline left unscored.
  • Verification is execution-grounded (task-owned external evaluator, never self-assessment), augmented by an ordered evidence-stage ladder — smoke / scout / full evaluation / replications — that gates immature high scores out of promotion. Evidence synthesis above that layer is LLM-as-judge.
  • Reliability/integrity cost is substantial and disclosed: 90,423 attempts rejected for contaminated lineage, SHA-256 submission verification, and on 9 of 75 tasks the whole lineage behind the best attempt was replaced — lowering the medal on 4.
  • Code, project page and a full archive of per-generation run records (artifacts, evaluation records, findings, frontier lanes, agendas, lineage traces) are publicly released.

Notable quotes

The central design choice is that evidence is never inherited as a raw transcript or a scalar score.
Evidence stage is deliberately distinct from score: a high score obtained only at a preliminary stage is treated as immature and cannot crowd out a complete result during promotion
Its benchmark advantage therefore lies in which side of a leaderboard threshold a run lands on, not in winning the majority of head-to-head score comparisons.
attempts drawn from a contaminated lineage are excluded outright rather than down-weighted (90,423 attempts were rejected across the campaign)

Limitations

  • The headline MLE-bench comparison changes two variables at once — scaffold and base model — so neither the medal gain nor the 12x spend ratio isolates the contribution of the evidence-inheritance architecture; the cost gap is largely a model-price gap.
  • There is no ablation of the inheritance machinery itself. Each arm is a single 75-task sweep, explicitly 'single-sweep outcomes rather than variance estimates', and the only ablation reported is of a domain-specific rocket control allocator.
  • Case studies are not standardized cross-system comparisons — each is scored by its own domain-native evaluator, the Weco rocket comparison is 'an outside reference point rather than a matched-model or matched-compute comparison', and the rocket result is bounded by a frozen low-order simulator with exact state feedback.

Open questions

  • How much of the gain comes from the typed evidence graph versus simply running 12 diverse parallel peers for up to 20 generations? A matched-model, matched-budget ablation with typed lanes off is the missing experiment.
  • Does the approach survive slower or noisier evaluators? The whole maturity ladder presumes a cheap, deterministic, task-owned scorer.
  • Can lineages and Gems transfer across campaigns, and does the LLM PI/Chair synthesis layer become the reliability bottleneck once the execution-grounded layer is trusted?
