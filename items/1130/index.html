Repair or Resample? Rethinking Failure Debugging in LLM Multi-Agent Systems

📰 Latest · 2026-08-27 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-27

Source: arxiv · 2026-08-26
Link: https://arxiv.org/abs/2608.25920

A controlled replay harness shows the standard way we 'fix' agent failures — rerun the whole task and hope — repairs only 6.90% of failures and is mostly resampling luck, while a single symptom-targeted intervention at the failing trace node repairs 20.15% with one third the attempt budget. If you build agent harnesses, this is the argument for record-and-replay with intervention anchors instead of blind retries.

Executive summary

The paper attacks a measurement problem in LLM multi-agent systems: when a rerun of a failed task succeeds, nobody can tell whether the failure was actually repaired or whether the model just sampled a luckier trajectory. The authors build SymTrace, a two-mode record/replay harness that logs every LLM and tool boundary, reconstructs the exact execution prefix up to a chosen intervention anchor, then resumes live generation. They release SymFail, 536 human-annotated failure trajectories from 200 fixed WebArena-Verified Hard and AssistantBench tasks run across AG2, CrewAI and Magentic-One. The empirical result: unguided full rerun reproduces the same failure only 67.97% of the time and repairs only 6.90% of cases at pass@3, self-reflection and critic feedback do worse than plain rerun, and a symptom-conditioned single intervention repairs 20.15% — a 191.89% relative gain.

The problem: terminal success is not evidence of repair

Existing repair methods (retry, self-reflection, critic agents, trajectory guidance) all re-execute the whole trajectory, which resamples upstream decisions rather than touching the failing step. Section 7 states the consequence bluntly: full task regeneration 'conflates repair with outcome variability, making terminal success insufficient evidence that the original mechanism was corrected.'

  • Failure identity is treated as a property of execution history, not of the task input alone.
  • A rerun that passes may have avoided the failing branch entirely rather than fixing it.
  • The paper separates 'same-failure reproduction' (did we hit the same bug again?) from 'repair' (did the native benchmark evaluator accept the outcome?) and measures both.

SymTrace: boundary logging plus selective replay

Snapshot Mode installs framework-specific hooks intercepting LLM request/response pairs and tool call/observation pairs 'without changing the MAS scheduler, agent logic, or state-update procedures'. Calls still hit the live endpoint; SymTrace records the realized request, result and event position. Events are organised into an event-dependency graph 'whose edges represent data or control dependencies', with the observed order stored separately because the graph may admit multiple valid schedules.

  • Replay Mode restarts the native system from the original task/state/config and injects historical results at every boundary BEFORE the intervention anchor.
  • Boundary matching validates each intercepted call against the expected record by event position and canonicalized request content; a mismatch terminates replay rather than silently drifting.
  • Reused prefix nodes are validated by content hash — the paper reports 100.00% prefix exactness.
  • At the anchor, injection stops, the repair instruction is applied, and endpoints go live again; the downstream suffix is genuinely regenerated and is NOT controlled.
  • Stated assumptions: deterministic native transitions under the recorded boundary values, and relevant external state reset or isolated. Replay does not recreate persistent external side effects.

SymFail: 536 human-annotated failures, four trace-observable categories

200 tasks were fixed before any experiment (33 AssistantBench dev tasks plus the first 167 WebArena-Verified Hard tasks in published order). Each task was run once under AG2, CrewAI and Magentic-One, giving 600 executions; the native benchmark evaluators identified 536 failures with complete trace and graph artifacts, and the 64 evaluator-accepted runs were dropped before annotation. Per framework: AG2 171, CrewAI 184, Magentic-One 181.

  • Taxonomy consolidated from Cemri et al. (2025) into four non-exclusive, trace-observable labels: C1 Task-Constraint Violation, C2 Repeated or Stalled Progress, C3 Unresolved Runtime Condition, C4 Plan-Action-Outcome Inconsistency.
  • Primary-category distribution over 536: C1 125 (23.32%), C2 69 (12.87%), C3 203 (37.87%), C4 139 (25.93%); 1,482 total label assignments, mean cardinality 2.77.
  • Four annotators: three label independently, a fourth adjudicates 'with authority to revise any decision rather than applying majority vote or label union'.
  • Reliability: Fleiss' kappa 0.62 for primary category and 0.81 for failure-node type; exact node agreement 73.88% unanimous. The final category set differs from the initial label union in 113/536 cases (21.08%). Per-category kappa is uneven — C3 0.718, C1 0.696, C4 0.688, but C2 only 0.374.

Results: rerun is unreliable, feedback adds nothing, symptom-targeting nearly triples repair

Every condition uses one model at temperature 0.00 through a single OpenAI-compatible endpoint. Task-level methods get up to 3 full attempts (pass@3); node-level methods get exactly 1 selective-replay intervention (pass@1). Repair success is decided by the NATIVE benchmark evaluator, so the headline repair numbers are outcome-grounded. Same-failure reproduction, by contrast, is decided by an LLM-as-a-judge pipeline — that part is model-judged. Statistics: 95% Wilson CIs, 10,000-resample paired bootstrap, two-sided exact McNemar with Holm correction.

  • Reproduction: unguided rerun rep1 = 67.97%, rep3 = 41.42%; SymTrace Replay rep1 = 80.78%, rep3 = 52.43%.
  • Replay's edge grows with prefix length: +9.80/+6.82 pp when only 2-3 nodes are reused, +25.69/+27.08 pp at 9 or more. But 381/536 cases (71.08%) reuse only 2-3 nodes — the harness is prefix-starved on most cases.
  • Task-level repair (pass@3 over 536): Unguided Full Rerun 6.90%, Self-Reflection 4.29%, Critic-Agent 3.73%. Plain rerun beats both feedback methods on every framework.
  • Stochasticity cuts the other way too: 54 initially SUCCESSFUL executions rerun 3x produced 85 failures out of 162 attempts, and 39 of the 54 cases regressed at least once.
  • Suspicious-Node Intervention: 20.15% pass@1 with ONE intervention vs 6.90% pass@3 for rerun with three full attempts — the 191.89% relative gain, budget-conservative in the baselines' favour.
  • Ablation within the same one-shot replay budget: Random-Node 3.73%, Last-Node 1.31% — so the gain is not from selective replay itself.

Why it matters for agent harness builders

The paper is effectively an argument that agent debugging needs deterministic prefix reconstruction plus a targeted intervention point, and that pass/fail retry statistics are a misleading repair metric. Anchor selection is hybrid: 'deterministic rules and a semantic judge jointly evaluate each newly completed node for the C1-C4 symptoms', and the controller suspends execution when the suspicion score exceeds a threshold. Because the run is already recorded, the prefix can be rebuilt to that boundary and resumed — localisation without paying for upstream tokens again.

  • Instrument at the LLM/tool boundary, not inside the scheduler — this is what makes replay framework-agnostic across AG2, CrewAI and Magentic-One.
  • Store an event-dependency graph plus the observed order, not just a flat log; the graph is what makes 'the earliest actionable node' addressable.
  • Treat 'did the rerun pass' and 'did we fix the bug' as different measurements; the paper shows they diverge badly.
  • Caveat for adopters: symptom detection is partly LLM-judged, and the study evaluates target selection and repair guidance jointly, so it does not isolate how much of the 20.15% comes from picking the right node versus the evidence-conditioned prompt.

Key findings

  • Unguided full rerun reproduces the same failure only 67.97% of the time on a single attempt and 41.42% across all three; SymTrace's prefix replay raises this to 80.78% / 52.43% while achieving 100.00% prefix exactness by content-hash validation.
  • Rerun 'repair' is largely resampling: unguided full rerun repairs 6.90% of the 536 failures at pass@3, and the same stochasticity destroys successes — rerunning 54 initially successful executions three times produced 85 failures in 162 attempts, with 39 of 54 cases regressing at least once.
  • Feedback-based repair does not beat blind retry under an equal budget: Self-Reflection 4.29% and Critic-Agent 3.73% pass@3, both below rerun's 6.90%, with no failure type they systematically address.
  • Suspicious-Node Intervention repairs 20.15% of failures with a SINGLE selective-replay intervention, versus 6.90% pass@3 for the strongest task-level baseline — the 191.89% relative gain over the same denominator with a smaller budget, winning on all three frameworks after Holm correction.
  • The gain is not from replay itself: Random-Node (3.73%) and Last-Node (1.31%) interventions get the identical one-shot replay budget and do far worse, isolating symptom-based target selection plus evidence-conditioned guidance as the active ingredient.
  • An evaluator-accepted answer can still be an unrepaired failure: in one CrewAI case the rerun returned an accepted answer while acknowledging it relied on general historical patterns rather than the required evidence the extracted pages never contained.

Limitations

  • Reproduction judgments are LLM-as-a-judge, not execution-grounded: a stratified audit of 72 judgments found 64 agreements, 5 confirmed disagreements and 3 uncertain, giving a 6.96% combined sensitivity upper bound. Repair pass rates, by contrast, come from the native benchmark evaluators.
  • Single-model, single-config study at temperature 0.00 through one endpoint, so the authors warn results 'may not generalize to other model families, providers, scales, or future versions'; data coverage is only WebArena-Verified Hard and AssistantBench.
  • Method attribution and annotation quality are both partial: anchor selection and repair guidance are evaluated jointly; replay guarantees only the pre-anchor prefix (the suffix is live and uncontrolled, and persistent external side effects are not recreated); category C2 has weak inter-annotator reliability (kappa 0.374); and most cases reuse only 2-3 prefix nodes, where replay's advantage is smallest.

Open questions

  • Is the SymFail dataset and SymTrace code actually available? The paper promises release and the appendix says the supplement includes both, but arXiv v1 contains no repository URL, DOI or anonymous link — treat the artifact as announced-but-unlinked until a URL appears.
  • How much of the 20.15% comes from picking the right anchor versus from the evidence-conditioned prompt, and would a rule-only detector hold up — i.e. can symptom localisation be made fully execution-grounded rather than partly LLM-judged?
  • Does the finding survive outside benchmark-derived web tasks and a single model configuration — in particular on coding agents with longer reusable prefixes, where replay's advantage grew to +25.69 pp at nine or more reused nodes?
