One Recipe, Many Harnesses: What Self-Evolution Encodes Across Languages and Models

📰 Latest · 2026-08-24 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-24

Source: arxiv · 2026-08-10
Link: https://arxiv.org/abs/2608.10178

The first paper to open the black box of self-evolved agent harnesses and price the parts: roughly 60-100% of the gain is a portable disciplinary core (never edit tests, minimal diff, localize from the failing test, verify it builds, run the target test) that survives distillation into ten language-agnostic memory lines, while 20-40% of every artifact is ecosystem-specific machinery worth 32-52% of the gain on ecosystem-heavy targets. Crucially the artifact encodes compensation for self-inflicted process defects, not new capability — gain tracks the base model's defect mass at r=0.81, and a planted-defect probe showed the loop recalls known disciplines but does not discover novel environment-specific facts.

Executive summary

The authors hold ONE self-evolution recipe (TRIAGE: typed failure signals route each edit to a harness slot and record it as a falsifiable contract with named should_pass/at_risk instances) fixed across an 8-language x 3-model grid on Multi-SWE-Bench code repair, then dissect the resulting 24 harnesses instead of reporting only aggregate wins. Gains are large where the base policy sabotages itself (Haiku C++ 12.9 -> 87.1, Java 2.9 -> 82.9 mean_solve@3) and are statistically zero in two null regions along the two axes (Python under every model; GPT-5-mini in every language, |z|<1.3). Content analysis shows harnesses converge on abstract concepts (cross-language Jaccard 0.55/0.57) but almost never on instantiation (0.12/0.14), with 20-40% of each harness bound to its ecosystem; a distilled memory-only universal harness of ten guidelines fully matches native evolution on Go (1.08) and JavaScript (1.13) but recovers only 0.48-0.68 on TypeScript, C++ and Java. The framing that matters for harness/skill builders: an evolved harness is a legible compensation layer that closes the gap between what a policy can do and what it does, not a capability extension.

The recipe: four editable slots, typed routing, falsifiable contracts

TRIAGE (Typed Routing and Instrumented Attribution for Guided Evolution) is a plug-in layer over mini-SWE-agent. The harness is H = (P, W, M, T): system/instance prompt templates, Python workflow hooks (only before_query and after_observation), a bounded lessons memory, and declarative shell-tool records. Every cell starts from the same minimal seed H0 and runs 3 rounds of greedy hill-climbing on 20 evolution instances; 50 held-out instances per language are evaluated once, at the end. Each round a rollout analyzer turns trajectories, grader stage records and budget traces into layered evidence, and an evolve agent emits a single JSON change manifest.

  • Memory is deliberately capped at 12 entries x 400 characters, and any entry containing an instance-specific token is rejected — the cap is the mechanism that forces distillation instead of accumulation, and it is why the memory slot is the portable component.
  • The contract has five fields: failure_evidence, root_cause, targeted_fix, predicted_impact ({should_pass, at_risk}), changed_fields. The next round scores it: predicted fixes confirmed / missed, anticipated vs unattributed regressions, verdict.
  • Selection score subtracts 2.0x the fraction of incumbent-solved instances now broken; tolerance band 0.12, revert after 2 non-improving rounds or a 0.25 catastrophic drop; the shipped checkpoint is floored at H0, so reported gain is lower-bounded by zero by construction.
  • Routing is ADVISORY, delivered as a dossier not a verdict, so a misattribution costs one iteration. Two guards: verification is always encouragement, never a hard submission gate (gates produced non-terminating rollouts), and an anti-monoculture rule forces a different component if recent rounds only edited the instance template.
  • Deterministic bucket priority: model_incompat > budget_exceeded > patch_broke_tests > unwinnable > patch_pollution > no_build > wrong_fix. wrong_fix (38.7% of 4,582 diagnosed rollouts) is deliberately NOT routed.

Where it works, and the two null regions

The evolved harness beats the minimal seed in most cells and matches or exceeds the hand-written mini-SWE-agent in 14 of 24 cells; on Claude Haiku 4.5 the ordering evolved > mini-SWE-agent > H0 is strict on every non-Python language. Every non-Python Haiku cell is significant at z = 3.3-11.7 and DeepSeek's at z = 1.7-4.6, while no GPT-5-mini cell reaches significance (|z| < 1.3) and Python is null or slightly negative under all three models. Notably the authors do not read GPT-5-mini as the stronger model — under the same mini-SWE-agent it is the weakest — suggesting models have qualitative behavioral properties independent of capability level.

  • Biggest cells: Haiku Java +80.0 pp (2.9 -> 82.9), Haiku C++ +74.3 pp (12.9 -> 87.1), Haiku Rust +61.1, Haiku TS +51.9.
  • Python's detector-covered defect rate is the lowest of the eight languages (5.6%): the rules the loop would install are ones Python policies already follow.
  • GPT-5-mini's evolved memory.md contains no test-file rule at all, on languages where every other model's harness installs one as its first entry — the loop independently reaches the same diagnosis.
  • Worked cell (C++ x Haiku): 16 of 18 seed failures were patch_broke_tests; round 1 installs a test-file boundary rule (10.0 -> 62.5), round 2 adds a build-and-run-the-target-test hook (62.5 -> 72.5), round 3 over-extends and is discarded by the best-checkpoint rule.

What the gain actually is: compensation for self-inflicted process defects

The failures the loop repairs are process defects, not comprehension: editing a test file (which collides with the hidden gold test patch so git apply fails and an otherwise-correct source fix scores zero), shipping non-compiling source, and submitting without running the target test. Of 256 recovered held-out instances across the grid, 88% carried a detector-covered defect under the seed (81% touched a test path, a further 7% broke the test build without touching one). Across the 24 cells, seed defect mass vs net gain correlates at r = 0.81, and the conversion rate differs by model (about 0.58 gain per unit defect mass for Haiku, 0.34 DeepSeek, 0.12 GPT-5-mini).

  • The authors find no recovered instance where the harness enabled a repair the base policy could not otherwise express: compensation, not a raised ceiling.
  • Which defect dominates is a property of the cell: non-compiling changes are 70% of C++ defects and 44% of C's while test-file editing is <=10%, and the reverse holds on scripting targets — which is exactly why a static hand-written scaffold must hard-code one guess for all cells.
  • Practical corollary they draw: a base policy's measured defect profile is a cheap leading indicator of where harness engineering pays off.
  • Honest scoping: build-break detection is structurally unable to fire on interpreted languages (Python 0% under all three models) even though agents demonstrably edit Python test files.

The artifact is behavioral rules in text, not tools — and tools actively hurt

Appendix G reproduces two full memory slots from the same model differing only in language. The abstract concepts recur almost one-for-one (never modify test files, minimal diff, localize from the failing test, verify it compiles, run the target test); the concrete tokens share nothing: make -j4 / ctest -R / *test*.cpp / *.snap on C++ versus go build ./... / go vet ./... / *_test.go / an errors.Is idiom rule on Go. The C++ instance template grows from 325 to 1,730 characters, and the same discipline appears in all three slots at once — as prose in the prompt, as a lesson in memory, and as a before_query hook that fires only when the transcript looks like the agent is about to submit and no test run is visible.

  • The loop essentially never writes tools. Pre-installing a plausible capability tool (find_duplicates) was net-negative: 11.1 -> 9.3 with the tool versus 11.1 -> 22.2 without, a 12.9 pp cost, because the tool competes for steps and attention with the behavioral disciplines that carry the gain.
  • Ablating the meta-agent driver on (Go, DeepSeek): seed 18.5, GPT-OSS-20B driver 34.2, DeepSeek-V4-Flash 33.3, Claude Sonnet 4.6 35.6 — the gain is not frontier-model knowledge injection, it is the diagnostic routing plus contract structure making harness editing an easy task.
  • Planted-defect probe: an injected environment gate whose only remedy is one specific operational fact. The loop never converged on it (78.3% -> 76.1% control; 76.1% -> 71.7% with the error text surfaced) and instead wrote the same generic verification discipline it writes everywhere — evidence of recall, not discovery.

Portability: a portable disciplinary core plus a 32-52% ecosystem margin

Three independent measurements — textual, distillation, transplantation — converge on the same band. Textually, 20-40% of each harness is ecosystem-specific (mean 26% Haiku, 29% DeepSeek), with concept-level Jaccard 0.55/0.57 against ecosystem-marker Jaccard 0.12/0.14, a factor of four. Distilling all languages' memories into ten generic guidelines (memory-only, naming no build command, test path or file convention) retains 1.08 on Go and 1.13 on JavaScript — statistically indistinguishable from native — but only 0.68 Java, 0.65 C++, 0.48 TypeScript. Transplanting a foreign native harness unchanged is positive in 18/20 ordered pairs (mean retention 0.63) yet falls below native in 14/20 and fully recovers in only 6/20.

  • Exporting and importing are nearly uncorrelated properties: JavaScript exports well into typed targets (into C++ 1.32, Go 1.00, Java 0.90) yet as a TARGET is the least recoverable language in the matrix (column mean 0.20).
  • The one wall — JS -> TS at -2.30 versus JS -> C++ at +1.32: a JS-evolved harness carries 'run the failing test before submitting' but no compile-verification step. On C++/Java, running the test entails building, so the generic rule silently supplies compile verification; on TypeScript, test runners transpile without type-checking, so a patch runs green while tsc (and the grader) rejects it.
  • The two experiments bracket native from opposite sides: on ecosystem-heavy targets universal <= transplant < native (C++ 0.65 vs 0.90; Java 0.68 vs 0.74), on generic targets the order reverses (Go 1.08 vs 0.84; JS 1.13 vs 0.20) because foreign ecosystem baggage is dead weight or worse.

Significance for skill/memory-layer builders

The paper turns 'self-evolving harness' from a black-box win into an accounting: your evolved skill/memory artifact is a compensation layer whose size is set by the base model's process-defect mass and whose portable fraction is set by how much of the required discipline the target ecosystem enforces for free. Three design lessons transfer directly: cap the memory so new lessons must merge or prune rather than append (and filter instance-specific tokens so lessons are replayable verbatim on unseen tasks); make every edit carry an explicit, named, two-sided prediction so a regression can be classified as anticipated versus unattributed and reverted at file granularity; and express verification as a nudge fired at the moment of the behavior (a hook), never as a hard gate. Economically the outer loop is cheap — metered meta-model spend was $256 against $3,667 of rollout spend (~5%).

  • Scale: 15,054 rollouts, 737,188 agent steps, $3,667 metered, all on one 64-core / 251 GB CPU-only machine; rollouts hard-capped at 80 steps and $1.5, mean 41.3 steps.
  • One evolved harness costs on the order of a few hundred rollouts and single-digit dollars of meta-model spend per cell, and the artifact is a few kilobytes of text — no gradient step, revertible at file granularity.
  • Operational rule of thumb from the paper: reuse or distill a harness to bootstrap a new ecosystem, but re-evolve natively for ecosystem-heavy targets (Java, C++, TypeScript).

Key findings

  • Self-evolution over a fixed recipe beats the seed in most of 24 (language, model) cells and matches or exceeds hand-designed mini-SWE-agent in 14 of 24; on Claude Haiku 4.5 gains reach +80.0 pp (Java 2.9 -> 82.9) and +74.3 pp (C++ 12.9 -> 87.1), with every non-Python Haiku cell significant at z = 3.3-11.7.
  • Two null regions, one per axis: Python gains ~0 under all three models (lowest detector-covered defect rate at 5.6%) and GPT-5-mini gains nothing in any language (|z| < 1.3) — and GPT-5-mini is the WEAKEST model under mini-SWE-agent, so nulls track behavioral profile, not capability.
  • The gain is compensation for self-inflicted process defects: of 256 recovered held-out instances, 88% carried a detector-covered defect (81% edited a test path, 7% broke the test build); defect mass predicts gain at r = 0.81 across cells, and no recovered instance showed a repair the base policy could not otherwise express.
  • Which defect binds is cell-specific: non-compiling changes are 70% of C++ and 44% of C rollout defects with test-file edits <=10%, and the reverse on scripting targets — the operational argument that a static one-size scaffold must hard-code one guess.
  • Harnesses converge on concepts (cross-language Jaccard 0.55 Haiku / 0.57 DeepSeek) but not instantiation (0.12 / 0.14, a factor of four), and 20-40% of every harness is ecosystem-specific.
  • Portability is bounded and triangulated: a distilled memory-only universal harness of ten guidelines retains 1.08 (Go) and 1.13 (JS) of native gain but only 0.68 Java / 0.65 C++ / 0.48 TS; unchanged transplants help in 18/20 ordered pairs (mean 0.63) yet fall short of native in 14/20, with one strongly negative cell, JS -> TS at -2.30.
  • The loop recalls disciplines rather than discovering facts: a planted, non-shortcut-able environment defect was never encoded (78.3% -> 76.1% control, 76.1% -> 71.7% with the error surfaced), and a pre-installed capability tool was net-negative by 12.9 pp; even a GPT-OSS-20B meta-agent driver reproduced the frontier driver's gain (34.2 vs 35.6, seed 18.5).

Notable quotes

Together, these findings quantify the compensation view: the language determines which disciplines a task requires, model capability determines how many of them the base policy already supplies, and evolution installs the difference.
A fifth to two-fifths of what the loop writes is therefore unusable outside its target ecosystem.
Transfer completes when there is no language-specific gap left to bridge.
Memory is capacity-bounded and admits only rules marked as cross-instance reusable, so the cap pressures distillation rather than accumulation; detailed component constraints are given in Appendix A.

Limitations

  • All evidence is single-episode, single-goal Multi-SWE-Bench repair verified by a fixed test suite, so persistent memory is only exercised as distilled cross-instance discipline (never as within-episode state across subgoals) and sub-agent decomposition is untested.
  • The defect definition is partly an artifact of the grading protocol: editing a test file is fatal only because the grader applies a hidden gold test patch on top of the agent's diff, so absolute gains partly reflect learning the evaluation protocol (the cross-harness comparison, which holds the protocol fixed, is the reliable quantity).
  • Low statistical power and a bundled method: 20 evolution / 50 held-out instances per language, one evolution run per cell, three rounds of greedy hill-climbing, an LLM concept/ecosystem rubric with imperfect precision, no head-to-head against other harness-optimization methods, and no compute-matched baseline that spends the evolution budget on extra rollouts instead.

Open questions

  • Does the split into a portable disciplinary core and an ecosystem-bound remainder survive at longer horizons and multi-goal agent tasks, where within-episode memory and sub-agent structure actually matter?
  • Can any loop of this kind be made to DISCOVER novel environment-specific operational knowledge rather than only recall general disciplines — the planted-defect probe was negative in both conditions?
  • Is the near-total absence of evolved tools a property of this substrate and 80-step / $1.5 budget, or a general result that behavioral text edits dominate executable capabilities?
