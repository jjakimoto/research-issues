SKILL.state: Scalable Long-Horizon Agent Skills

📰 Latest · 2026-08-28 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-28

Source: arxiv · 2026-08-26
Link: https://arxiv.org/abs/2608.26263

A direct argument for deleting the transcript: SKILL.state replaces append-only conversation history with a single mutable JSON execution state, discards the reasoning trace after every validated state patch, and holds prompt size flat (~1.8k tokens) out to 200 steps while cutting total tokens up to 16.2x. Budget-matched controls collapse to 0.18-0.22 at the same token budget, so the win is the structure, not the brevity.

Executive summary

SKILL.state (Badhe, Tiwari, Chung; Google and Purdue) is a runtime architecture for executing long-horizon procedural agent skills. At each step the model sees exactly three things — the immutable procedural specification, the current structured execution state, and the latest observation — and returns a chain-of-thought trace, a JSON state patch, and one action; the runtime deterministically validates and merges the patch, then throws the reasoning away permanently. This yields an O(1) prompt footprint and O(T) cumulative tokens versus the O(T^2) of history-appending runtimes. Across a synthetic diagnostic benchmark (SkillExecBench: Warehouse and Software Repository), InterCode CTF and Sierra tau-Bench, with Gemini-3-Flash, Gemma-4-31B-it and Qwen-3-8B-it, it matches or beats ReAct / summarization-memory / LangGraph-style stateful baselines on accuracy while cutting cumulative tokens by 40-95%.

The state representation and storage format

Execution state is a first-class runtime object, not a memory store: a plain JSON dictionary conforming to a schema authored once per domain. The model never writes state directly — it emits a state_patch (a JSON dict of key mutations, null meaning delete) plus an action, and the runtime applies a dictionary merge. There is no vector store, no retrieval, no episodic log; the state IS the memory, serialized compactly straight into the prompt.

  • Prompt contract: (procedural spec P, current state Sigma_t, observation O_t). No prior observations, actions or reasoning ever re-enter the context.
  • Model output contract: exactly two keys — state_patch and action — preceded by free-form reasoning explicitly labelled as discarded after execution.
  • Schema reuse is aggressive: all 100 InterCode CTF challenges share ONE static 5-field schema.
  • Warehouse state is a flat 500-key inventory map, each holding an item id or null.
  • Within-step multi-step chain-of-thought is fully preserved during generation — only its persistence is removed. This is context management, not reasoning ablation.

Skill lifecycle: what this paper does NOT do

This is a paper about skill EXECUTION only. Skills are pre-authored procedural specifications selected before the runtime is invoked; there is no skill acquisition, no induction from trajectories, no evolution of a library, and no retirement policy. The authors position it against their own prior work on skill discovery and composition: the contribution is 'the largely unexplored mechanics of skill execution once a skill has been selected.'

  • The skill spec is immutable across the episode and identical across all four compared runtimes — context management is the sole independent variable.
  • Schemas are hand-authored once per domain; dynamic schema discovery is flagged as an explicit open limitation.
  • No skill library, versioning, or deprecation mechanism is proposed or evaluated.

Verifier grounding: deterministic, not LLM-as-judge

Every scoring path is execution-grounded or programmatic; no LLM judge is used anywhere. SkillExecBench runs a deterministic ground-truth simulator seeded by a fixed RNG so all four runtimes see the identical event sequence. InterCode CTF is binary pass@1 on an exact-match flag from a real bash Docker container. tau-Bench uses the official programmatic evaluator checking the final SQLite database state.

  • Schema ownership and patch validation live in the runtime; an invalid patch triggers a rollback-retry cycle, so a malformed model output cannot corrupt state.
  • Decoding pinned at temperature 0.0 / top-p 1.0; 5 procedural generator seeds per synthetic config, mean +/- SD reported.
  • Significance: paired t-test, p < 0.01, for SKILL.state vs baselines at horizons T >= 50.

Baselines and the budget-matched controls

Three runtime paradigms are compared: Prompt (ReAct-style full transcript), Memory (MemGPT-style rolling window plus refreshed summary), and Stateful (LangGraph-style structured state block injected ALONGSIDE the full transcript). Three budget-matched controls pin the baselines to SKILL.state's ~1,800-token budget: sliding-window truncation, summary-capped, and ReAct + LLMLingua perplexity compression.

  • The Stateful/LangGraph baseline is the key control — it has structured state too, but keeps the transcript, and still degrades quadratically.
  • Noise robustness injects 5/20/50 purely observational distractor events per turn; state recovery silently mutates the world outside the action loop and measures 'hallucination lag' in turns.
  • LLMLingua's entropy filter strips slot identifiers that look redundant but are semantically load-bearing.

Results that matter to a harness builder

Warehouse at T=200: SKILL.state holds 0.94 accuracy at 1,811 average prompt tokens / 122,384 total, while Memory blows up to 6.18M total tokens at 0.84 and ReAct falls to 0.74. On InterCode CTF, pass@1 rises to 54.2% (+7.8 pts over the best baseline) with 60.4% fewer tokens than ReAct. The state-recovery result is the most operationally striking: history-based runtimes hallucinate for 5-14 turns after a silent external state change, while SKILL.state needs 0 recovery steps.

  • Budget-matched controls collapse: truncation 0.18, LLMLingua 0.22, summary-capped 0.52, vs SKILL.state 0.94 at the same ~1.8k budget.
  • tau-Bench: 58.3% Retail and 32.4% Airline, both best-in-table, with Airline holding ~2,800 tokens/step where baselines peak above 11,000.
  • Open-weight models benefit relatively more at short/medium horizons (Gemma-4-31B 0.68 vs 0.55 Stateful at T=50) but converge at T=100 (0.42 vs 0.42).
  • One scenario per environment ('Canceled Order', 'PR Closed') defeats ALL runtimes — the paper does not claim universal recovery.

Failure modes and engineering implications

On Gemma-4-31B at T=100 the authors bucket failures: 68% premature state overwrite/deletion (the model omits existing keys instead of merging in place), 20% schema comprehension / type coercion, 12% JSON syntax slips. All three are structured-output-adherence problems rather than reasoning failures, which points at grammar-constrained decoding as the fix for small models.

  • The merge operator's semantics are the sharp edge: a patch-and-merge protocol with explicit null-deletion demands the model understand it is patching, not rewriting.
  • No wall-clock latency, GPU-hour or dollar cost is reported anywhere — the entire efficiency argument is token counts.
  • No code, data, or SkillExecBench release is linked; Appendix A gives full prompt templates for all four runtimes, which is enough to reimplement. The arXiv comment says 'accepted at EMNLP'.

Key findings

  • Discarding the reasoning trace after each validated state patch keeps the prompt flat at ~1,736-1,905 tokens from T=10 to T=200, converting O(T^2) cumulative token burn into O(T) — 16.2x less than the LangGraph-style baseline at T=100 and ~50x less than Memory at T=200 (122k vs 6.18M).
  • The gain is structural, not compressive: at an identical ~1,800-token budget, sliding-window truncation scores 0.18, LLMLingua 0.22 and summary-capped 0.52, while SKILL.state scores 0.94.
  • Adding structured state to a transcript is not enough — the LangGraph-style baseline keeps the full history and still degrades (0.91 → 0.88 on Warehouse T=100→200, 0.63 on Software Repo T=100). Removing the history is the operative change.
  • Zero-lag recovery from external state drift: a corrective observation takes effect immediately (0 recovery steps), whereas history-based runtimes hallucinate stale facts for 5-14 turns.
  • Real-benchmark generalization holds: InterCode CTF pass@1 54.2% at 387k total tokens vs 977k-1.13M for baselines; tau-Bench Retail 58.3% and Airline 32.4%.
  • Small-model failures are formatting failures, not reasoning failures: 68% premature state overwrite/deletion, 20% type coercion, 12% JSON syntax — arguing for grammar-constrained decoding rather than a bigger model.

Notable quotes

The language model never receives previous observations, previous actions, or previous reasoning traces.
Crucially, within-step multi-step reasoning is fully intact during generation to support complex deductive planning.
Sliding-window truncation drops to 0.18 because critical early inventory allocations are evicted.
This error distribution shows that small-model degradation stems from structured output adherence rather than reasoning capacity, motivating constrained decoding in future runtime iterations.

Limitations

  • The design rests on the state being a sufficient statistic for the future. The authors name three settings where it fails: no fixed schema is known in advance; a correct update depends on an earlier observation whose relevance was not recognized at the time; or the objective is defined over the trajectory itself (auditing, provenance debugging), where history is the deliverable.
  • Single-agent only, with hand-authored per-domain schemas; multi-agent use would introduce concurrent writes requiring deterministic conflict-resolution semantics the merge operator does not have.
  • No latency, throughput or monetary cost is reported despite the abstract motivating the work partly with latency, and no code or SkillExecBench release is linked — the efficiency argument is entirely token counts.

Open questions

  • What is the actual end-to-end latency and dollar profile? Discarding history kills prompt-cache reuse across steps, which could offset token savings on providers with cached-input pricing — never measured.
  • Does grammar-constrained decoding actually recover the 68% overwrite-and-delete failures on open-weight models, or is in-place merge a semantic skill constrained decoding cannot enforce?
  • Could a small state serve as the query key into a durable archive, making the 'relevance recognized too late' failure mode recoverable rather than fatal?
