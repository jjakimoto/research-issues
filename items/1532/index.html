    From Experiments to Decisions: Reusing Evidence in Autonomous Coding Research

    Source: arxiv · 2026-09-10
    Link: https://arxiv.org/abs/2609.13299

    A 400-task post-mortem of an agent-run coding campaign showing that persistent memory is not enough: agents carry forward conclusions their experiments never justified, so the paper proposes a five-field handoff record, a dispatch tree (investigate/repair/reopen/stop) and a promotion predicate that requires each check to both pass AND have evidence that it applies to the decision being made.

    Executive summary

    Bobber Cheng reconstructs how evidence was reused across a 400-task NeuroGolf (ARC-derived ONNX program-golf) campaign run largely by autonomous coding agents, plus cross-domain ROGII wellbore-prediction records from the same operator. Concrete episodes show both failure modes: an overbroad 'no scalar can help' exclusion refuted by an executable floating-point counterexample, and a coordinator that acknowledged a novelty-only stop then summarized it 51 minutes later as 'measured and closed'. From these the paper proposes an inspectable handoff (proposition/scope, candidate+evaluator identity, test or counterexample, gate-status vector, next action + reopening condition), a dispatch tree that treats stopping and reopening as equally constructive, and a formal promotion-eligibility predicate. The protocol is explicitly proposed practice, not an evaluated algorithm — no counterfactual control exists.

    The problem: memory stores results, not their scope

    Persistent memory lets the next agent recall an experiment while inheriting a conclusion broader than the evidence. A failed program, an exhausted family search, a component lower bound and an execution rejection each license different next actions; conflating them makes a system simultaneously too conservative about exploration and too permissive about promotion.

    • Thesis: preserve what each experiment justifies, not just what it produced
    • One exact failing input refutes a program under its evaluation conditions; a finite search without a survivor does not rule out other representations
    • Agents, not humans, performed the diagnoses; the human role was process steering (loop design, allocation), not per-solution review

    Execution-grounded verification, not an LLM judge

    Success is defined by a deterministic evaluator: each task needs an ONNX program for an ARC-derived grid transformation, with grids encoded as padded ten-color one-hot float32 tensors of shape (1,10,30,30). Every output entry is thresholded strictly above zero and compared against the complete encoded target — neither argmax nor visible-grid equality suffices — plus interface and execution checks. Score is max{1, 25 - ln(max{1, M+P})} over accounted intermediate memory M and parameter count P; incorrect or invalid programs score zero.

    • Grounding is execution + exact tensor comparison, so 'verified' claims are reproducible and re-runnable years later
    • The paper still warns: a finite-corpus maximum is not general correctness, a runtime guarantee, or a formal proof
    • Visible-output equality can hide padding differences the full-output evaluator catches

    Case 1 — a negative conclusion that exceeded its evidence (Task 129)

    A prior search report dismissed a one-scalar extension on the grounds that it 'can only scale or invert the monomial', reasoning about exact positive support. But the evaluator thresholds the result of finite-precision execution, a different equivalence. The later cost-one program P002 has idealized expression o_hw * n_c^23 * a^26; evaluated exactly with a single final rounding it predicts the wrong count-two answer, while the source-derived sequential model rounds 5070u -> 50u -> 0 and gets it right. The transferable operation: compare what an exclusion preserves against what the evaluator actually observes.

    • The flaw was the scope of the rationale, not the fact that the restricted search failed
    • The counterexample only licenses a bounded distinguishing test — it does not show the scalar program was generated and wrongly discarded
    • A conditional source model does not recover the original execution path

    Case 2 — different evidence warrants different next actions (Tasks 188/196/364/368)

    Task 188 shows the handoff risk directly: one worker rejected a factored cost-127 candidate on fresh-batch failures, and a later worker banked the same named program anyway, with no record that it read the earlier warning. Task 196 shows reopening: a note said bounded propagation was the only legal strategy but permitted reopening for a genuinely new construction, and a perimeter-signature approach improved 2360 to 2300 and passed 266 stored plus 2000 fresh cases. Task 368 shows stopping as constructive: a scoped rank argument plus admissibility checks justified retaining 852 rather than burning effort on excluded operators. Task 364 shows a repairable-but-unfinished candidate.

    • 'Remember failures' is insufficient — dispatch needs the scope, promotion needs the applicable counterexamples available to the validator
    • Equal costs are not equal bytes: a different 109-cost program failed 94/266 stored cases while another passed 266/266
    • A diagnostic instruction that always demands another implementation can itself waste research effort

    The proposed protocol: handoff, dispatch tree, promotion predicate

    Each handoff preserves five items: proposition and tested scope; program/evaluator identity; test or counterexample; gate-status vector; next action and reopening condition. Three authorizations are kept separate — permission to probe, eligibility to promote, warrant to exclude. The dispatch tree first asks whether evidence linkage or gate applicability is unresolved (never convert unknown into a prohibition or a pass), then whether an established applicable constraint rules out the route, then which uncertainty the next bounded check should resolve: validate, repair, reopen, or bounded discovery. Only promotion is formalized: eligible(p,E) = 1 iff for every required check q, both the applicability a_E(q,Gamma,k) and the result v_E(p,q) are pass; missing or conflicting evidence is 'unknown', not failure.

    • Statuses are three-valued (pass/fail/unknown) and bound to a specific candidate, evaluator, comparator and population
    • A changed candidate must retest still-applicable failures; old failure alone does not refute new bytes
    • A budget guard parks the route with a reopening condition rather than inferring impossibility
    • Worked handoff: a candidate withheld at 94/266 stored failures; the distinct controller rewrite passes 266/266

    Process-level failures and cost

    Two operator chains show the loop itself diverging from its target: an anti-starvation request implemented as a three-day rotation had to be corrected to full coverage before the deadline, and a discovery protocol demanding agreement on all 70 generated configurations before testing 60 stored cases was diagnosed as mismatched with the fixed-corpus objective. In ROGII, the coordinator compressed a novelty-gate stop into 'every mechanism cell measured and closed' about 51 minutes later. Reported spend is $800 in full-month subscription payments across roughly a two-week project.

    • A decision record must distinguish not-novel, not-measured and measured-failure through summary compression
    • Fixed-corpus score and general correctness are different claims
    • Campaign effort: roughly 213.5 hours, plus a later 51 h 2 min 12 s discovery interval

    Key findings

    • An overbroad exclusion ('a one-scalar initializer cannot add a new threshold relation') was refuted by execution semantics: unchanged P002 passes 265/265 complete stored targets, while a derivative keeping the same equation, operand order and scalar value but computing in binary64 before the final binary32 conversion passes 0/265.
    • Memory without scope caused a real unsafe handoff on Task 188: a worker rejected a factored cost-127 candidate after 10/2000 fresh failures, a later worker banked the same named program and then saw 5 failures in another 2000-case batch, and the record does not show the warning was ever read.
    • Candidate identity matters more than cost labels: one cost-109 program failed 94/266 stored cases while a distinct cost-109 controller rewrite passed 266/266 — 'equal costs are not equal bytes'.
    • Gating on a proxy can be actively harmful: in the retained ROGII S3 adaptation experiment, all three prefix-based acceptance thresholds produced worse pooled target outcomes than ungated adaptation, with the strictest gate worst.
    • Summary compression destroys distinctions that were correctly received: the coordinator acknowledged closure 'at its novelty gate, before any building', then ~51 minutes later reported 'every mechanism cell measured and closed'.
    • Archive scale and portfolio effect: 29,591 ledger rows over 400 tasks, 97 extracted cost states across 92 tasks, and 348 of 394 tasks with endpoint acceptance records improved — for a reported $800 in full-month subscription access over roughly two weeks.

    Limitations

    • Everything is a retrospective reconstruction of one operator's archive with no counterfactual control: the dispatch tree and promotion predicate are proposed, inspectable practice, never empirically evaluated.
    • Registry snapshots record strikes and costs, not observed exclusions — historical scratch-registry bytes and dispatch exposure are unknown, and time order does not identify causation.
    • The numerical explanation is a conditional source-derived model, not the original July execution trace; the nine-program replay covers 2187 retained cases, not private platform inputs.

    Open questions

    • Does enforcing an executable regression corpus of applicable counterexamples at promotion time actually save budget, and by how much, under a matched-budget comparison?
    • Can the applicability judgment a_E(q,Gamma,k) — whether a check is even valid for the requested decision — be automated, or does it inherently need a human or a separate verifier?
    • How should a coordinator's summarization step be constrained so that 'not novel', 'not measured' and 'measured failure' survive aggregation across many lanes?
