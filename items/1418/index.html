SkillWeaver: Web Agents can Self-Improve by Discovering and Honing Skills

📚 Foundations · 2026-09-10 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-10

Theme: Procedural memory and learned skills for self-improving agents
These systems turn successful interaction traces into reusable procedural knowledge without updating model weights. Agent Workflow Memory stores adaptable textual routines, while SkillWeaver discovers, practices, and debugs executable APIs; both improve transfer but make verifier quality and skill lifecycle management central concerns.
Source: arxiv
Link: https://arxiv.org/abs/2504.07079

Shows how autonomous web exploration can be distilled into executable, honed Playwright APIs that act as reusable procedural memory and transfer between agent backbones.

Executive summary

SkillWeaver is a non-parametric self-improvement framework in which web agents autonomously propose tasks, practice them, distill successful trajectories into reusable Python APIs, and test or debug those APIs. The resulting skill library expands the agent’s action space without model fine-tuning and can be transferred to weaker agents. Average success rose from 22.6 to 29.8 on WebArena and from 40.2 to 56.2 across four live websites.

Problem and procedural-memory representation

Web agents must adapt to complex, unfamiliar websites without overfitting to fixed task distributions. SkillWeaver externalizes procedural knowledge as executable Playwright functions rather than retaining raw trajectories or only natural-language routines, making the learned behavior structured, composable, and easier to transfer between agents.

  • The paper contrasts explicit APIs with trajectory-based fine-tuning and in-context demonstrations, which impose training, storage, and catastrophic-forgetting costs.
  • It reports that screenshot and HTML files from Mind2Web consume approximately 0.3 GB per trajectory with an average of 7.3 actions.
  • Each synthesized API includes a function signature, implementation, documentation, prerequisite state, and a usage log recording previous executions.

Three-stage autonomous skill pipeline

Stage I uses an LLM as an automatic curriculum to propose novel procedural, navigational, and information-seeking tasks, prioritizing short-horizon skills and progressing from simple routines toward compositions. Stage II practices proposed tasks, evaluates trajectories with an LLM reward model, and converts successful state-action sequences into generalized Python APIs. Stage III executes generated APIs as tests, creates parameter values when needed, and uses environmental feedback to debug them.

  • The proposal module receives screenshots, website names, URLs, accessibility trees, and the current skill repertoire.
  • The reward model judges completion from the task, action trajectory, screenshots, code outcomes, and observable website changes.
  • Static checks reject recurring generation errors, including unsuitable selectors and malformed function interfaces.
  • Previously synthesized APIs remain available during exploration, allowing later skills to call and compose earlier ones.

Evaluation design

The authors evaluate on five WebArena domains and on 57 manually evaluated Online-Mind2Web tasks spanning Drugs, Flights, Cooking, and Cars websites. Each website receives 160 exploration iterations, where an iteration attempts a proposed skill or tests an existing one. The default agent uses GPT-4o with a 10-step limit, while a GPT-4o-mini variant tests cross-model skill transfer.

  • WebArena supplies stable, functional evaluators; live websites test the approach under dynamic and noisy conditions.
  • The baseline uses atomic Playwright actions, while the skill-equipped agent adds retrieved APIs whose preconditions are checked.
  • The live subset contains 23 Drugs tasks, 17 Flight tasks, 8 Cooking tasks, and 9 Car tasks.

Quantitative results

On WebArena, GPT-4o’s average task success increased from 22.6 to 29.8, a 31.8% relative gain reported in the conclusion. GPT-4o-mini improved from 9.2 to 14.1, showing that skills synthesized with a stronger model can augment a weaker one. Across the four live websites, average success increased from 40.2 to 56.2, a 39.8% relative gain.

  • Every evaluated WebArena domain improved for both GPT-4o and GPT-4o-mini.
  • The largest live-site gain was on Flights, from 11.7 to 29.4; Cars remained unchanged at 11.1.
  • On live sites, synthesized APIs sometimes reached the required final state but the agent still failed subsequent steps demanding environmental understanding or visual reasoning.

Transfer, composition, and failure modes

The skill library acts as a plug-and-play action-space extension and can be reused by another API-capable agent without changing its architecture. Exploration also produced compositional APIs that invoked multiple simpler skills. However, the paper documents failures in retrieval, parameter selection, long-range planning, test-data generation, and the verification oracle itself.

  • Synthesized APIs were comparable to human-crafted APIs where official API support was low or medium, but weaker on high-support GitLab and Maps environments.
  • Agents sometimes failed to call an available relevant API or supplied parameters that produced empty results.
  • Exception-free execution was an inadequate success criterion because generated code could silence failures and still be marked verified.
  • Some functional tests could not be constructed without realistic website-resident inputs such as valid collaborator email addresses.

Key findings

  • Executable Python APIs provide an explicit, transferable form of procedural memory without updating model parameters.
  • A propose-practice-synthesize-hone loop lets an agent expand its own skill repertoire from autonomous website exploration rather than annotated demonstrations.
  • Average success increased from 22.6 to 29.8 on WebArena and from 40.2 to 56.2 on the evaluated live websites.
  • The same API library substantially improved GPT-4o-mini, supporting cross-agent knowledge transfer.
  • Compositional APIs emerged, but reliable skill retrieval, parameter grounding, and functional verification remained unresolved.

Notable quotes

Our objective is to develop a framework that enables web agents to autonomously discover skills and construct a continuously expanding skill library in the form of APIs.
To ensure efficient exploration and high success rates in subsequent skill practice and API synthesis stages, we specifically target short-horizon, reusable skills that can be completed within a single API call.
After a certain number of exploration iterations, we observe that the pipeline begins to generate compositional APIs that call multiple simpler APIs.
This represents a measure for evaluation having unintended consequences.

Limitations

  • The verification criterion could accept malfunctioning APIs that merely avoided raising exceptions, so honing did not guarantee functional correctness.
  • Exploration was performed separately for each website, and some tests required realistic site-specific data that the agent could not generate.
  • Agents still failed to retrieve suitable APIs, bind correct parameters, or complete tasks requiring long-range planning and visual understanding.

Open questions

  • Can semantic or state-change-based test oracles verify that a skill accomplished its intended effect while also detecting unsafe side effects?
  • Can reusable skills transfer across websites and survive interface drift without repeating 160 exploration iterations for every site?
  • How should retrieval, parameter grounding, and composition be improved so agents reliably invoke learned skills for long-horizon tasks?
