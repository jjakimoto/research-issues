Metrics That Write Themselves: Evolving an Evaluator from Its Own Blind Spots

📰 Latest · 2026-08-24 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-24

Source: arxiv · 2026-08-19
Link: https://arxiv.org/abs/2608.18744

A self-improving loop needs a metric before it needs a policy, and this shows an evaluator can author its own: EvalCEGAR treats a pool of small executable Python operators as a CEGAR abstraction, searches for a collision (two candidates the pool scores identically but ground truth separates), and hands that counterexample to an LLM as the authoring request. Every metric revision is grounded in EXECUTION (hidden EvalPlus unit tests), and the shipped artefact is 55 lines of Python with zero inference-time model calls — versus an LLM judge that ties its accuracy delta but charges one model call per candidate forever.

Executive summary

EvalCEGAR (AWS Generative AI Innovation Center) evolves an automatic evaluation metric as a pool of small Python operators that each flag one named defect, pass, or abstain, and vote. Borrowing counterexample-guided abstraction refinement from program verification, it reads the pool as an abstraction, finds a 'blind spot' (a signature class containing both a correct and an incorrect candidate), and uses that counterexample — not a prompt — as the operator-authoring request; when a blind spot defeats every attempt it widens the interface an operator may read instead of resampling. Validated on MBPP+/HumanEval+ where hidden unit tests give an exact oracle, the loop writes a 55-line operator that closes 15.4% of the gap to a perfect filter on 428 unseen tasks (delta +0.0065, p=0.0010) with a quarter of the best hand-written operator's flags, while the 15 hand-written operators applied together LOSE accuracy.

Problem: the metric is the bottleneck of any self-improving loop

A self-improving system needs a reliable automatic metric before it needs a policy — self-refinement, self-debugging and reflective loops all assume a signal that separates better answers from worse. Reference overlap misses semantics by construction, and an LLM judge carries position, verbosity and self-preference biases that belong to the judge rather than the answer. The authors' first attempt at the obvious loop stalled in two measured ways that become the problem statement.

  • Obstacle 1 — the operator space is enormous and a model asked for 'an evaluation operator' samples one tiny fixed region; scoring all 295 level-1 operators yields no discovery at all.
  • Obstacle 2 — what it writes repeats itself behaviourally: 183 operators that flag anything realise only 96 distinct flag sets; and a rejection teaches the loop only that a candidate failed, not which distinction it failed to draw.
  • Design choice grounded in an asymmetry: saying how good an answer is needs a standard nobody has written down, but pointing at something specific that is wrong usually does not — so each operator states ONE falsifiable objection and the pool votes.

The evolution topology: pool-as-abstraction, collision targeting, interface escalation

The operator pool maps each candidate answer to a signature — the vector of verdicts the pool returns. Two answers with the same signature are indistinguishable to the metric, so a same-signature pair that disagrees on ground truth PROVES the metric cannot express that distinction. The largest such signature class becomes the target, and the specification handed to the author model covers every training sample failing the same way plus every correct one (a spec naming just two samples is satisfiable by a lookup table — an earlier round measured exactly that failure). Each admission re-partitions the signature space, so the next request has moved by construction.

  • Level 1 interface: op(task, code). After 3 failed level-1 attempts the SAME target escalates to level 2: op(task, code, ctx), where ctx exposes peers, a runner, prompt-visible asserts and an input generator — capped at 600 observations over at most 16 peers, exposing nothing from the hidden suite.
  • A target surviving every attempt at both interfaces is abandoned; when all targets are abandoned the loop returns an 'insufficiency certificate' naming the distinction the vocabulary could not express.
  • Composition: admitted operators are combined by an m-of-k vote (m=2, k<=6) chosen on the training split with no dev split, no tuned threshold, no learned weights.
  • Author model is one FROZEN Claude Opus 4.7, 47-48 calls per run under a 60-call ceiling across 8 rounds; the faulty candidates it judges come from weaker generators, so the model that writes bad code never wrote the operators judging it.

What grounds a metric revision: execution, not an LLM judge

Ground truth is EXECUTION: hidden EvalPlus unit-test suites settle correctness outright, and they label only the training samples the loop targets and admits on. The authored operators are ordinary executable Python; a level-2 operator may run the candidate and its peers on perturbed inputs, but never sees the hidden suite. No formal proof and no LLM judge is anywhere in the admission path, and the shipped metric contains no inference-time model call at all.

  • Admission gate is a floor on the DEPLOYED DECISION evaluated on the training split: delta > 0, at least 3 tasks helped, helped > hurt. It is deliberately NOT a fault-coverage floor — the recall-gated arm rejected the best operator for covering none of the 140 known faults.
  • Four anti-leakage screens reject an operator before the gate sees it, each closing a way an earlier round accidentally reconstructed the oracle: deciding from syntax without running the candidate; keying on a constant the fault generator emits; branching on prompt keywords; and reaching a flag by text match while executing elsewhere.
  • Statistics are pre-committed: every delta tested against a size-matched shuffle null (b=1000, seeded), Bonferroni within families and Benjamini-Hochberg across screens.
  • The LLM's only role is authoring operator source code from a specification; it never sees ground-truth labels.

Setup and endpoint (why the numbers look small)

Tasks are Python problems from MBPP+ and HumanEval+ as distributed by EvalPlus. 150 MBPP+ tasks were split 75 train / 75 held out, then 228 remaining MBPP+ tasks and 125 of 164 HumanEval+ tasks were added to the held-out side, giving 428 unseen tasks and 2592 samples. The endpoint is SELECTION ACCURACY: drop what the metric flags from the candidates passing prompt-visible checks, draw one uniformly from what remains, and measure the change against flagging nothing.

  • Only 58 of the 428 held-out tasks are 'decidable', so accuracy runs from 0.7170 (flag nothing) to 0.7593 (perfect operator): total headroom 0.0424 — which is why absolute deltas are tiny.
  • The endpoint is recall-dominated: a flagged correct sample merely leaves the kept set, while a caught incorrect one changes what remains to draw from.
  • Human/oracle label budget for a new domain: ~10 decidable examples to author and admit, plus ~60 labelled candidates to decide which admitted operators vote.
  • Baselines: 15 hand-written operators, their strongest single member, and an LLM judge given exactly the level-1 interface in 4 configurations.

Results, transfer and the two necessary mechanisms

The loop-authored operator is 55 lines of Python: keep the peers that pass the prompt-visible asserts, run them and the candidate on perturbed inputs, and flag disagreement with the surviving plurality. It reaches 94.2% of the hand-written comparator's effect with a quarter of its flags, overlaps the closest hand-written operator at only Jaccard 0.245, and its +0.0065 rises to +0.0481 over the 58 decidable tasks alone. Both mechanism ablations, run inside the loop on identical information, drop admissions to zero.

  • 6 of 8 runs admit an operator; all 6 are positive out of sample and ALL 6 are level-2 operators.
  • Across the study the gate admitted 26 operators: 25 non-harmful held-out, 17 individually significant where chance predicts 1.3. The 15 hand-written operators are not such a pool: 9 flag anything, 5 are non-harmful, 1 is significant.
  • Transfer to HumanEval+ (different oracle module, prompt style, difficulty; nothing re-tuned): +0.0125, p=0.0010, +10/-1 tasks, 28.8% of that pool's headroom — matching the comparator EXACTLY with 36 flags against its 103.
  • Gate ledger: the narrow interface reaches 2 helped tasks 55 times out of 124 consultations and never reaches 3; the wider interface reaches 3 six times and every one was admitted.
  • Composition solved exactly: all 313,911 and 2,007,327 subsets enumerated and scored. The original TP-FP objective ranks its own argmax as low as the 4.9th percentile; balanced accuracy lands at the 91.1-98.7th percentile. Of 2,007,292 non-vacuous subsets, ZERO harm the endpoint.

Cost, reward-hacking risk, and why it matters for autonomous research loops

Cost is quoted in model calls from actual ledgers. The run that wrote the shipped operator made 47 authoring calls and every candidate scored since has cost nothing; all eight runs together made 376 calls. The LLM judge costs one call per candidate with nothing amortised — 1762 calls for a single pass, 37.5x the run that produced the operator. The judge ties the operator's delta (+0.0070 vs +0.0065) but on a near-disjoint flag set (Jaccard 0.105); their intersection is a high-precision region worth +13/-1 tasks and their union beats both parts.

  • Self-confirmation guarded structurally: operators never read the oracle, the four screens exist because an earlier round DID reconstruct it by accident, and the author model is not the grader.
  • Judge-specific contamination risk: both benchmarks are public, so a judge may have memorised solutions where an executable operator cannot.
  • Referential instability of the wider interface: growing the electorate from 3424 to 12744 samples changes at least one verdict for ALL 35 operators, so a deployed level-2 operator must pin its electorate — although held-out delta moves UP.
  • Portable rules for any pool of executable checks: admit on the decision not on coverage; when nothing resolves a counterexample, widen the interface; on a selection endpoint, weight the classes by the training TP/FP ratio.
  • An independent verifier-induction search agrees on where the wall is: 2 of 48 admitted at level 1 with an unrejectable null, 6 of 16 at level 2 (+0.0054).

Key findings

  • Ground truth is EXECUTION, not a judge: EvalPlus hidden unit-test suites are the exact oracle, and an operator is admitted only when it improves the deployed selection decision (delta > 0, >=3 tasks helped, helped > hurt) — a fault-coverage floor instead admits ZERO operators in 3 of 3 seeds and would have rejected the best operator.
  • The shipped metric is a 55-line Python operator with zero inference-time model calls: +0.0065 = 15.4% of headroom on 428 unseen tasks at p=0.0010 with 126 flags, versus the hand-written comparator's +0.0069 with 515 flags; the 15 hand-written operators applied together LOSE accuracy (-0.0067).
  • Cost asymmetry is permanent: 47 authoring calls once (376 across all eight runs) and nothing per candidate, against the judge's 1 call per candidate forever — 1762 calls for a single pass, 37.5x the authoring run.
  • Interface escalation is necessary, not merely helpful: 336 level-1 attempts admitted nothing, and all 6 successful operators are level-2. An independent verifier-induction baseline hits the same wall.
  • Transfer holds without re-tuning: on HumanEval+ the authored operator matches the best hand-written operator EXACTLY (+0.0125, same 10 helped and 1 hurt tasks) with 36 flags against 103.
  • Composition is safe and its objective was mis-specified: of 2,007,292 non-vacuous subsets ZERO harm the endpoint, while the original TP-FP objective ranks its own argmax as low as the 4.9th percentile.
  • An LLM judge on identical information ties the delta (+0.0070) but on a near-disjoint flag set; the 27 flags they agree on are worth +13/-1 tasks, so the operator's value is a complementary, checkable error profile rather than a higher ceiling.

Notable quotes

An operator is admitted only if it improves the decision the metric is deployed to make, not if it covers more known faults, and admitted operators vote.
This changes the coordinates of the search instead of resampling within them: if the useful operator is not expressible at level 1, no amount of sampling finds it.
A checkable operator and a model judgement fail on different inputs, so their agreement is a high-precision region neither reaches alone.
And the loop is not the only route to an operator of this quality: a judge ties its delta, so what it buys is a complementary error profile, not a higher ceiling.

Limitations

  • Everything is validated where an exact oracle already exists (MBPP+/HumanEval+ hidden unit tests), which is precisely the setting the method is NOT for; the motivating case — open-ended output with no oracle — is never tested, and the paper concedes 'Where unit tests exist, run the unit tests.'
  • Effect sizes are tiny in absolute terms (+0.0065 on a 0.0424 headroom, only 58 of 428 held-out tasks decidable), every delta is measured only against 'flag nothing', and no two rules separated in 9 paired tests.
  • The operator prior duplicates itself: 183 operators that flag anything realise only 96 distinct flag sets, and 9 of 14 admissions on fresh seeds were rediscoveries.
  • Level-2 verdicts are a function of the peer electorate rather than of the candidate alone, so a deployed operator has to pin its electorate; and what the gate discards is unmeasured.
  • Reward-hacking risk is real and only structurally contained: earlier rounds reconstructed the oracle by accident (each of the four screens closes one such route).

Open questions

  • Does the loop actually work where no oracle exists? The method is motivated by domains with no usable metric but only validated where hidden unit tests settle correctness.
  • How do you break the operator prior's behavioural duplication? The authors point to an explicit behavioural archive (MAP-Elites style) as the untried remedy.
  • Since the judge and the operator tie on delta while failing on near-disjoint inputs, should a self-improving loop deliberately compose executable operators WITH a model judge, and how should the combined signal be weighted?
