    SkillApt: Learning When to Activate Agent Skills from Counterfactual Evidence

    📰 Latest · 2026-09-26 Full Article
    Read full article →View on GitHub

    Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
    Date: 2026-09-26

    Source: arxiv · 2026-09-22
    Link: https://arxiv.org/abs/2609.26863

    Shows that 'should I load this retrieved skill' is a separate decision from 'is it relevant': a lightweight, unlearned gating rule matches baseline accuracy while loading skills only 31.5% of the time and cutting tokens ~74% - directly relevant to any agent harness that stuffs every retrieved skill or tool doc into context by default.

    Executive summary

    SkillApt is a post-retrieval activation controller: given a candidate skill a retriever already surfaced, it decides LOAD or ABSTAIN by comparing the current task state against a store of paired WITH/WITHOUT execution outcomes for that same skill, rather than assuming relevance implies usefulness. On the frozen SRA-Bench confirmatory evaluation (111 states, gpt-5.6-terra) the evidence-based variant SkillApt-E matches BM25 Top-1's observed accuracy (0.838 vs 0.838) while cutting activation from 100% to 31.5% and mean token usage from 4,782 to 1,231 (-74.3%). A cross-model diagnostic on SpreadsheetBench shows both skill utility and how learnable the activation boundary is vary substantially by base model, with weaker models' controllers degenerating to trivial policies.

    The problem: relevance is not the same as execution utility

    The paper frames the standard retrieve-then-inject pattern for LLM agent skills as conflating two different questions. A skill can be semantically on-topic yet still be unnecessary, costly, or actively harmful in a specific execution state.

    • Motivating example: a spreadsheet-repair skill may rescue one execution, merely add tokens and latency to another where the agent already knows the fix, and steer a third toward the wrong edit - all three look equally relevant to a retriever.
    • Framed as: given a candidate skill, should it actually be activated in the current execution state? - distinct from which skill is relevant.
    • Positioned as complementary to retrieval, progressive loading, and skill acquisition/refinement work, none of which estimate state-conditioned marginal utility of activation.

    The gating mechanism: counterfactual evidence plus a fixed threshold

    SkillApt has three components - counterfactual evidence construction, evidence-conditioned applicability estimation, and a LOAD/ABSTAIN policy - plus evidence accumulation. It has no learned parameters and no threshold optimization.

    • Evidence construction: for a skill and state it records matched WITH and WITHOUT executions identical except target-skill availability (same task, model, decoding config, environment, evaluator); the utility contrast is stored per pair, and infrastructure failures censor the pair rather than creating a negative label.
    • State representation: a deterministic 256-dim signed feature hash - lowercase, whitespace-tokenize, add adjacent bigrams, assign each token a coordinate and sign via SHA-256, sum, L2-normalize. Explicitly not a learned state encoder.
    • Evidence score: a similarity-weighted vote over the 5 highest-cosine-weight historical pairs, returning exactly 0.5 with no evidence (a unit-weight prior).
    • Decision rule: Quarantine if the skill is flagged environment-invalid; else Load if the score exceeds 0.5, otherwise Abstain - a fixed threshold, with equality abstaining.
    • A fusion ablation averages the evidence score with a semantic-similarity baseline, but is explicitly a higher-cost ablation, not the default controller.

    Benchmarks, models, and skill library

    The primary evaluation is SRA-Bench (skill retrieval / incorporation / execution); a second benchmark and four extra models are used only for a cross-model diagnostic.

    • SRA-Bench scale: 5,400 tasks, 26,262 corpus skills, 636 gold skills. The paper froze 48 skill identities x 5 development + 5 locked-final states; 4 domains were executable - CHAMP, LogicBench, MedCalc-Bench, TheoremQA (ToolQA and BigCodeBench were infrastructure-blocked).
    • SRA runs use gpt-5.6-terra (temperature 0, top-p 1, low reasoning effort) with unchanged official evaluators.
    • Cross-model diagnostic on SpreadsheetBench with separately fitted per-model controllers: Terra, Qwen3-32B, Mistral-Small-3.2-24B, Claude Sonnet 5.
    • Baselines: Never Load, Gold Always, BM25 Top-1, Semantic-only, and SkillApt-E+Sem.
    • Protocol frozen with seed 20260922 after a 32-state exploratory screen; 113 states designated confirmatory, 2 censored for timeouts, leaving 111 evaluated with paired bootstrap plus McNemar's test.

    Confirmatory results: same accuracy, a third of the activations, a quarter of the tokens

    On the 111-state frozen confirmatory set, SkillApt-E ties BM25 Top-1 on accuracy while activating far less often; the paper is explicit that the tie is not proven statistical equivalence.

    • SkillApt-E: accuracy 0.838, activation 0.315, mean tokens 1,231 (-74.3% vs BM25 Top-1's 4,782).
    • Paired accuracy delta vs BM25 Top-1: 0.00pp, 95% CI [-6.31, +6.31]pp, McNemar p=1.0 - observed equality, not statistical equivalence or superiority.
    • Other SkillApt-E diagnostics: useful-target recall 0.250, correctness-harm avoidance 1.000, cost-negative avoidance 0.916, unnecessary-activation rate 0.252.
    • Skill utility is heterogeneous even within one skill: of 145 executable development pairs, 24 were positive, 17 neutral, 104 negative (102 correctness-tied-but-cost-negative, only 2 correctness-harmful); 19 of 29 skills showed both positive and negative utility across their own states.

    Retrieval bottleneck, failure analysis, and cross-model diagnostic

    Because SkillApt only acts on what retrieval surfaces, weak retrieval directly caps the ceiling; a separate cross-model study shows the controller's behavior is not model-agnostic.

    • BM25 hits the true target skill for only 0.239 / 0.389 / 0.513 of confirmatory targets at rank 1/5/10 (MRR@10 0.301).
    • Failure decomposition of 53 target misses among the 111 states: 9 utility-positive misses, 4 applicability false abstentions, 2 candidate-selection errors, 28 negative activations, 11 base-capability limits, 2 censored.
    • SpreadsheetBench per-model controllers: Terra's 18/1/5 training mix supports selective behavior; Qwen3-32B's 2/0/22 mix triggers a preregistered majority-class stop; Mistral-Small-3.2-24B's controller abstains throughout validation.
    • Claude Sonnet 5 shows the clearest utility/learnability gap: Always Load reaches 0.750 accuracy vs 0.375 for Never Load, but Evidence-only stays at 0.375 with zero activation and Full fusion reaches only 0.450 at 12.5% activation.

    Real-world probe

    A small, separate real-world software-engineering lifecycle probe corroborates the pattern outside SRA-Bench.

    • 54 designed runs across 2 fixtures.
    • dataset-contract-repair held 100% -> 100% correctness with token medians dropping 203,892 -> 166,492.
    • eslint-global-import-cleanup rose from a partial pass rate to 3/3 on the affected fixtures (+20pp aggregate) with token medians dropping 1,051,919 -> 729,809.

    Key findings

    • SkillApt-E matches BM25 Top-1's observed accuracy on SRA-Bench (0.838 vs 0.838, paired CI [-6.31,+6.31]pp, McNemar p=1.0) while cutting activation from 100% to 31.5% and mean tokens from 4,782 to 1,231 (-74.3%).
    • The controller is deliberately unlearned: a fixed 0.5 threshold over a similarity-weighted vote across the 5 nearest historical WITH/WITHOUT pairs, using a 256-dim signed-feature-hash state representation rather than a trained encoder.
    • Skill utility is highly heterogeneous even within a single skill: of 145 executable development pairs, 104 were correctness-tied-but-cost-negative and only 2 correctness-harmful; 19 of 29 skills showed both positive and negative utility across their own states.
    • Retrieval is the binding bottleneck: BM25 surfaces the true target skill only 23.9% / 38.9% / 51.3% of the time at rank 1/5/10 (MRR@10 0.301).
    • Cross-model diagnostics show utility and boundary-learnability are model-dependent: Qwen3-32B and Mistral-Small-3.2-24B controllers degenerate to trivial policies, while Claude Sonnet 5's real 0.750-vs-0.375 Always/Never gap is only partially recovered (0.450 at 12.5% activation).
    • A small real-world software-engineering probe (54 runs, 2 fixtures) reproduces the pattern outside SRA-Bench.

    Notable quotes

    This is signed feature hashing, not a learned state encoder.
    SkillApt-E and BM25 Top-1 both achieve observed accuracy 0.838, while SkillApt-E reduces activation from 1.000 to 0.315 and mean tokens from 4,782 to 1,231 (74.3%).
    Incomplete retrieval bounds attainable downstream benefit.
    The evidence supports selective activation, not a universal controller or a new retrieval method.

    Limitations

    • The accuracy tie with BM25 Top-1 is only observed equality, with a paired CI spanning [-6.31, +6.31]pp.
    • The v1 controller has limited useful-target recall (0.250) and still produces 28 negative activations; it is a post-retrieval complement, not a substitute for candidate generation or base-model capability.
    • Cross-model transfer of the SRA-fit policy is unestablished; SpreadsheetBench diagnostics use separately fitted, model-specific controllers.
    • SRA-Bench has no official train/dev/test split, has sparse per-skill evidence, and final skill identities were not held out; two SRA domains and external SkillsBench paired validation were infrastructure-blocked.

    Open questions

    • Can the applicability boundary transfer across base models rather than requiring a separately fit controller per model?
    • How to raise useful-target recall (currently 0.250) and reduce negative activations without adding learned parameters?
    • Would a genuinely cost-aware utility label, rather than collapsing all correctness ties to 1/2, shift the LOAD/ABSTAIN boundary?
