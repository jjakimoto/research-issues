Can Agent Memory Systems Track Evolving State?

📰 Latest · 2026-08-24 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-24

Source: arxiv · 2026-08-20
Link: https://arxiv.org/abs/2608.19652

Every popular agent-memory substrate (Mem0, A-Mem, LightMem, MemoryOS, HippoRAG/LightRAG/GraphRAG, BM25/dense, and raw long context) is near-useless at answering with the CURRENT value of a fact after it has been revised across sessions — 0.09-0.28 accuracy, with 50-66% of answers landing on the specifically superseded value. Retrieval is not the bottleneck, and a ~350-token answer-time state-tracing wrapper buys +32 to +67 points on any backend without adding an LLM call.

Executive summary

Fan et al. (UIUC) isolate a failure they call state drift: the right fact IS in the assembled context, but the agent answers with a stale or un-recomputed version of it. They show drift is the leading confirmed failure category on existing memory benchmarks even under perfect retrieval (44.4% of LongMemEval-oracle failures; 63.5% on MemoryArena-shopping), then build StateMemBench — 234 synthetic multi-session scenarios / 322 probes generated as symbolic event programs, with closed-pool grading that scores whether an answer is the current state, the superseded state, or neither. Ten memory/retrieval systems plus four long-context models all score between 0.006 and 0.277 overall; their proposed StateMem (per-turn state units + supersession marking + a deterministic LLM-free dependency Rechecker) reaches 0.363 on DeepSeek-V4-Flash and 0.233 on Qwen-3.5-9B. Most usefully for practitioners, the same discipline applied as a prompt-level answer-time wrapper (fixed 155-token instruction + a 250-word question-scoped value-chain trace, replacing the answer call the backend already makes) lifts all six backends by +31.7 to +66.6 points on StateMemBench, of which +15.0 to +31.7 survives a length- and cost-matched control.

State drift: a failure axis distinct from recall and from reasoning

The paper defines state drift as acting on a stale or incomplete version of a fact that is present in context, and separates it from retrieval failure, comprehension failure, schema mismatch and reasoning failure with a conservative labeling procedure (a failure is assigned to drift only after all other readings are excluded; unassignable cases are dropped, plus an adversarial filter and cross-model-family judging). On LongMemEval's oracle setting recall is 1.0 by construction, so no residual failure can be retrieval in disguise — and drift is still the largest confirmed bucket. Drift is also not a reasoning shortfall: on 50 paired items, turning on DeepSeek-V4-Flash's reasoning trace did not help (84.0% to 76.0%, McNemar p=0.34), while explicit state maintenance on the same task did.

  • Judge-labeled rates are explicitly framed as upper bounds; human annotators assign LESS drift than the judge.
  • Inter-judge agreement: kappa=0.67 on LongMemEval, 91.6% raw on MemoryArena-shopping (PABAK 0.83); a cross-family GPT-4o judge agrees at kappa=0.37.
  • Drift concentrates where a decision integrates multiple sources: multi-session questions drift at 71.4% of failures vs 25.0% for knowledge-update questions.
  • Judges could agree THAT a failure was drift but not on its mechanism (mode kappa near zero) — the stated motivation for building a benchmark where the mechanism is fixed by construction.

How StateMemBench was constructed (programmatic traps, closed-pool grading)

Each scenario is generated as a symbolic event program — a sequence of typed state operations (rule declarations, value updates, scoped exceptions, commitments, retractions) over ground, derived and declared state. The gold answer is computed by deterministically replaying the program. In parallel they implement a family of 'lazy reader policies' (trust the most recent mention, trust the most frequent value, quote a stated derived value without recomputing, invalidate too eagerly); a scenario becomes a trap exactly when one or more policies disagree with full replay, and the disagreeing policies become its failure-mode signature. Causal dependencies are stated explicitly in the dialogue so no commonsense inference is needed — the benchmark measures maintenance, not discovery.

  • Five modes: status (superseded value wins), salience (louder/more frequent competitor wins, nothing was superseded), sequence (stale derived value not recomputed after an input changed), compound (interacting mechanisms), anti-trap (the anchored answer is CORRECT — catches over-eager invalidation).
  • Set A (short): 190 single-probe scenarios, 18 sessions, median 165 turns, ~3k tokens.
  • Set B (long): 44 scenarios fusing three trap threads into one ~38-session conversation, median 599 turns, ~7-15k tokens, probed by a three-part question (132 probes).
  • 234 scenarios / 322 graded probes total; grading is closed-pool — gold, the targeted policy's computed drift answer, and 1-2 neutral distractors (never shown to the model), so drift is a scored outcome rather than an inferred one.
  • Probe-category sizes: status n=116, sequence n=72, salience n=51, compound n=44, anti-trap n=39; domains finance n=93, shopping n=127, research n=102.

What was tested, and the failure modes that showed up

Baselines span four families, each run on two answer substrates (Qwen-3.5-9B and deepseek-v4-flash, thinking off, temperature 0, single run, graded by a fixed deepseek-v4-pro judge): retrieval (BM25, OpenAI text-embedding-3-small dense), graph-RAG (nano-graphrag, HippoRAG, LightRAG, GraphRAG), memory systems (Mem0, A-Mem, LightMem, MemoryOS), and long-context. Holding the full transcript is NOT a strong baseline here: the best long-context model reaches 0.277 and same-backbone long context only 0.149. Category ordering is stable across substrates: anti-trap sits near ceiling everywhere (0.69-0.92 — i.e. systems are good at NOT invalidating), while salience, sequence and compound are near zero for essentially every baseline.

  • The closed pool exposes a metric trap: LightMem, MemoryOS and no-memory land off-pool on 60-94% of cells, so their low drift-rates are an artifact of never producing a plausible answer at all — hence in-pool count is reported alongside drift-rate.
  • Among engaged methods on the weak substrate (Qwen), drift-rate is 61-66% for long-context, Mem0, BM25 and StateMem alike — the memory layer barely changes the outcome when the answerer is weak.
  • On DeepSeek, long-context / Mem0 / BM25 drift-rates move only 1-3 pp and correct answers 0-9, i.e. their bottleneck is the memory layer, not the answerer; only StateMem's drift-rate drops materially (64.3% to 49.1%) with correct answers rising 75 to 117.
  • Salience looks like a substrate ceiling rather than a memory-design problem: every Qwen arm scores at most 0.18 while GPT-5.4-Nano hits 0.569.
  • Zep is discussed as prior art (valid-time intervals on KG edges) but is not in the evaluated table; concurrent STALE uses an LLM adjudicator over a predefined schema, whereas StateMem's propagation is deterministic and LLM-free.

StateMem: state units, supersession, and an O(|E|) LLM-free Rechecker

Ingestion runs one TurnEncoder LLM call per conversational turn, parsing it into zero or more state units u = (id, content, priority in {hard, soft}, source, deps) with typed derived_from / coupled_with links, given the current compact rendering of active units as context; the encoder may also flag existing units as at risk of supersession and volunteer replacements. The update stage applies flagged supersessions (superseded units stay in the store for auditability but are withheld from answering) and then a deterministic Rechecker walks the dependency graph, marking any unit that depends on a just-changed unit as needs_recheck — O(|E|), zero extra LLM calls. Ablations locate the value precisely: extraction alone is worth little, supersession marking is the single biggest step, recompute guidance is worth ~6 pp, and dependency propagation is a wash overall because it over-propagates on Set B anti-traps (-12.5 pp).

  • DeepSeek ablation chain: extraction-only 0.174 -> +supersession 0.298 -> full 0.363; without recompute guidance 0.301; WITHOUT dependency propagation 0.373 (slightly better than the full system).
  • Qwen ablation chain: 0.155 -> 0.171 -> 0.233; w/o dep-propagation 0.222; w/o recompute guidance 0.208.
  • State tracking does not cost recall: StateMem is the best memory system on LongMemEval (0.580 Qwen / 0.656 DeepSeek vs Mem0 0.566/0.594) and on LoCoMo (0.566/0.592), with margins concentrated on temporal-reasoning (0.624 vs 0.391) and knowledge-update (0.795) question types.
  • Authors caution the StateMemBench margin is an upper bound because StateMem mirrors the same lazy-reader policy family that generated the traps; LongMemEval/LoCoMo are the generalization check.

The practical result: a ~350-token answer-time wrapper beats the whole machinery

StateMemWrapper keeps none of StateMem's storage machinery. It replaces the answer call the backend was already going to make, receiving the transcript, the backend's retrieved chunks and the question. Stage one (Trace) writes, scoped to the question, the value chain of every slot the question touches — initial value, each revision, current operative value, chronological with turn numbers — plus the latest stated inputs of every standing rule, capped at 250 words and committed BEFORE the answer to block post-hoc justification. Stage two (Resolve) commits under four precedence rules: later supersedes earlier, standing rules outrank instances, derived quantities are recomputed rather than quoted, and a fact is retired only by explicit supersession or expiry. A matched control equalizes call count, word budget, answer format and context but does generic question-conditioned extraction, so the wrapper-minus-control delta isolates structure from sheer text volume.

  • StateMemBench: +31.7 to +66.6 points over each backend alone (biggest for the near-floor LightMem and MemOS), of which structure contributes +15.0 to +31.7; significant in all twelve cells (paired McNemar p<=0.04, bootstrap CIs exclude zero) and beating the control in 23 of 24 cells.
  • LongMemEval is substrate-dependent: on Qwen structure carries the gain (+11.7 to +25.0, the generic control often HURTS), while on DeepSeek the control recovers most of the lift and structure adds only -5 to +5 — a strong answerer needs less explicit structure.
  • Question conditioning is load-bearing: a question-blind 250-word summary falls below the no-wrapper baseline on both benchmarks and has the highest drift rate of any arm.
  • The wrapper beats full StateMem on the same frozen scenarios (StateMem 0.283 vs at least 0.567 on Qwen) — when the transcript fits in context, resolve state at answer time; the persistent store earns its keep only when it does not fit.
  • Cost overhead is two bounded constants — a 155-token instruction plus the 250-word trace at 169-188 output tokens over the control — roughly 350 tokens per question independent of conversation length, i.e. 0.2% of the LongMemEval answer prompt.

Key findings

  • Drift survives perfect retrieval: on LongMemEval-oracle (recall = 1.0 by construction) DeepSeek-V4-Flash still fails 36 of 306 questions, and judges from two model families both confirm 44.4% (16/36, Wilson 95% CI [30%,60%]) as state drift — the largest confirmed failure category. It rises to 71.4% of multi-session-question failures vs 25.0% of knowledge-update failures.
  • Off-the-shelf memory does essentially nothing for evolving state: on StateMemBench (DeepSeek substrate) Mem0 0.177, A-Mem 0.199, GraphRAG 0.174, HippoRAG 0.184, LightRAG 0.093, LightMem 0.012, MemoryOS 0.025, dense retrieval 0.205 — none beats plain long context by much (0.149) and all are far below StateMem's 0.363.
  • Wrong answers are specifically the superseded value, not noise: engaged methods drift on 60-66% of probes (full context 64.0-65.5%, Mem0 59.9-62.7%, BM25 59.9-60.9%). StateMem is the only method whose drift-rate falls materially (64.3% -> 49.1% on the stronger backbone, correct answers 75 -> 117), while long-context/Mem0/BM25 shift by only 1-3 pp.
  • Systems are conservative in exactly the wrong direction: anti-trap scenarios (where the anchored answer is correct) sit near ceiling for everyone (0.62-0.92, dense retrieval 0.923), while salience (0.000-0.098 for most arms), sequence (0.000-0.056) and compound (0.023-0.16) are near zero. Nothing invalidates or recomputes.
  • Supersession marking, not fancy graph structure, is what pays: extraction-only 0.174 -> +supersession 0.298 -> full 0.363 on DeepSeek; recompute guidance is worth ~6 pp; dependency propagation over-propagates on long-horizon anti-traps (-12.5 pp) so removing it is slightly BETTER overall (0.373 vs 0.363).
  • The cheapest intervention is a prompt-level one: a question-scoped value-chain trace + four precedence rules, replacing (not adding to) the answer call, gives +31.7 to +66.6 points on StateMemBench across six backends for ~350 tokens per question — 0.2% of the LongMemEval answer prompt — with +15.0 to +31.7 attributable to the structure itself (significant in all 12 cells, p<=0.04). A question-BLIND 250-word summary is worse than no wrapper at all.
  • State tracking is not bought at the cost of recall: StateMem is the top memory system on LongMemEval (0.580 Qwen / 0.656 DeepSeek) and LoCoMo (0.566 / 0.592), essentially level with full-context on DeepSeek.

Notable quotes

Precisely, state drift occurs when a fact, constraint, or dependency established or updated across prior context is present in the assembled context, but the agent acts on a stale or incomplete version of the state rather than the one in force at decision time.
The adversarial traps defeat simply holding the full transcript in context.
When the transcript fits in context, resolving state at answer time is good enough, but the persistent store can be useful when it does not fit.

Limitations

  • StateMemBench is fully synthetic and its traps come from the same lazy-reader policy family StateMem was designed to counter, so the authors explicitly read their own benchmark margins as an upper bound and treat LongMemEval/LoCoMo as the generalization check.
  • The 'long horizon' is short: ~3k tokens in Set A and ~7-15k in Set B, far below modern context windows, so this measures drift well before true long-horizon pressure; the grading judge shares a family with one substrate, scenarios were rendered by a Claude-family model, both substrates are small-to-mid-scale (frontier answerers untested), and every reported number is a single run at temperature 0.
  • StateMem's ingestion is expensive — one TurnEncoder LLM call per turn, i.e. ~165-600 calls per scenario — so it costs far more than a long-context call; and the drift-prevalence rates are LLM-judge labels that human annotators consistently undercut (mechanism-level judge agreement is near zero).

Open questions

  • Does the answer-time wrapper still win once the transcript no longer fits in context? The paper's own result (wrapper > StateMem on the same scenarios) is contingent on transcript-sized answer calls, which is exactly what breaks at real agent horizons.
  • Can dependency propagation be made selective enough to keep its gains on sequence/compound traps without over-invalidating anti-traps (the -12.5 pp Set B regression that made removing it net-positive)?
  • Salience errors look like an answerer-capability ceiling (every Qwen arm at most 0.18 vs 0.569 for GPT-5.4-Nano) rather than a memory-design issue — so how much of state tracking is fixable in the memory layer at all versus requiring a stronger model to consume the explicit state?
