Harness or Model? Isolating the Harness Effect in Agentic Coding with a Contamination-Controlled Private Suite

📰 Latest · 2026-09-14
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-14

Source: arxiv · 2026-09-08
Link: https://arxiv.org/abs/2609.11987

A paired same-model study finds no resolvable capability advantage for vendor-native agent harnesses over a neutral one — but the neutral harness costs 1.2-1.6x more per solved task and stalls at the time ceiling far more often, and the paper doubles as a cautionary tale about how SDK usage-semantics mismatches can silently double-count cache tokens in agent cost reporting.

Executive summary

Arjmandi (evolutionID GmbH) ran 792 graded agent runs across 6 cells on a private, contamination-controlled 256-task suite (179 mined repository tasks + 77 post-cutoff contest problems), holding the model fixed and varying only the harness: claude-agent-sdk vs deepagents on claude-opus-4-8, and openai-codex SDK vs deepagents on gpt-5.5. Neither paired contrast resolved an average solve-rate advantage (-1.25 pp for Opus, +1.25 pp for GPT-5.5, both intervals straddling zero), but on Opus the aggregate hides a post-hoc workload interaction: native trails by 9.0 pp on repository tasks and leads by 23.7 pp on contest tasks (permutation p = 0.003). Completion and correctness separate sharply — 22 of 81 runs cancelled at the 1,200 s ceiling had already produced a passing patch. The revision's headline methods result is a usage-semantics defect in the author's own telemetry that double-counted cache tokens for deepagents cells, invalidating the August 2026 cost conclusions.

Design: paired same-model harness contrasts

Six cells cross three harnesses with four models. C1/C2 hold claude-opus-4-8 fixed (claude-agent-sdk 0.2.130 vs deepagents 0.7.4 / LangGraph 1.2.10); C3/C4 hold gpt-5.5 fixed (openai-codex 0.1.0b3 vs deepagents); C5 (gemini-3.5-flash) and C6 (deepseek-v3.2) are side cells. Every run is one chat session in its own KVM microVM with a fresh repo clone, an append-only event ledger, a 1,200 s wall-clock ceiling, and a Docker-isolated offline grading oracle. Vendor approval/sandboxing layers are disabled so all three harnesses face identical constraints.

  • 256 private tasks: Track A = 179 repository tasks from 4 production codebases with hidden FAIL_TO_PASS/PASS_TO_PASS tests and gold patches; Track B = 77 contest problems published after the eligibility date.
  • Frozen pool of 80 tasks locked by sha256; repeats k=2 for C1-C4, k=1 for side cells, giving 800 planned keys.
  • 792 of 800 keys graded: 380 pass, 404 fail, 7 timeout, 1 apply_error, zero grader errors.
  • Every grading environment gated on two invariants — polarity (gold passes, base fails) and determinism.

Contamination control

Four defence layers rather than a single private-suite claim. A machine-readable cutoff registry was frozen 2026-06-24; the eligibility date 2026-03-02 is the newest binding study-model cutoff plus a 30-day buffer. A runtime drift gate verifies the served model identifier before every scored phase.

  • The registry documents look-alike hazards — gemini-3.5-flash-lite carries a March 2026 cutoff past the eligibility date, so a silent substitution would void the control.
  • The drift gate caught OpenAI serving gpt-5.5-2026-04-23 for the pinned gpt-5.5, and DeepSeek self-reporting three different cutoffs across probes.
  • The author bounds the claim: documented cutoffs plus private provenance, not proof of zero exposure; the canary emission probe was never run on the study models.

Capability: neither contrast resolves an advantage

Primary uncertainty is a task-level bootstrap (10,000 resamples). Cell solve rates: C1 48.8%, C2 50.0%, C3 55.6%, C4 54.4%, C5 44.9%, C6 19.7%. The GEE logistic nativeness x vendor interaction is 0.12 on the logit scale (robust SE 0.23, p = 0.60). pass@2 is 57.7% for both Opus cells; 61.0% vs 57.1% for C3 vs C4.

  • Opus 4.8: -1.25 pp, 95% CI [-10.0, +7.5], sign-flip p = 0.89.
  • GPT-5.5: +1.25 pp, 95% CI [-4.4, +6.9], sign-flip p = 0.83.
  • The 80-task pool oversamples screening-discordant tasks (30% of the pool vs 9.4% of the suite), so all averages are conditional on that selection.

The post-hoc workload split

The Opus aggregate averages two effects of opposite sign: 61/80 x (-9.0 pp) + 19/80 x (+23.7 pp) = -1.25 pp. The difference of differences is -32.7 pp, CI [-56.7, -9.7]. Two permutation tests with different nulls agree (label shuffle p = 0.003, stratified sign-flip p = 0.014), as does the GEE (nativeness x contest 1.62, SE 0.66, p = 0.014).

  • On GPT-5.5 both harnesses solve 100% of the 19 contest tasks, so no interaction is estimable and the repository difference is +1.6 pp (null).
  • Per-family panel on Opus (native vs neutral): 39% vs 43% AccessCtl, 27% vs 42% IdentityApp, 46% vs 62% FieldSvc, 84% vs 61% contest.
  • The partition was chosen after seeing the data; the paper labels it exploratory and calls for a designed replication.

Correctness vs autonomous completion

The driver cancels at 1,200 s and the oracle grades whatever patch exists at cancellation, so a ceilinged run can still pass — decoupling two endpoints benchmarks usually conflate. The neutral harness reached the ceiling far more often and issued roughly twice the tool invocations at similar solve rates.

  • 22 of 81 ceilinged runs passed: C2 11/32, C4 4/7, C5 2/12, C6 5/29, C1 0/1.
  • Ceiling hits: C2 32 vs C1 1; C4 7 vs C3 0.
  • Median wall-clock for completed runs: 392 s (C1), 596 s (C2), 280 s (C3), 420 s (C4).
  • Median tool invocations per session: C1 44.5 vs C2 90.5; C3 51.5 vs C4 75.

The telemetry defect and corrected costs

The host normalizer added cache-read and cache-write tokens to tokens_in whenever those keys were present — correct for Anthropic's native API (input exclusive of cache), harmless for the codex SDK, but wrong for LangChain's usage_metadata, which reports input inclusive of cache, so the deepagents cells were double-counted. Reconciliation against raw per-turn events is exact for 693 of 703 rows carrying usage.

  • Under source semantics every cell caches at 87-98%; the August manuscript's 48% cache share was the arithmetic signature of the double count.
  • Re-priced at frozen list prices, cost per solved task: C1 $3.10, C2 $5.07, C3 $2.88, C4 $3.39, C5 $4.67.
  • Opus cost ratio 1.63 at list, 1.34 with C1 at its SDK-reported cost; GPT-5.5 ratio 1.18, CI [1.05, 1.33].
  • The corrected estimator reproduces billed OpenAI spend within 2-4% but leaves a 25-29% residual on Anthropic, where 58 runs ended with no usage record.
  • Allocating the $288 Anthropic residual moves the C2/C1 per-solve ratio between 0.68 and 2.29, so the billed ordering is unresolved.
  • The August manuscript's 2.6x and 1.8x ratios are formally withdrawn.

The truncation probe and concurrent work

A 12-task probe swapped deepagents' default 100,000-byte tool-output truncation for a native-like 30,000-byte cap; it is reported as an inconclusive pilot. Three concurrent 2026 studies address harness effects with different comparators, none running the vendor-native vs neutral comparison on the same model.

  • Whether the 30 KB cap ever bound cannot be established: events and wire traces retain tool results only as 2,000-character previews.
  • C2: $3.68 -> $3.43 per run; C4: $2.13 -> $2.43 per run.
  • Prior art: Harness-Bench (106 tasks, 5,194 trajectories), Vats and Golev's Scaffold Effect (0-8 pp paired differences alongside a 40x token spread), Lewis's Same Model, Different Harness.

Key findings

  • Neither paired same-model contrast resolves a harness advantage: -1.25 pp on Opus 4.8 (48.8% vs 50.0%) and +1.25 pp on GPT-5.5 (55.6% vs 54.4%); the GEE nativeness x vendor interaction is 0.12 (SE 0.23, p = 0.60).
  • The Opus aggregate averages two opposite effects: -9.0 pp on 61 repository tasks and +23.7 pp on 19 contest tasks, a -32.7 pp interaction with permutation p = 0.003 — but the partition was chosen after seeing the data.
  • 22 of 81 runs cancelled at the 1,200 s ceiling had already produced a passing patch, and the neutral harness hit the ceiling 32 times (C2) vs 1 (C1), with roughly double the tool invocations.
  • A normalizer rule that added cache tokens to tokens_in double-counted cache for the deepagents cells, because LangChain reports input inclusive of cache while Anthropic reports it exclusive; every cell actually caches at 87-98%, not the 48% first reported.
  • Re-priced from raw per-turn usage at list prices, the neutral harness cost 1.63x per solved task on Opus (CI [1.29, 2.09]) and 1.18x on GPT-5.5 (CI [1.05, 1.33]).
  • The corrected estimator matches billed OpenAI spend within 2-4% but leaves a 25-29% residual on Anthropic; allocating it moves the C2/C1 ratio between 0.68 and 2.29, so the billed ordering is unresolved.

Notable quotes

Correctness and autonomous completion are therefore distinct endpoints in our data.
The normalizer contains one rule that is correct for exactly one of the three harnesses: if the usage record carries cache-read or cache-write keys, add both to tokens_in.
What the pattern does establish is that a single aggregate solve rate is not the quantity a deployment decision needs.
A cap experiment needs demonstrated exposure to the cap.

Limitations

  • The 80-task pool is not a random sample — it oversamples screening-discordant tasks (30% vs 9.4%), and all 179 repository tasks come from four codebases inside one organization.
  • Configuration differences beyond the harness remain: the codex cell ran in 4 GiB VMs against 8 GiB elsewhere, inference budgets and tool surfaces differ, and ~30 tasks have white-box coupling whose per-task labels were not retained.
  • The design was never formally pre-registered; the workload split, outcome-flow reanalysis and probe re-reporting are all post-hoc.

Open questions

  • Does the repository-vs-contest sign reversal survive a designed replication with pre-specified strata and three repeats?
  • Was a correct patch available earlier in the ceilinged trajectories, and can agent stopping be optimized safely?
  • Does the truncation-cap hypothesis hold once evaluations log raw tool-output lengths and truncation-fired events per tool call?
