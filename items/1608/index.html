ReplicationBench: Can AI Agents Replicate Astrophysics Research Papers?

📚 Foundations · 2026-09-19
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-19

Theme: Execution-grounded autonomous-science evaluation
DiscoveryWorld evaluates complete discovery cycles in a controlled simulator, while ReplicationBench evaluates faithful reproduction of full computational papers against expert-authored numerical targets. Both show why procedural activity or plausible prose must be separated from successful experiments, explanatory knowledge, methodological fidelity, and correct results.
Source: arxiv
Link: https://arxiv.org/abs/2510.24591

Establishes expert-validated, paper-scale replication of real computational science as an objective reliability target for autonomous research agents.

Executive summary

ReplicationBench evaluates whether tool-using agents can reproduce the numerical core findings of complete astrophysics papers rather than answer isolated scientific questions. Its core dataset contains 20 peer-reviewed papers and 111 expert-written tasks; ReplicationBench-Plus adds 11 papers and 58 LLM-generated, expert-curated tasks. With a simple sandboxed scaffold, the best reported unweighted score is 0.22, and expert trace analysis exposes failures in persistence, conceptual fidelity, and technical execution.

Evaluation target

The benchmark treats successful replication as evidence that an agent can faithfully follow expert methodology and correctly execute a long-horizon computational workflow.

  • Each paper supplies a manuscript, dataset, execution metadata, and quantitative tasks covering core results.
  • Tasks include data processing, parameter estimation, Bayesian inference, simulation, theoretical calculation, and machine learning.

Dataset and task construction

The core set selects self-contained, peer-reviewed astrophysics papers whose principal results can run within six hours on a four-core CPU workstation and one GPU. Authors or domain experts write objective tasks, expected numeric outputs, tolerances, dependencies, and difficulty ratings; manuscript answers are masked to prevent copying.

  • Core dataset: 20 papers and 111 tasks, with average difficulty 4.1 on a 1–9 logarithmic scale.
  • ReplicationBench-Plus uses ShowYourWork repositories to create 58 LLM-generated, expert-curated tasks across 11 papers.

Agent protocol and scoring

Agents work in a Singularity/Apptainer sandbox with Python, shell, file operations, and a submission tool. Runs are capped at six hours and five million API-counted tokens; a numeric value is correct within its author-provided tolerance, a task earns credit only when all requested values are correct, and the main score averages uniformly across papers.

  • Seven frontier models were evaluated with three attempts per paper.
  • Datasets are pre-downloaded so evaluation emphasizes research execution rather than acquisition friction.

Benchmark results

All evaluated models score poorly despite high task-completion rates. Claude 4.5 Sonnet leads with a 0.22 unweighted score and 0.39 Best-of-N score; GPT-5 scores 0.18 and 0.28, respectively. Best-of-N consistently exceeds average performance, indicating that reliability—not complete absence of capability—is a central bottleneck.

  • Scores decline as expert-rated task difficulty increases.
  • Median runtime ranges from 2 minutes for o4-mini to 40 minutes for Claude 4.5 Sonnet, while median token use ranges from 10K to 32K.

Expert failure analysis and significance

Domain experts identify three recurring failure classes: premature submission or fallback answers, conceptual and procedural mistakes that simplify or omit required methodology, and technical failures involving resources, dependencies, legacy formats, or inefficient implementations. These errors can remain invisible to non-experts, supporting outcome-based, author-grounded evaluation before agents are trusted on novel research.

  • A no-computation baseline estimates memorization rates below 9% across evaluated models.
  • Removing manuscript masking can inflate some scores by 15–20 percentage points or more through direct answer copying.
  • The framework offers a scalable template for evaluating computational research agents beyond astrophysics, although transfer remains untested.

Key findings

  • The strongest model achieves only 0.22 unweighted paper-averaged performance, despite static scientific benchmarks nearing saturation.
  • Best-of-N gains are large for every model, with Claude 4.5 Sonnet rising from 0.22 to 0.39, showing substantial within-model reliability variance.
  • Agents commonly understand a paper's broad intent yet fail through subtle methodological omissions, premature fallback behavior, or inefficient technical execution.
  • Objective numeric grading with author-defined tolerances reduces dependence on subjective rubric judgments while preserving paper-scale realism.
  • Masking task-relevant results is necessary because unmasked manuscripts enable direct copying after failed replication attempts.

Notable quotes

We limit agents to a maximum of 6 hours of execution time, including both code runtime and language model response time, and up to 5 million total tokens as counted by the language model API.
For all models, Best-of-N performance is significantly higher than average performance.
Agents often execute incorrect procedures due to conceptual misunderstandings or reasoning failures, particularly by omitting necessary steps which require more advanced domain knowledge.
However, ReplicationBench does not measure agents’ ability to independently design research projects or iterate on truly open-ended directions.

Limitations

  • Difficulty ratings, task decompositions, and resource estimates depend on author or expert judgment and therefore vary in calibration.
  • The benchmark covers replication of known results in astrophysics, not independent research design or genuinely open-ended scientific iteration.
  • Evaluation uses simple scaffolds and does not systematically test browsing, multimodal inputs, memory tools, human supervision, or larger runtime and token budgets.

Open questions

  • How much can domain-specific scaffolding, persistent planning, memory, or human supervision improve replication reliability at fixed model capability?
  • Do ReplicationBench scores predict agent reliability in quantitative finance, machine learning, and other data-driven scientific domains?
  • Can hybrid human–LLM task generation scale the benchmark without changing task difficulty, coverage, or grading quality relative to author-written tasks?
