FinSkillBench: Evaluating AI Agents and Domain Skills for Investment Management

📰 Latest · 2026-08-24 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-24

Source: arxiv · 2026-06-09
Link: https://arxiv.org/abs/2608.18099

A 17,820-episode, execution-graded benchmark showing that giving an LLM agent curated, human-authored finance skill packages (procedures + validated Python solvers) lifts mean score from 0.366 to 0.528, while letting the agent write its own skills buys nothing (+0.005) at ~2x the tokens. The effect is about tooling and procedural plumbing, not model IQ — and it says nothing about live P&L.

Executive summary

FinSkillBench (Agent Skills '26 workshop paper at ACM CAIS 2026) is a point-in-time investment-management agent benchmark: 12 subtasks across portfolio construction, risk management and fundamental analysis, 2,603 task episodes, each with hidden ground truth and a task-specific deterministic verifier (no LLM-as-judge anywhere). The scientific manipulation is procedural-resource access, held factorial against fixed tasks, tool signatures, turn budget (12) and temperature (0): no-skill (empty skill corpus and domain tools withheld), curated (human-authored SKILL.md + validated Python entry points), and self-generated (agent must author 1-3 skill docs in-episode, then reload them). Over a full 17,820-episode run across 9 models, curated skills add +16.2 pp (0.366 -> 0.528, bootstrap CI [+0.152, +0.171]) with gains concentrated in optimization and risk tasks, while self-generated skills add +0.5 pp for ~2x median tokens; a cross-harness replication on Nous Research's Hermes Agent (8 models, 1,920 no-skill + 5,280 curated episodes) reproduces the direction but doubles the magnitude (+32.5 pp), which the authors attribute partly to the no-skill arm also withholding tools. The paper is explicit that this measures whether an agent can discover and correctly use domain resources, not unaided financial reasoning and not investment performance.

What is actually measured: 12 subtasks, structured outputs, deterministic verifiers

Each episode carries a task_id, domain skill label, subtask, an as_of_date, a visible input object, a hidden expected_output, and a verification object naming the scorer. Portfolio construction and risk management expose 40 tasks per subtask; the three fundamental-analysis subtasks have larger filtered manifests (243 / 179 / 148 for normalization / earnings quality / driver decomposition) of which the runner uses the first 100 each. Grading is execution-grounded and per-subtask, not a rubric or a judge model: labels fall into exact numerical (convex-solver outputs, Black-Litterman posteriors, stress P&L), semi-structured ranked (risk identification with partial credit for defensible alternative wordings), and accounting-derived (canonical line items, screen components, segment bridges with tolerances, typically 5% relative). Failure to emit valid JSON via the submission tool is scored invalid_submission or incomplete_submission rather than dropped.

  • Portfolio construction: unconstrained optimization (l2_distance_and_objective), constrained optimization (constraint_satisfaction_and_objective), tool-use parameterization (parameter_match), rebalancing (turnover_compliance_and_objective), Black-Litterman (view_specification_and_weights).
  • Risk management: constraint monitoring (exact_match), risk identification (ranked_list_recall), stress testing (absolute_error, ~1% P&L tolerance, 5% sector-attribution tolerance), risk remediation (constraint_satisfaction_plus_cost).
  • Fundamental analysis: XBRL normalization (metric_absolute_error), earnings quality (Piotroski components + Beneish flag + ratio terms), driver decomposition (driver_f1_and_direction).
  • Ground-truth computations lean on classical methods: Markowitz mean-variance, Black-Litterman, Fama-French 5-factor + momentum, Piotroski F-Score, Beneish M-Score.

How the data and labels were built (point-in-time discipline, leakage controls)

Three substrates: a market stack (daily OHLCV 2024-01 to 2025-12, dividend-adjusted prices, daily market cap, FF5+momentum, 8 macro series) yielding Ledoit-Wolf shrinkage covariances (252-day window, PSD-checked with ridge correction), rolling 252-day OLS factor betas, a 5-factor composite expected-return view (earnings yield 25%, ROE 20%, 12-1 momentum 25%, EPS revision 15%, low-vol 15%) scaled via Grinold-Kahn; a reporting stack from SEC EDGAR submissions and XBRL CompanyFacts; and, for risk management, constructed objects (200 synthetic portfolios with deliberately planted risk profiles, 12 mandates across 3 difficulty tiers, 12 stress scenarios = 4 historical replays + 8 hypothetical). Universe is a frozen 30-name, GICS-sector-stratified S&P 500 snapshot (chosen to avoid survivorship bias, at the cost of breadth). Ground truth is computed offline via cvxpy (SCS with OSQP fallback) and never shown to the agent.

  • Every episode has an explicit as_of_date; system prompts forbid post-date information and tooling returns only point-in-time slices.
  • Large numeric structures are deliberately lossy-compacted in the visible prompt (a covariance matrix is summarised) but available at full precision only through tool calls, so the benchmark tests whether the agent pipes exact inputs rather than reasoning off rounded text.
  • All 320 PC/RM ground-truth entries were validated twice: structural property checks plus re-derivation from stored inputs (exact reproducibility, L2 < 0.001 or abs error < 0.005; zero errors/warnings).
  • Per-domain automated validation: 9 checks (PC), 11 (RM), 12 (FA), including an explicit point-in-time leakage check; FA cross-source agreement is only 75.4% exact match.
  • Two ground-truth bugs were found and patched before the run: 'unconstrained' GT had been generated with the easy constraint set, and black_litterman() overwrote view_adjustments each loop iteration instead of appending.
  • No pretraining-contamination study is reported; leakage control here means point-in-time slicing and hidden labels, not a check against model training corpora.

The manipulation: three procedural-resource conditions, one agent loop

A ReAct-style function-calling loop with fixed system prompt, task prompt and tool schema; tools cover skill discovery/loading, skill authoring (self-generated only), retrieval of full task fields, script execution scoped to the active skill directory, domain data queries, and final JSON submission. Turn budget 12, up to 3 retries for transient provider failures, temperature 0. The design is factorial over the resource, not the interface: tool signatures are invariant across conditions. Notably, the no-skill arm withholds both the SKILL.md package and the finance domain tools (e.g. compute_risk_report, optimize_portfolio), so the measured 'skill effect' is really documents-plus-executables versus neither.

  • Models (main run): gpt-5.4, claude-sonnet-4.6, gpt-4.1, gemini-2.5-pro, grok-4, DeepSeek-V3.2, Phi-4, glm-5.1, gemini-3.1-flash-lite.
  • Full run: 9 models x 3 conditions x 12 subtasks, one sample per cell, 40 tasks/cell for PC and RM and 100 for FA = 17,820 episodes.
  • Reliability: 17,176/17,820 (96.4%) returned valid JSON; 644 (3.61%) invalid_submission; 3,736 (21.0%) hit the turn budget; 75 (0.4%) incomplete_submission.
  • Phi-4 scored 0.000 across all 1,980 of its episodes (turn-budget exhaustion) and is excluded from most condition analyses.

Results: curated skills help a lot, self-generated skills do not

Excluding Phi-4 (5,280 evaluations per condition), no-skill averages 0.366, curated 0.528 (+0.162, CI [+0.152, +0.171]) and self-generated 0.371 (+0.005, CI [-0.002, +0.011]). Gains track where the skill supplies executable computational primitives: portfolio construction +0.278, risk management +0.218, fundamental analysis only +0.054. At subtask level the ordering is almost entirely explained by baseline level — unconstrained optimization moves 0.247 -> 0.719 (+0.472) and risk identification 0.023 -> 0.332 (+0.309), while tool-use parameterization (baseline already 0.803) gains +0.069 and XBRL normalization is flat at -0.003. Model-level effects are heterogeneous and non-monotone in base strength: gpt-4.1 gains the most (+0.405), gpt-5.4 only +0.091, grok-4 goes backwards (-0.027, malformed final outputs), Phi-4 is flat zero.

  • Aggregate pooled mean across all conditions: 0.375, or 0.422 dropping Phi-4.
  • Curated is also slightly cheaper than no-skill on mean tokens (35,378 vs 38,783) and median latency (49.79s vs 59.75s) — the skill shortens flailing.
  • Self-generated skills load in 97.7% of non-Phi-4 episodes yet cost roughly double the median tokens (40,034 vs 19,952) and more turns (9.29 vs 7.46) for no accuracy gain.
  • Two failure modes block skill uptake entirely: turn-budget exhaustion (Phi-4) and malformed final outputs (grok-4).

Cross-harness replication: same sign, very different magnitude

The comparison is re-run on the Nous Research Hermes Agent with the same skills, tools, prompt template, submission protocol and max_turns=12, with all Hermes built-in skills, toolsets, memory and personality disabled except skills_list and skill_view. Eight models each ran 240 no-skill episodes (60 FA / 100 PC / 80 RM), 1,920 no-skill total against 5,280 curated. Overall 0.354 -> 0.679 (+0.325), with non-overlapping 95% CIs in every domain: FA +0.129, PC +0.435, RM +0.459. The no-skill baseline replicates closely (0.354 vs 0.366), but the uplift is roughly double the FinSkillBench harness's +0.162 — the authors attribute this partly to Hermes loading tools as Python functions rather than as scripts read from a skills folder.

  • Subtask cross-check: risk identification 0.023 -> 0.332 (+0.309) on FinSkillBench vs 0.043 -> 0.457 (+0.414) on Hermes; constrained optimization has similar baselines (0.148 vs 0.177) but very different deltas (+0.358 vs +0.087).
  • Open-weight glm-5.1 reaches the second-highest curated score (0.779), which the authors read as support for locally deployed financial agents where data privacy matters.
  • Their recommendation: report skill effects stratified by baseline level, because any single 'X pp uplift' number is conditional on that harness's tools, prompts and turn budget.
  • Because both no-skill arms withhold domain tools, neither number decomposes documents vs executables; a clean four-arm design is left to future work.

For the skeptic: what this does not show

The paper is unusually candid about its own scope. Curated-skill gains are not knowledge gains: skills bundle procedural reminders, API/argument-shape guidance, executable financial algorithms, and warnings about failure modes such as precision loss when passing covariance matrices through model-generated JSON. Because curated skills include validated Python, the object measured is the agent's ability to discover and use domain resources, not unaided financial reasoning — which makes comparisons to text-only finance benchmarks invalid. Labels are engine-derived, so a high score means agreement with the authors' cvxpy/Black-Litterman/XBRL pipeline and its assumptions, not economic correctness. Nothing here is a return, a Sharpe ratio out of sample, or a P&L.

  • One sample per (model, condition, task) cell at temperature 0; agent-loop variance is unmeasured, notably in the 21% of episodes that exhausted the turn budget.
  • Universe is 30 US large-cap names over roughly 2024-2025 (prices back to 2017 for RM), no derivatives, international, private or illiquid assets.
  • Driver decomposition has a ceiling: some expected labels depend on segment-level data not fully present in the processed XBRL panel.
  • Provider drift is acknowledged — the Phi-4 and grok-4 tool-calling failure modes may not reproduce on other endpoints or dates.
  • This is a workshop paper with a small author team; benchmark, skill packages, evaluation tools and full trajectories are said to be released.

Key findings

  • Curated skill packages (procedural Markdown + validated Python entry points) raise the mean score from 0.366 to 0.528 (+16.2 pp, bootstrap 95% CI [+0.152, +0.171]) over 5,280 paired evaluations per condition, excluding the non-functional Phi-4.
  • Self-generated skills are effectively free-lunch-free: +0.005 (CI [-0.002, +0.011]) despite loading in 97.7% of non-Phi-4 episodes and consuming roughly double the median tokens (40,034 vs 19,952) and more turns (9.29 vs 7.46) than no-skill.
  • Gains concentrate where executable primitives matter and where the baseline is low: portfolio construction +0.278, risk management +0.218, fundamental analysis only +0.054; unconstrained optimization 0.247 -> 0.719 and risk identification 0.023 -> 0.332, while XBRL normalization is flat (-0.003) and tool-use parameterization (baseline 0.803) gains only +0.069.
  • Skill benefit is not monotone in model strength: gpt-4.1 gains +0.405 versus gpt-5.4's +0.091; claude-sonnet-4.6 has the best no-skill baseline (0.534) and gains +0.125; grok-4 loses ground (-0.027) via malformed outputs and Phi-4 scores 0.000 on all 1,980 of its episodes by exhausting the 12-turn budget.
  • Deployment-style reliability is mediocre and reported rather than hidden: 96.4% of 17,820 episodes returned valid JSON, 3.61% were invalid_submission, 21.0% hit the turn budget, and 0.4% were incomplete.
  • The Hermes Agent replication reproduces the sign in all three domains with non-overlapping CIs but roughly doubles the magnitude (0.354 -> 0.679, +32.5 pp; FA +12.9, PC +43.5, RM +45.9 pp), which the authors trace to harness differences — a direct demonstration that headline uplift numbers are harness-conditional.
  • Scoring is fully execution-grounded: hidden expected_output per episode, twelve task-specific deterministic verifiers, no LLM-as-judge; all 320 PC/RM ground-truth entries passed property checks plus exact re-derivation (L2 < 0.001), while FA labels rest on two sources that agree exactly only 75.4% of the time.

Notable quotes

A 900-float covariance matrix emitted by a model and re-parsed into an optimizer differs from the source at the last few digits, and those differences change the optimum.
This suggests skill use is an interaction between model capability, tool-calling behavior, and skill-following reliability, not a monotone function of base model strength.
The 30-ticker S&P 500 sample supports controlled evaluation but does not cover all asset classes, international markets, derivatives, private assets, or illiquid securities.
It is not investment advice and should not be used to justify autonomous trading, suitability determinations, or client-specific recommendations.

Limitations

  • The 'skill effect' is not decomposed: the no-skill arm withholds both the SKILL.md package and the domain tools (compute_risk_report, optimize_portfolio), so the +16.2 pp (and Hermes's +32.5 pp) mixes documentation, executable solvers, and their interaction; the authors note a clean four-arm design is future work.
  • Labels are engine-derived (cvxpy solvers, Black-Litterman routines, an XBRL pipeline whose two sources agree exactly only 75.4% of the time), so scores measure agreement with the authors' modelling choices, not economic truth; the universe is 30 US large-caps over roughly 2024-2025, and one sample per cell at temperature 0 leaves agent-loop variance unmeasured including in the 21% of turn-budget-exhausted episodes.
  • Because curated skills ship executable Python, the benchmark grades an agent's ability to discover and drive domain resources rather than financial reasoning; it reports no live returns, no out-of-sample P&L, and no analysis of pretraining contamination (leakage control is point-in-time slicing plus hidden labels).

Open questions

  • Do self-generated skills pay off in a multi-episode setting where generated procedures persist, get tested, and are corrected over time — the regime this one-episode design explicitly cannot evaluate?
  • How much of the curated gain is procedural documentation versus full-precision executable tooling, which only the untested four-arm design can separate?
  • Is the 'gains are largest where the no-skill baseline is near zero' pattern a real ceiling effect, and does agreement with deterministic solvers on a frozen 30-name universe predict anything about performance on live, wider, multi-asset mandates?
