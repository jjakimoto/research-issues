Apodex 1.1: Scaling Agentic Intelligence for Complex Work

📰 Latest · 2026-09-12 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-12

Source: huggingface-daily-papers · 2026-08-24
Link: https://arxiv.org/abs/2608.23283

Apodex 1.1 argues the next scaling surfaces for agents are not parameters but executable environments and trained multi-agent coordination — and backs it with a 35B model that reaches a frontier performance band on professional, finance, and science work.

Executive summary

Apodex 1.1 is a general-purpose agentic model plus execution stack built around 'working capability': sustained, verifiable progress toward a real-world objective. It develops that capability along two explicit scaling axes - Environment Scaling (diverse, verifiable file/search/code worlds) and Agentic Coordination Scaling (trained decomposition, delegation, asynchronous integration, replanning) - joined by a shared harness and AgentOS runtime that owns workspace, provenance, coordination state, and a controlled delivery contract. Training combines a unified SFT mixture with PIVOT-RL, which localizes optimization at retrospectively identified 'pivot' decision points. Across professional work, finance, science, math, search, and coding, Agent Team consistently lifts ReAct scores, and a 35B Mini retains much of the gain.

The task contract: completed work, not answers

The report formalizes every task as a tuple of workspace space, initial workspace, objective, actions, transition operator, observation interface, resource budget vector, delivery contract, and a task-level verifier. A natural-language report can be an artifact in the workspace but does not itself define success; the verifier judges the completed delivery and is deliberately distinct from any verifier the solver can call as a tool.

  • Budgets may constrain turns, tool calls, tokens, wall-clock time, or concurrency.
  • Asynchronous user messages are admitted by the runtime, not chosen by the model.
  • A message that materially changes the objective or delivery contract instantiates a NEW task contract, even if workspace state carries forward.

Environment Scaling: file, search, and code worlds

Three environment families share one task contract but stress different bottlenecks: file worlds (authority and transformation), search worlds (discovery and evidence alignment), code worlds (executable transformation and verification). Scaling is allocated to measured capability gaps rather than uniformly, and difficulty is calibrated with an acquisition-pressure coordinate combining candidate count and hop count against the tool budget.

  • File-world coverage is profession-conditioned via a registry of 33 domains, 318 occupations, and 1,208 deliverable clusters.
  • Code worlds mix harvested worlds from real pull requests with synthesized worlds; verifier hardening precedes task perturbation.
  • Synthesized worlds are probed for reward hacking - only sandbox-successful attacks count as verifier failures, and scoring is isolated from the solver.
  • Construction principle: 'forward cheap, inverse expensive' - generators build and solve a world from latent state; the agent sees only the rendered workspace.

Agent Team 1.1: explicit task board and asymmetric verification

Apodex 1.1 externalizes the lead agent's decomposition onto a persistent task board (items with a bounded objective, dependencies, owner set, resolution state, returned evidence) and adds four capabilities: asynchronous human intervention, asymmetric verification, adaptive Max Team Effort, and evidence-grounded synthesis. Verification is deliberately narrower than generation - a verifier gets one claim, its evidence, and the applicable constraint, and tries to falsify it rather than re-solve the problem.

  • Board resolution states: open / in_progress / resolved / cancelled; 'resolved' is a semantic judgment, distinct from a subagent execution being 'reported'.
  • Adaptive Max Team Effort spends extra compute only on weak, contested, or load-bearing claims.
  • A dedicated post-execution synthesis stage builds a claim-evidence graph, then a writer agent drafts under the same citation/delivery constraints; untraceable claims are qualified or omitted.

AgentOS: runtime for long-horizon execution

Workspace state is instantiated as files, retrieved evidence, executable state/logs, artifact index, provenance dependency graph, and runtime control state. Three filesystem namespaces (/inputs read-only, /workspace scratch, /outputs deliverables) plus an optional read-only shared document library make the delivery contract checkable.

  • Tiered compaction is triggered by provider-reported token usage: first evict old tool-observation bodies, escalate to LLM summarization only if measured relief is insufficient.
  • Each budget has a soft deadline plus a hard timeout; on the soft deadline a bounded tool-free finalization call recovers a partial result instead of hard cancellation.
  • Delivery uses a single-publisher lease and an exact manifest of output paths, reconciled against a baseline snapshot so empty or stale files cannot satisfy the contract.
  • Stated limits: the publication guard is tool-level, not syscall-level; the coordination plane is run-scoped and not atomically checkpointed with the filesystem.

Training: unified SFT plus PIVOT-RL

SFT normalizes reasoning, tool use, search, file work, coding, math, professional delivery, and multi-agent coordination into one stateful interaction schema, with per-domain variants merged by model soup. PIVOT-RL then localizes RL at 'pivots' - retrospectively identified points where the policy adopts an unproductive strategy, leans on insufficient evidence, misuses a tool, or fails to revise an assumption.

  • At each pivot the useful prefix is preserved and a localized continuation is built with a short corrective hint; the hint is never a prediction target and is absent at inference.
  • Localized continuations are mixed with unhinted full tasks; completed trajectories enter optimization asynchronously to handle wildly varying wall-clock costs.

Evaluation: ReAct vs Agent Team, plus HDS6 process grading

Every benchmark is run in two modes - a minimal ReAct loop that exposes the underlying policy, and Agent Team that measures the lift from trained coordination. Beyond outcomes, HDS6 grades the execution process across six capabilities (long-horizon state coherence, evidence fidelity, hypothesis management, boundary/failure reasoning, tool and execution-state management, self-correction) with 24 rubric items plus an integrity gate.

  • HDS6 judging is outcome-blind, excludes private reasoning, and re-grounds every cited event against the recorded trajectory.
  • Largest HDS6 item deltas from v1.0 to v1.1: Initial Decomposition +1.3 and Final Verification +0.8.
  • The authors caution Deep Discover panels are not a strictly matched ablation (v1.0 aggregates eight runs, v1.1 is a single run).

Key findings

  • Agent Team coordination adds a consistent lift over the same model in a bare ReAct loop: +9.3 points on GDPVal (69.5 to 78.8), +4.1 on APEX-Agents, +5.6 on FrontierFinance, and +8.3 on FrontierScience-Research.
  • The 35B Apodex 1.1 mini reaches 40.0 / 45.0 / 24.2 (FrontierFinance / FrontierScience-Research / APEX-Agents) with ReAct alone, and 50.2 / 51.7 / 27.7 with Agent Team, leading the selected FrontierFinance comparison at a compact scale.
  • On the internal 41-task FrontierSearchBench, Agent Team scores 69.1 average versus 67.4 for GPT-5.6-Sol and 64.4 for Claude-Opus-5, and roughly halves the share of zero-credit tasks (19.5% to 9.8%) relative to its own ReAct run.
  • Math is the largest generational jump: Agent Team goes from 12.5/13.0/5.8 to 36.5/30.5/26.5 on IMO 2025, IMO 2026, and USAMO 2026 - above the stated reference thresholds of 35/29/25 - and 96.7% / 63.3% on IMO-ProofBench Basic/Advanced.
  • Coding remains the weak axis: 70.8 on Terminal-Bench 2.1 (vs 91.9 for Gemini 3.6 Flash) and 77.7 on SWE-bench Verified (vs 92.2 for Claude Opus 5).
  • End-to-end research delivery is hard for everyone: on the 97-task FrontierResearchBench, Apodex 1.1 w/ Agent Team passes 12.4% while the best evaluated systems pass only 20.6%.
  • The file-world scenario registry spans 33 domains, 318 occupations, and 1,208 deliverable clusters.

The two largest single-item deltas are Initial Decomposition (+1.3) and Final Verification (+0.8), which align respectively with the harness-supported organization of work and stronger verification behavior.

Limitations

  • Several headline comparisons are internally reproduced under the Apodex harness, and key benchmarks - FrontierSearchBench (41 tasks) and FrontierResearchBench (97 tasks) - are internal and not public, so the leading positions are not independently verified.
  • The HDS6 comparison is not a matched ablation: the Deep Discover v1.0 result aggregates eight runs while v1.1 comes from a single run, and HDS6 cannot attribute gains to any individual system component.
  • The runtime contract is explicitly not a correctness guarantee - the publication guard is tool-level rather than syscall-level, the coordination plane is run-scoped with no process-restart recovery, and BioMysteryBench numbers rest on tiny counts (4/17 and 6/17).

Open questions

  • How much of the Agent Team lift comes from trained coordination behaviors versus simply spending more inference compute? No compute-matched ReAct baseline is reported.
  • Why does the approach transfer so unevenly - frontier-band on finance and science research, but clearly behind on Terminal-Bench 2.1 and SWE-bench Verified, despite code being one of the three scaled environment families?
  • Can coordination state, message history, and the workspace be jointly versioned? Today a resumed run can only see the filesystem as it currently is.
