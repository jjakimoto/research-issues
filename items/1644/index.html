    Apodex 1.1: Scaling Agentic Intelligence for Complex Work

    ← Go backHacker News — Front Page: Front page turns over: agentic…NextStrategic Index Reconstitution: Differential Games… →
    📰 Latest · 2026-09-20 Full Article
    Read full article →View on GitHub

    Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
    Date: 2026-09-20

    Source: huggingface-daily-papers · 2026-08-24
    Link: https://arxiv.org/abs/2608.23283

    A full technical report on an agentic frontier system that argues the next scaling surfaces are not parameters but executable environments and trained multi-agent coordination — and backs it with a 35B 'mini' that reaches frontier-band scores on finance and science work. It is unusually concrete about the runtime contract (task board, /inputs-/workspace-/outputs namespaces, single-publisher delivery leases) that most agent papers leave implicit.

    Executive summary

    Apodex 1.1 (Apodex Team, 75+ authors) defines 'working capability' — sustained, verifiable progress toward a real-world objective — and develops it along two declared scaling dimensions: Environment Scaling (more diverse, verifiable file/search/code worlds) and Agentic Coordination Scaling (trained decomposition, delegation, async integration, replanning). Both are bound by a shared execution harness and AgentOS, a runtime that maintains persistent workspace, provenance, coordination state, and a controlled artifact-delivery contract. Training is SFT (model-soup merged across capability domains) plus an agentic RL method, PIVOT-RL, that localizes optimization at hindsight-identified 'pivot' decision points. Evaluation contrasts a bare ReAct scaffold against the Agent Team system across professional work, finance, science, math, search, and coding, plus an internal process-quality framework (HDS6).

    The task contract and what counts as done

    The report formalizes every task as E = (W, W0, q, A, T, Omega, B, D, V_D): workspace space, initial workspace, objective, actions, transition operator, observation interface, a resource-budget vector, a delivery contract D, and a task-level verifier V_D. A natural-language answer can be an artifact in the terminal workspace but does not by itself define success; V_D judges the completed delivery and is explicitly distinct from any verifier the solver may call as a tool. Asynchronous user messages are runtime admissions recorded in the trace, not model actions.

    • Budget vector B may constrain turns, tool calls, tokens, wall-clock time, or concurrent executions
    • Replay requires the environment manifest to preserve exogenous state, tool versions, and seeds
    • Outcome space Y_D may be a scalar, a vector of checks, or a structured verdict

    Environment Scaling: file, search, and code worlds

    Three environment families share one task contract. File worlds center authority and transformation over multi-format workspaces; the scenario registry spans 33 domains, 318 occupations, and 1,208 deliverable clusters, with difficulty driven by structural depth rather than file count. Search worlds center discovery and evidence alignment, with the gold object being the source set plus claim-to-evidence alignment, not a final answer. Code worlds are stateful sandboxes: harvested from real pull requests (fail-to-pass and pass-to-pass tests) plus synthesized worlds that get hardened verifiers before perturbation, with reward-hacking attacks tested in-sandbox. The construction principle is stated as 'forward cheap, inverse expensive.'

    • An acquisition-pressure coordinate rho_acq = (N_cand + N_hop) / B_tool calibrates difficulty for acquisition-heavy worlds
    • Each rollout gets an immutable world manifest plus a fresh mutable sandbox; sticky routing pins a session to one worker
    • A trajectory is retained only if initial state is reconstructable, execution isolated, and the verifier replayable
    • Failure allocation is gap-driven: unsuccessful trajectories are abstracted into capability deficiencies that spec the next Task Pipeline

    Agent Team 1.1 and AgentOS

    Apodex 1.1 externalizes decomposition from latent reasoning onto a persistent task board (items with stable ids, owners, dependencies, and states) held outside the LLM context and periodically re-injected after compaction. Four additions over 1.0: asynchronous human intervention, asymmetric verification (verifiers get one claim plus its evidence and try to falsify it rather than re-solve the problem), adaptive Max Team Effort (extra compute only to weak, contested, or load-bearing claims), and a dedicated evidence-grounded synthesis stage (claim-evidence graph, then a writer agent). AgentOS gives each run three namespaces — read-only /inputs, working /workspace, collection root /outputs — plus an optional read-only /shares library; publication uses a single-writer lease with an exact declared manifest reconciled against a baseline snapshot at termination. Context pressure is handled by tiered compaction (evict tool-observation bodies first, LLM-summarize the middle only if relief is insufficient).

    • Subagent execution lifecycle (created/queued/running/reported) is deliberately distinct from task-board resolution
    • With planning mode on, finalization additionally requires at least one delegated branch and an independent verifier
    • /outputs/scratch/ is the one shared, quota-bounded area exempt from the single-writer partition
    • Budgets have a soft deadline that triggers consolidation plus a bounded tool-free finalization call before any hard cancellation

    Training: SFT soup + PIVOT-RL

    SFT is a unified mixture (reasoning, tool use, search, file work, coding, math, science/finance, professional delivery, multi-agent coordination) normalized into a common stateful interaction schema, filtered for behavioral validity, with domain-specialist variants combined by model-soup merging. RL targets credit assignment on long trajectories: PIVOT-RL uses retrospective analysis to find 'pivots' where the model began an unproductive strategy, preserves the useful prefix, restores the executable environment state, and builds a localized continuation task with a short corrective hint that is never a prediction target and is absent at inference. Notably, neither the hyperparameters, data volumes, nor the full-size model's architecture are disclosed; the 397B parameter figure appears only incidentally in the HDS6 section, and Mini is stated as 35B.

    • Self-evolution is explicitly scoped to the managed engineering loop, not unconstrained self-modification
    • Rubric-scored SFT data selects task-relevant rubric dimensions rather than a single aggregate judge score
    • No pretraining corpus, compute budget, or RL hyperparameters are disclosed

    Evaluation: ReAct vs Agent Team, and process quality

    Every headline is reported twice — ReAct (minimal scaffold, exposes the model policy) and Agent Team (trained coordination plus organized compute) — which makes the system-level lift legible. Agent Team gains: +9.3 on GDPVal, +4.1 on APEX-Agents, +5.6 on FrontierFinance, +8.3 on FrontierScience-Research, +11.8 on BioMysteryBench. Coding is the visible weak spot, and the authors report it without spin. Beyond outcomes, HDS6 scores the execution process on six capabilities x four rubric items (24 items), judged agentically over a stitched multi-agent log, outcome-blind, with an integrity gate: a fabricated tool result or a narrated action that never occurred zeroes the whole trajectory.

    • FrontierSearchBench (41 internal tasks) scores in [-100, 100] with incorrect assertions penalized below zero
    • Agent Team roughly halves the share of zero-credit search tasks vs ReAct (19.5% -> 9.8%)
    • FrontierResearchBench is built on FrontierChallenge, 97 executable tasks in task-specific Docker environments
    • Largest 1.0->1.1 HDS6 item deltas were Initial Decomposition (+1.3) and Final Verification (+0.8)

    Key findings

    • Trained coordination, not just more agents, is the reported lever: Agent Team adds +8.3 points on FrontierScience-Research (55.0 -> 63.3), +5.6 on FrontierFinance (48.7 -> 54.3), +9.3 on GDPVal win rate (69.5 -> 78.8), and +11.8 on BioMysteryBench (23.5% -> 35.3%) over the same model under ReAct.
    • The 35B Mini is the sharpest result: ReAct alone lifts it from 33.2 -> 40.0 on FrontierFinance and 15.4 -> 24.2 on APEX-Agents vs Apodex 1.0 mini, and Agent Team pushes it to 50.2 / 51.7 / 27.7.
    • Math crosses the stated reference thresholds: Agent Team scores 36.5 (threshold 35) on IMO 2025, 30.5 (29) on IMO 2026, 26.5 (25) on USAMO 2026, and 96.7% / 63.3% on IMO-ProofBench Basic / Advanced.
    • Coding is where Apodex lags: 70.8 on Terminal-Bench 2.1 (vs 91.9 for Gemini 3.6 Flash) and 77.7 on SWE-bench Verified (vs 92.2 for Claude Opus 5).
    • End-to-end scientific delivery is hard for everyone: on FrontierResearchBench's 97 Docker-based tasks, Apodex 1.1 w/ Agent Team passes 12.4%, while the best system in the table reaches only 20.6%.
    • Environment construction is quantified: the file-world scenario registry spans 33 domains, 318 occupations, and 1,208 deliverable clusters, and every trajectory must be replayable to contribute training signal.

    A single integrity gate sits above the rubric: a fabricated tool result or a narrated action that never occurred zeroes the entire trajectory outright, bypassing the weighted score.

    Limitations

    • Comparability is uneven and the authors say so: many external numbers are their own internal reproductions under the Apodex harness (all external GDPVal entries, the Claude Opus 5 APEX-Agents result, the DeepSeek V4 FrontierFinance entries), the BioMysteryBench Claude 4.x rows use a different task set, and FrontierSearchBench / FrontierResearchBench are internal and not publicly reproducible.
    • Model disclosure is thin. Architecture, pretraining data, compute, RL hyperparameters, and training scale are absent; the full model's 397B size appears only in passing in the HDS6 section.
    • The authors flag real runtime boundaries: the publication guard is tool-level rather than syscall-level, and the coordination plane is run-scoped and not checkpointed atomically with the workspace filesystem, so process-restart recovery and filesystem rewind are out of contract — and the HDS6 Deep Discover panel is not a matched single-run ablation.

    Open questions

    • How much of the Agent Team lift comes from trained coordination behaviors versus simply spending more inference compute? The paper reports no compute-matched ReAct baseline, so the 'organized work beats more samples' claim remains asserted rather than isolated.
    • Why does a system engineered around file/code state and executable verification underperform on the most executable benchmarks (Terminal-Bench, SWE-bench)? The report does not analyze the gap.
    • Does PIVOT-RL's hint-conditioned localized continuation generalize, or does it teach recovery only from failure modes the retrospective analyzer can already name — and how is the hindsight pivot labeler itself validated?
