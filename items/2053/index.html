    OneStreamer: Unifying Perception, Memory, and Proactive Response in Streaming Video Interaction

    Date: 2026-10-07

    Source: huggingface-daily-papers · 2026-10-01
    Link: https://arxiv.org/abs/2610.01762

    A 4B Qwen3-VL fine-tune keeps only a 16-frame visual window. It has the model write its own timestamped captions as text memory, and it learns when to stay silent, stand by or answer by supervising only 27.5% of state tokens. It tops all eight streaming benchmarks it reports, beating the 11B MOSS-VL-Realtime on each, at about 1/14 the context and roughly 1/37 the time-to-first-token of keeping the full visual history. Weights (Apache-2.0), the OneStreamer-1M dataset and inference/eval code are on Hugging Face and GitHub.

    Executive summary

    OneStreamer is a streaming video LLM initialised from Qwen3-VL-4B-Instruct. It treats proactive generation as one interface for three things: writing memory, perceiving the current frames, and deciding when to respond. Proactive Hierarchical Caption Memory (PHCM) has the model emit time-aligned local-detail captions (triggered by an Observe control token) and event summaries (a Summary token). These text records are kept in context after their source frames leave a Recent-16 FIFO visual window. Proactive State Transition Learning (PSTL) supervises every output-anchor token but only a quota-capped subset of repeated waiting tokens. Trained for one epoch on the new 1.16M-record OneStreamer-1M corpus, the 4B model reports the best score among compared methods on all eight online perception/memory and proactive-response benchmarks.

    Problem: memory vs. real-time perception vs. response timing

    A streaming assistant has to keep evidence before it knows which observations will matter, and it has to answer as soon as enough evidence exists. Earlier approaches each fall short somewhere. Keeping or compressing historical visual tokens competes with recent frames for context and can hurt real-time perception. Streaming chain-of-thought traces are not reusable time-grounded fact records. Dense supervision of silence/response state tokens over-weights the many repeated silence labels compared with the rare response decisions.

    • Three QA settings are distinguished: Memory QA (past evidence), Perception QA (current frames) and Proactive QA (question first, answer once evidence arrives).
    • The paper cites prior evidence that extensive visual history can interfere with current perception, which motivates a short visual window plus text memory.

    Architecture and PHCM

    The video arrives as ordered clips. A vision encoder plus projector produce visual tokens, and a Recent-N FIFO window keeps only the latest N frames. These are interleaved with a text history of accumulated caption records and dialogue. The LLM predicts task-specific control tokens and generates text when a token starts an output. The Observe token starts a dense local-detail caption of objects, actions, scenes and state changes. The Summary token starts a sparser summary of a completed event. The Silence token means keep watching. For proactive QA, the Standby token means evidence is emerging but not yet sufficient, and the Response token starts the user-visible answer. Generated records are appended to the text history and stay after their frames are evicted. There is no retriever, memory encoder or re-access to discarded visual features.

    • During training, causal streaming caption targets supervise how the model interprets the video prefix it has seen so far. Each caption is released only after its supporting interval (or completed segment) has been observed.
    • For OVOBench/StreamingBench, memory is built from a 128-frame context at 4 fps, and questions are answered with that memory plus the 16 most recent frames at 1 fps.
    • Hierarchy ablation (OVOBench Overall): no memory 70.1, Observe only 71.7, Summary only 71.2, both 72.1.

    PSTL: selective state-token supervision

    State tokens in a sequence are grouped by transition (previous control state to current state). The quota q is the size of the largest group that ends in an output anchor (Observe/Summary for captioning, Response for QA and interaction). Every group is subsampled uniformly without replacement to at most q tokens. This keeps all output-initiating tokens and representative state-change and state-persistence tokens. Unselected tokens stay in the teacher-forced sequence and are masked only from the cross-entropy state loss. All caption and answer text keeps full supervision. PSTL is not applied at inference.

    • Supervises 27.5% of annotated state tokens.
    • Beats dense CE, dense frequency-balanced focal loss (Streamo), a random 27.5% subset, and transition-only (18.1%) supervision.

    Data: OneStreamer-1M and the synthesis pipeline

    1,160,004 listed records in four families: Proactive Caption Memory (60,000), Proactive Interaction (271,570), Proactive QA (197,584) and Perception & Memory QA (630,850). The data combines newly built OneStreamer-Core with cleaned open-source sets (Streamo, JoyAI-VL-Interaction, MMDuet2, ViSpeak, StreamForest, VideoChat-OL, Seeker, VST). Captions come from Gemini3.1Pro and Seed2.1Pro at frame/clip, segment and video level and are verified against the video. QA pairs get a coarse evidence interval that is checked by Qwen3.5-397B-A17B answering from the clip alone. Response times are then calibrated to the earliest near-peak second, scored with Qwen3.5-9B answer likelihood (reasoning tasks) or WeMM-Embedding-9B similarity (perception tasks).

    • Calibration moves response times earlier by 13.72 s on average, and 86.62% of records get an earlier time.
    • Training data is decontaminated at the source-video level against every evaluated test set, including non-overlapping clips from the same video.
    • Training: frozen vision encoder, projector and LLM trained for 1 epoch (1,174 steps), 131,072-token sequences, peak LR 1e-5, global batch 128, 991,773 loaded examples packed into 150,261 sequences, 32 H200 GPUs, plus offline LLaVA-Video data.
    • The data ablation step CQTC (verification plus timing calibration, no new samples) lifts OVO-Timing from 33.0 to 42.0 and the five-benchmark average from 53.4 to 55.6.

    Results, efficiency and release

    OneStreamer-4B scores 72.1 on OVOBench, 86.9 on StreamingBench Real-Time, 66.8 on OVBench and 71.3 on ODVBench. On proactive benchmarks it scores 48.7 on ProactiveVQA, 36.6 on OmniMMI (with ASR), 41.6 F1 on OVO-Timing and 2.87 on ViSpeak. That is +13.3/+5.1/+11.4/+13.7 and +14.4/+7.2/+12.2 over the Qwen3-VL-4B base. The paper reports an average relative gain of 25.0% over the base and 6.1% over the strongest competitor on each benchmark. At answer time on a 360 s OVOBench sample, PHCM uses 4,308 context tokens, 9.98 GB and 0.124 s TTFT, versus 62,094 tokens, 25.18 GB and 4.560 s for keeping the full history. Building memory online averages 0.636 s per 1 s update with a 128-frame window.

    • The paper itself only links a project page. The Hugging Face model card (not the paper) lists MCG-NJU/OneStreamer-4B weights under Apache-2.0, the MCG-NJU/OneStreamer-1M dataset, and GitHub MCG-NJU/OneStreamer with Inference/ and Eval/ code.
    • Competitor numbers are either taken from the original papers or re-run from released checkpoints (marked with a dagger). Re-runs use whichever of two settings (the original paper's or OneStreamer's) gives the higher benchmark-level score.

    Key findings

    • With only 4B parameters it beats the 11B MOSS-VL-Realtime on all eight benchmarks, for example 72.1 vs 70.2 on OVOBench, 66.8 vs 53.7 on OVBench and 41.6 vs 38.5 F1 on OVO-Timing. Its gain over the Qwen3-VL-4B base is up to +14.4 points (ProactiveVQA).
    • Keeping self-generated captions with the same Recent-16 window raises OVOBench Backward ASI from 63.5 to 71.6, beating full visual history (67.6). Real-time perception also improves slightly (OVOBench RT 80.9 to 81.4, StreamingBench RT 86.3 to 86.9), so memory does not cost perception. EPM is still slightly below Full (62.6 vs 63.0).
    • PSTL supervises 27.5% of state tokens and reaches 48.7/36.6/41.6 on ProactiveVQA/OmniMMI/OVO-Timing. A random 27.5% subset gets 26.6/27.4/1.4 and dense focal loss gets 47.0/32.8/26.5, so the gain comes from which tokens are selected, not from sparsity alone.
    • Compared with keeping the full history, PHCM cuts answer-stage context by 93.1%, GPU memory by 60.4% and TTFT from 4.560 s to 0.124 s. It adds only 1,272 tokens, 0.29 GB and 0.030 s over plain FIFO. Online memory writing averages 0.636 s per 1 s update.
    • Caption supervision is necessary: a model trained without the 60K caption-memory examples gains nothing from keeping its own descriptions as memory (OVOBench -0.1, StreamingBench +0.3), while OneStreamer gains +2.0 and +0.6.
    • Data quality alone matters: verifying content and calibrating response times without adding samples raises OVO-Timing F1 from 33.0 to 42.0.

    Notable quotes

    Dense state-token supervision can overemphasize waiting when repeated silence tokens outnumber output-initiating tokens, yet supervising only state changes omits direct supervision of when the current state should persist.
    These results suggest that inference-time prompting alone does not reproduce the memory gains obtained with dedicated caption supervision.
    Some response targets are assigned before sufficient visual evidence is available, which can encourage reliance on language priors and increase the risk of hallucinated answers.
    This case highlights two remaining challenges for evidence-grounded streaming interaction: accurately interpreting object-state changes and correcting earlier responses when subsequent evidence reveals an error.

    Limitations

    • Memory is append-only and the model does not go back to fix mistakes. In the paper's own failure case it describes a printer cover being lifted as 'closing' and then outputs silence for three more seconds while the open state is clearly visible. A wrong caption written into memory would likewise persist as a false fact.
    • Only one scale and backbone (Qwen3-VL-4B) is tested, and inference settings are tuned per benchmark (frame windows, fps, ASR on most OmniMMI tasks, an LLM judge for ProactiveVQA). Many baselines are re-runs that take the better of two settings, so cross-paper comparisons are not perfectly controlled.
    • The data pipeline depends heavily on proprietary annotators (Gemini3.1Pro, Seed2.1Pro) and large Qwen3.5 verifiers. The authors note that timing calibration does not always find the earliest answerable moment.

    Open questions

    • How does append-only text memory hold up over hours-long streams? The efficiency tests use 360 s clips, where it produced 26 observations and 2 summaries. Does memory need compaction or forgetting, and do early caption errors compound?
    • OneStreamer scores 99.5 on OVOBench HLD (hallucination detection) vs 41.9 for its own base model and 23.1-58.6 for the other baselines in the table. What drives that jump (answerability-judgment training data, caption memory, prompt format), and does it carry over beyond the benchmark?
    • Do PHCM and PSTL carry over to larger backbones, and to RL-trained response policies such as MMDuet2-style multi-turn RL, or is the gain specific to SFT at 4B?
