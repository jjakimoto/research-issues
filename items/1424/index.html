ExecCritic: Learn to Test, Test to Improve for Coding Agents

📰 Latest · 2026-09-10 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-10

Source: arxiv · 2026-09-08
Link: https://arxiv.org/abs/2609.09133

ExecCritic splits a coding agent into an independent Test agent and a Repair agent joined by a fail-closed harness that freezes the generated test during source-only revision, and post-trains each role separately with RL. On SWE-bench Verified the composed Qwen-3.5-35B-A3B pair reaches 72.6% resolved versus a 61.2% no-test baseline, while untrained self-generated tests actively hurt (57.3%).

Executive summary

The paper argues that when one agent trajectory writes both the patch and the test, their errors correlate and a wrong patch passes a wrong test. ExecCritic decouples them: a Test agent sees only the issue and the buggy Base checkout and emits a bundle (repository-native test patch, exact run command, JSON behavior contract); a fail-closed harness qualifies it by requiring a clean Base failure and then freezes it; a Repair agent iterates source-only patches against bounded execution feedback for at most five revision rounds. Both roles use Qwen-3.5-35B-A3B and are trained separately — SFT on 5K DeepSeek-V4-Flash trajectories then GRPO with execution rewards for the Test agent, and GRPO with a Round-0 direct-solve bonus for the Repair agent. Test quality, not the presence of feedback, determines whether the loop helps.

The coupling problem the scaffold targets

In repository repair the official evaluator is hidden, so the agent must construct its own stopping evidence. If the same policy writes the patch and the check, a shared misinterpretation shapes both — the paper's example is a bug that only triggers on an empty list, where the agent fixes the nonempty case and writes a test covering only that case. ExecCritic removes write permission over the test from the Repair agent.

  • Independence here is of generation context and write permissions, not statistical independence of errors
  • Test and Repair follow separate trajectories from the same public inputs (issue + Base checkout)
  • The harness, not the agent, decides admission: a Test bundle enters Repair only on a clean Base failure
  • Gold outcomes are used only in offline audit/reward, never inside the Test agent's trajectory

Topology and harness contract

One bundle targets one coherent issue behavior and may hold multiple test nodes/assertions. The Test agent gets at most five submission attempts per episode; failure to produce a clean Base failure marks a Base-gate failure, the Round-0 patch is kept and still scored. During repair the harness resets an isolated workspace to Base, applies the candidate source patch plus the frozen bundle, and returns bounded feedback. A local pass immediately terminates the episode; five failed revisions force-submit the latest candidate.

  • Test bundle = test diff + exact execution command + JSON behavior contract
  • Fail-closed: operational errors yield bounded diagnostics, never a behavioral verdict or local acceptance
  • Repair rounds: max 5 revisions of 40 turns each after Round 0; the test is immutable throughout
  • A local pass is a stopping condition, not a correctness claim — the official evaluator retains authority

Verifier grounding and reward design

Test reliability is grounded in Base-to-Gold success: the test must fail cleanly on Base and pass after applying the reference patch. RL additionally rewards balanced accuracy at discriminating up to eight deduplicated labeled candidate patches; single-class pools score 0.5 by convention, and any candidate execution hitting an operational error zeroes the whole trajectory's advantage. Repair reward is ordered on patch validity, selected-test passage, and official success, with a larger bonus for resolving at Round 0.

  • Test SFT: 5K CoT trajectories from DeepSeek-V4-Flash-0731 on SWE-ReBench, then 200 GRPO steps
  • DAPO-style dynamic sampling: 16 nonzero-variance issue groups x 8 rollouts = 128 rollouts per update
  • Length penalty: a rollout more than eight turns longer than the shortest in its group keeps half its reward
  • Repair training restricted to SWE-ReBench issues where the base model's Round-0 accuracy is low; forbidden test modification is treated as an invalid terminal patch

Results: test quality flips the sign of feedback

Holding the Base Qwen Repair agent fixed and varying only the feedback source shows the thesis: self-generated base tests are net negative. Frontier agents benefit too but with much smaller headroom on Verified than on Pro, attributed to Pro's broader F2P coverage.

  • Base Qwen Repair, no test: 61.2%; with Base-35B tests 57.3% (-3.9pp); with RL-35B tests 64.1%; with GPT-5.6-sol tests 65.3%; with Oracle F2P 69.4%
  • Trained Repair agent, no test: 68.3%; with RL-35B tests 72.6%; with Oracle F2P 77.6% — a 5.0pp remaining test-quality gap
  • GPT-5.6 on SWE-bench Verified: 81.5% -> 85.7% with generated tests (+4.2pp), 89.7% with Oracle
  • GPT-5.6 on SWE-bench Pro: only 61.6% -> 62.3% (+0.7pp) with generated tests, versus 73.4% (+11.8pp) with Oracle
  • Pro's F2P cases per instance: median 3 / mean 14.43 versus median 1 / mean 3.03 for Verified

Cost, overhead, and generalization

The composed gain is not compute-matched — it includes one-time test generation plus revision turns. Measured revision overhead is nonetheless modest, and the trained Test agent transfers unevenly to non-Python repositories after Python-only post-training.

  • 120 trajectories entered feedback-guided repair; additional Repair turns averaged 13, median 11, p75 ~17, p90 34
  • 35.8% of those used at most five turns; 47.5% at most ten
  • Cross-language Base-to-Gold: Python 62.2%, Rust 66.7%, C++ 58.3%, C 26.1%, Java 2.4%
  • Turn counts are explicitly not token usage, latency, or dollars — no monetary cost is reported
  • Code at github.com/MSR-Orchard/execcritic

Key findings

  • Self-generated tests from an untrained backbone are actively harmful: the same Base Qwen Repair agent drops from 61.2% to 57.3% resolved (-3.9pp) with Base-35B tests, but rises to 65.3% with GPT-5.6-sol tests and 69.4% with Oracle F2P.
  • Role-specific post-training lifts Test-agent Base-to-Gold success from 22.2% to 39.6% (SFT) to 62.2% (RL), roughly matching Codex-5.3 at 61.0% but still 25.6pp below GPT-5.6-sol's 87.8%.
  • Composing the two trained Qwen agents reaches 72.6% on SWE-bench Verified — 11.4pp over the no-test baseline and 4.3pp over the trained agent's own 68.3% Round-0 — with no stronger model or Oracle at evaluation time.
  • Imitation saturates before RL does: Base-to-Gold rises 1K->3K->5K SFT trajectories but 10K adds nothing, while on-policy RL from the 5K checkpoint reaches 62.2%.
  • Reasoning-visible teacher trajectories matter mostly for RL headroom: DeepSeek-V4-Flash (CoT kept) vs GPT-5.6-sol (no CoT) differ by 4.2pp after SFT but 26.0pp after RL (62.2 vs 36.2), despite GPT-5.6-sol being the stronger standalone model.
  • Overhead is small relative to the gain: only 120 trajectories entered feedback-guided repair, averaging 13 extra agent turns (median 11), with 35.8% finishing within five turns.
  • Feedback quality shapes credit assignment during training too — Repair training on Oracle F2P tests beats training on generated tests, 68.3/72.6 vs 67.6/70.9 (Round 0 / final).

Notable quotes

The patch and the test agree, but they agree on the same incomplete interpretation of the issue.
An unreliable test can instead steer revision toward an incomplete or incorrect requirement.
Across the 120 trajectories that entered feedback-guided repair, the number of additional Repair-agent turns averages 13, with a median of 11, a 75th percentile of approximately 17, and a 90th percentile of 34.

Limitations

  • Test and Repair are separate policies composed only after training; a shared-weight, role-conditioned checkpoint with end-to-end optimization is left to future work because joint training risks degenerate coordination between the roles.
  • The 72.6% composed result includes extra test-generation and revision compute and is explicitly not a compute-matched comparison against the 61.2% baseline; only agent turn counts are reported, not tokens, latency, or dollars.
  • Harness qualification does not prove semantic alignment with the issue, and one bundle covers one coherent behavior — the authors' coverage-based explanation for the weak +0.7pp result on SWE-bench Pro.
  • Post-training was Python-only; Base-to-Gold collapses to 26.1% on C and 2.4% on Java.

Open questions

  • Can a single role-conditioned checkpoint learn both test construction and repair end-to-end while preserving generation independence and test immutability?
  • What closes the remaining 5.0pp gap between RL-35B-test feedback (72.6%) and Oracle F2P feedback (77.6%)?
  • Why does reasoning-visible SFT data help RL so disproportionately, given that teacher identity and CoT visibility were varied jointly?
