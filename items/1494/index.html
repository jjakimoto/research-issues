ChatDev: Communicative Agents for Software Development

📚 Foundations · 2026-09-14
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-09-14

Theme: Role-structured multi-agent software development
ChatDev and MetaGPT made multi-agent coding concrete by replacing an undifferentiated agent with specialist roles and staged deliverables. ChatDev emphasizes paired conversational phases and clarification, while MetaGPT emphasizes SOPs, structured artifacts, dependency-aware routing, and executable feedback.
Source: arxiv
Link: https://arxiv.org/abs/2307.07924

Foundational operationalization of the software lifecycle as coordinated conversations among design, coding, review, and testing agents.

Executive summary

ChatDev turns software development into a chain of role-specific, two-agent conversations spanning design, coding, code completion, code review, and system testing. Its chat chain determines what agents communicate, while communicative dehallucination has assistants request missing details before producing solutions. The paper reports higher completeness, executability, consistency, and composite quality than GPT-Engineer and MetaGPT, alongside substantially greater time and token costs than the single-agent baseline.

Problem and motivation

Prior deep-learning approaches typically optimize isolated stages of the waterfall lifecycle with stage-specific models, leaving design, implementation, and testing technically fragmented. ChatDev instead treats natural and programming language as a shared interface through which specialized LLM agents can collaborate.

  • Software development requires coordination among roles with different expertise.
  • Single-step generation is poorly suited to tasks requiring iterative design and debugging.
  • Vague instructions are identified as a major source of coding hallucinations and incomplete compliance.

Role-structured chat chain

ChatDev decomposes development into three sequential phases and five subtasks: design, coding, code completion, code review, and system testing. Each subtask pairs a specialized instructor and assistant and extracts their agreed solution for the next subtask.

  • The dual-agent topology is intended to simplify consensus formation.
  • Inception-style system prompts specify each role, objective, tools, protocol, termination conditions, and constraints.
  • Short-term memory preserves dialogue within a phase; long-term memory passes extracted solutions rather than entire transcripts across phases.

Communicative dehallucination

The dehallucination mechanism reverses the normal instruction-response pattern: before providing a final answer, the assistant asks the instructor for concrete missing details and uses the reply to refine its solution. It is activated during code completion, review, and testing.

  • The mechanism addresses one concrete issue over multiple communication rounds.
  • A subtask ends after two unchanged code modifications or ten communication rounds.
  • The implementation uses ChatGPT-3.5 at temperature 0.2 and Python 3.11.4 for execution feedback.

Dataset and evaluation

The authors construct the Software Requirement Description Dataset with 1,200 prompts across five areas, 40 subcategories, and 30 prompts per subcategory. They compare ChatDev with GPT-Engineer and MetaGPT using completeness, executability, embedding-based requirement consistency, and a multiplicative composite metric.

  • ChatDev reports 0.5600 completeness, 0.8800 executability, 0.8021 consistency, and 0.3953 quality.
  • Against GPT-Engineer, ChatDev wins 77.08% of GPT-4 comparisons and 90.16% of human comparisons.
  • Against MetaGPT, ChatDev wins 57.08% of GPT-4 comparisons and 88.00% of human comparisons.

Significance and diagnostic evidence

The ablations indicate that staged communication, communicative dehallucination, and explicit roles all contribute to performance. Removing roles causes the largest degradation, reducing quality from 0.3953 to 0.2212 and executability from 0.8800 to 0.5800.

  • Code completion chiefly improves completeness, while testing is critical for executability.
  • Removing communicative dehallucination lowers quality from 0.3953 to 0.3094.
  • Natural language accounts for 57.20% of communication and supports system design, while programming-language exchanges drive implementation and debugging.
  • The framework makes intermediate conversations and solutions inspectable.

Key findings

  • A sequential chat chain connects role-specific design, implementation, review, and testing conversations through extracted solutions.
  • Communicative dehallucination makes assistants solicit precise implementation details before finalizing responses.
  • ChatDev achieves the highest reported score among the compared methods on all four automatic metrics.
  • Removing role descriptions produces the largest ablation loss, especially in executability and composite quality.
  • Multi-agent development generates larger codebases than GPT-Engineer but requires substantially more time and tokens.

Notable quotes

It’s worth noting that the conceptually simple but empirically powerful chain-style structure guides agents on what to communicate, fostering cooperation and smoothly linking natural- and programming-language subtasks.
We divided software development into 5 subtasks within 3 phases, assigning specific roles like CEO, CTO, programmer, reviewer, and tester.
Meanwhile, eliminating communicative dehallucination results in a decrease across all metrics, indicating its effectiveness in addressing coding hallucinations.

Limitations

  • The agents often implement simple, low-information-density logic and are presented as more suitable for prototypes than complex real-world applications.
  • The evaluation does not comprehensively measure functionality, robustness, safety, or user-friendliness.
  • Compared with a single agent, multiple agents consume more tokens and time.

Open questions

  • How well does the role-structured chat chain scale from prototype tasks to large, long-lived software repositories?
  • Can equivalent quality gains be retained with fewer agent interactions and lower token cost?
  • How can generated software be evaluated automatically for functionality, robustness, safety, and usability?
