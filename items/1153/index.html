Apodex 1.1: Scaling Agentic Intelligence for Complex Work

📰 Latest · 2026-08-28 Full Article
Read full article →

Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
Date: 2026-08-28

Source: huggingface-daily-papers · 2026-08-24
Link: https://arxiv.org/abs/2608.23283

A frontier-lab-style system report that is unusually explicit about the model/harness split — formal task contract, AgentOS runtime, trained multi-agent coordination — but the headline wins ride on that harness, several competitor numbers are the authors' own reproductions, and only the 35B mini weights appear to be released.

Executive summary

Apodex 1.1 argues agentic capability should be scaled along two surfaces other than parameters: Environment Scaling (executable file/search/code worlds with independent verifiers and replay) and Agentic Coordination Scaling (trained decomposition, delegation, staged fan-in, replanning), joined by a persistent runtime called AgentOS. Training is a unified SFT mixture merged by model soup, then PIVOT-RL, a hindsight-localized RL scheme that restarts trajectories at 'pivot' decision points with a hint that is never a prediction target and is absent at inference. Evaluation is reported in two modes — a minimal ReAct scaffold and the Agent Team scaffold — across GDPVal, APEX-Agents, FrontierFinance, YC-Bench, FrontierScience-Research, BioMysteryBench, HLE, DeepSearchQA, IMO/USAMO, Terminal-Bench 2.1, SWE-bench Verified, two internal benchmarks and a 24-item process rubric. The paper is candid about several evaluation caveats but discloses essentially nothing about architecture, pretraining, data volume, compute, cost, or safety.

What this document is (and is not)

A vendor system report, not a controlled study. Authorship is 'Apodex Team'. It defines a formal task contract and consistently distinguishes the model policy from the scaffold that runs it — the single most useful framing for a harness builder. Every quantitative claim is produced by the authors' own evaluation runs; no independent leaderboard entry is cited for Apodex itself.

  • The flagship parameter count (397B) appears exactly once, incidentally, in the process-rubric discussion — never in an architecture section. Mini is 35B.
  • No architecture family (dense vs MoE), active-parameter count, context length, pretraining corpus or token budget is given anywhere.
  • Checked at time of reading: the HuggingFace collection resolves and lists only Apodex-1.1-mini plus FP8 / GPTQ-Int4 / NVFP4 quantizations — no flagship weights. The linked GitHub repo could not be checked from this host (proxy-blocked), so its existence is unverified either way.
  • The word 'safety' does not appear in the paper — no safety, misuse, red-teaming or evaluation-integrity section, only a short paragraph on runtime guarantees.

Environment Scaling: three world families with different verification boundaries

File, search and code worlds share one task contract but differ in what can be trusted. File worlds are profession-conditioned, with difficulty varied by business-logic chain length and how much of the delivery contract must be inferred rather than copied — explicitly not by file count. Code worlds use cached base images plus per-task repository state, with both harvested (real-PR) and synthesized worlds.

  • Anti-reward-hacking is concrete: synthesized code worlds are probed to see whether a solver can obtain reward without completing the task, and only attacks that succeed in the sandbox count as verifier failures; scoring is isolated from the solver.
  • A trajectory is retained only if the initial state is reconstructible, execution is isolated, and the verifier can be replayed; the replay record includes world seed, generator version, tool versions, action/observation sequence, file deltas, verifier version and termination reason.
  • Construction principle stated as 'forward cheap, inverse expensive': the generator builds and solves from latent state; the agent sees only the rendered workspace.
  • No count is given for total environments, tasks or trajectories — the scenario registry figures are the only scale numbers for the environment corpus.

AgentOS and Agent Team: the harness details worth stealing

The most transactable part of the report. The runtime exposes three filesystem namespaces — read-only /inputs, working /workspace, and /outputs as the collection root — plus an optional read-only cross-run document library. Coordination state lives on an external task board outside the LLM context, periodically re-injected after compaction.

  • Task board items carry a stable id, owner set, dependency refs and a resolution state; 'resolved' is a coordinator semantic judgment deliberately decoupled from the runtime subagent lifecycle, so a subagent can be 'reported' while its item stays open.
  • Finalization gate: a normal final answer is accepted only when every active item is resolved or cancelled; with planning mode on, it additionally requires at least one delegated branch and one independent verifier to have run.
  • Delivery is a single-writer lease with an exact declared manifest; non-publishers are fail-closed on writes, entries are reconciled against a baseline snapshot at termination (so an empty or stale same-named file cannot satisfy the contract), and the terminal answer is checked for delivery claims the manifest does not cover.
  • Tiered compaction is triggered by provider-reported token usage, not a local estimate: tier 1 evicts old tool-observation bodies while protecting fan-in reports; tier 2 (LLM summarization) fires only if measured relief was insufficient.
  • Budget exhaustion is graceful: a soft deadline plus an outer hard timeout, with a bounded tool-free finalization call to recover a partial result. Hard cancellation is a last resort.
  • Verification is deliberately asymmetric: a verifier gets one claim, its evidence and the applicable constraint, and is asked to attack it — not to re-solve the problem.
  • Stated harness limits: the publication guard is tool-level, not a syscall-level monitor, and the coordination plane is run-scoped and not atomically checkpointed with the workspace filesystem.

Training: SFT soup + PIVOT-RL

SFT normalizes multi-domain data into a common stateful interaction schema, filters trajectories with invalid tool interactions or incomplete delivery, and merges per-domain variants via model-soup. PIVOT-RL uses retrospective analysis to find pivots where the model started down an unproductive path, preserves the useful prefix, restores executable environment state, and constructs a localized continuation with a short corrective hint that is never a prediction target and is absent at inference.

  • Zero numbers are given for training: no dataset sizes, trajectory counts, GPU-hours, RL steps, hyperparameters or reward weights.
  • RL scaling trends are shown as a figure with no axis values reported in the text.
  • There is no ablation isolating Environment Scaling from Agentic Coordination Scaling, and no PIVOT-RL ablation against a plain outcome-reward baseline — the paper says outright that its process rubric does not isolate the causal contribution of any individual component.

Results: what is measured, and how much of it is self-produced

Two modes are reported throughout — ReAct (minimal scaffold, meant to expose the model policy) and Agent Team (trained coordination plus more organized compute). The Agent Team lift is the core empirical claim, but the evidential quality of the comparison rows varies a lot and the captions say so.

  • Self-reproduced by the authors, not vendor-reported: ALL external-model GDPVal entries, the Claude-Opus-5 APEX-Agents result (42.3), and the DeepSeek V4 FrontierFinance entries. Only the external YC-Bench figures come from a public leaderboard.
  • The harness confound is surfaced rather than hidden on the internal research benchmark, which carries an explicit Harness column: Apodex 1.1 w/ Agent Team scores 12.4% in the authors' own FrontierAgent harness while Apodex 1.1 in Claude Code scores 10.3%.
  • Harness is NOT disclosed for the coding table, and the caption says the highest reported score is kept where multiple settings exist.
  • The two internal benchmarks are unreleased, so the best headline result (69.1, beating GPT-5.6-Sol's 67.4) is not externally reproducible — though the paper states the search benchmark's construction, ground truth and scorer were completed before and independently of all evaluated runs.
  • No cost or token accounting anywhere for the Agent Team lift. The only latency data are two appendix case studies: 82.4 min wall-clock / 864 recorded steps, and 24.7 min / 324 steps.

Key findings

  • The Agent Team scaffold, not the base policy, carries the headline results: +4.1 APEX-Agents, +9.3 GDPVal, +5.6 FrontierFinance, +8.3 FrontierScience-Research, +11.8 BioMysteryBench, +12.1 FrontierSearchBench over the same model in ReAct — with no cost, token or latency accounting for that extra compute.
  • Only the 35B mini weights appear to be released (HuggingFace lists mini plus FP8/GPTQ-Int4/NVFP4 quantizations); the 397B flagship is API-only, so the headline numbers cannot be reproduced by a third party even in principle.
  • Concrete, reusable harness mechanisms: three-region filesystem namespace; an external task board whose coordinator-owned resolution state is decoupled from the subagent lifecycle; a finalization gate requiring all items resolved plus a delegated branch and an independent verifier; a single-publisher lease with manifest reconciliation against a baseline snapshot; provider-token-triggered tiered compaction; and soft-deadline consolidation instead of hard cancellation.
  • Asymmetric verification is presented as the fix for verifier context pollution — give the verifier one claim plus its evidence and ask it to falsify, rather than re-solving the task.
  • Coding is the clear weak spot: 70.8 on Terminal-Bench 2.1 and 77.7 on SWE-bench Verified, both well under Claude Opus 5 / Gemini 3.6 Flash, and both reported without a stated harness.
  • On the authors' own research benchmark every system is bad — the best reaches 20.6% full-credit pass rate — and Apodex scores 12.4% in its own harness vs 10.3% in Claude Code, a scaffold delta the paper is transparent about.

Notable quotes

The current registry spans 33 domains, 318 occupations, and 1,208 deliverable clusters, with the angle layer producing distinct tasks within an occupation.
The asymmetry is in the task, not necessarily in model size.
Scores should therefore be interpreted as within-panel system comparisons rather than compared directly across panels; Deep Discover should not be read as a strictly matched single-run model ablation.
Reliably completing a specified scientific workflow and delivering every required artifact therefore remains challenging for all evaluated systems.

Limitations

  • All Apodex numbers are self-reported with no independent leaderboard entry, and every external GDPVal number, the Claude-Opus-5 APEX-Agents number and the DeepSeek V4 FrontierFinance numbers are the authors' own reproductions under the Apodex harness — a reproduction-quality risk that runs in the incumbent's disfavor by construction.
  • The ReAct-vs-Agent Team comparison confounds trained coordination with simply spending far more inference compute; no token, wall-clock or dollar cost is reported, so the lift cannot be normalized per unit compute, and there are no ablations separating Environment Scaling from Coordination Scaling or testing PIVOT-RL.
  • No architecture, pretraining data, compute budget or context length is disclosed; two of the most favorable results come from unreleased internal benchmarks; and the paper contains no safety, misuse or red-teaming discussion at all.

Open questions

  • How much of the Agent Team lift survives a compute-matched baseline (best-of-N, or a longer single-agent ReAct budget) rather than a scaffold-vs-scaffold comparison?
  • Since the report's own table shows a ~2-point swing between FrontierAgent and Claude Code for the same model, how much of every other reported number is harness rather than policy?
  • Do the AgentOS mechanisms help a model that was NOT trained on coordination traces — i.e. are they portable harness wins, or co-adapted with training?
