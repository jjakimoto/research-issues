    EverMine: Dissecting the Self-Evolution of Research Capabilities in Long-Horizon Alpha Research

    Read full article →View on GitHub

    Topic: Quantitative trading; machine learning for quant & trading; agentic coding techniques; LLMs & multimodal LLMs; and autonomous research (autoresearch / AI-scientist) systems — methods, papers, tools
    Date: 2026-10-02

    Source: arxiv · 2026-09-27
    Link: https://arxiv.org/abs/2609.33524

    This is a controlled test of whether an LLM alpha-mining agent that writes and reuses its own skills, tools and research rules beats one whose capabilities stay frozen. Under matched budgets the answer was no: across 18 long runs and 48 matched-state branches, every Evolving-minus-Fixed difference in portfolio IC had a 95% interval spanning zero. The case audits also show self-written screening thresholds discarding factors with positive marginal value. Anyone building a self-improving researcher should adopt the method: branch from the same history and portfolio, then swap only the capability state.

    Executive summary

    EverMine splits an autonomous alpha-research run's state into three parts: research history (Hist), the current factor portfolio (Frontier), and reusable capabilities (Cap: skills, tools, procedure documents). It then measures self-evolution three ways. First, end-to-end runs with a frozen Cap0 (Fixed) versus a writable Cap (Evolving) under identical multi-resource budgets. Second, checkpoint branches that hold Hist and Frontier fixed and swap only Cap. Third, replays of real screening decisions from restored platform states. On 10-minute Binance spot data (U60 universe, AlphaGen-style 30-factor pool scored by portfolio IC, OOS window held out), neither the end-to-end comparison nor the Cap swap showed a consistent gain from accumulated capabilities. Parameter tuning of existing formulas still added net IC in 16 of 18 runs, and a factor's marginal value often flipped sign depending on portfolio state and submission order.

    Problem: does self-evolution help when the frontier keeps moving?

    In long-horizon alpha research, a new factor's value depends on what the current portfolio already covers. Every accepted factor therefore changes the remaining search space, so a rule learned at one portfolio state may not hold at a later one. The authors argue that comparing only final endpoints mixes the effects of history, portfolio and capabilities, because all three evolve together. The value of accumulated capabilities has to be measured from the same research state. Experience-based screening also creates blind spots, because screened-out candidates never get evaluated.

    • Marginal gain is defined as Q(Frontier ∪ {candidate}) − Q(Frontier), using a shared update algorithm. The same candidate's gain therefore differs across portfolios.
    • Q is portfolio IC: the time average of the per-bar cross-sectional Pearson correlation between the combined signal and the next 10-minute close-to-close return.
    • The research question is whether capabilities that are explicitly saved and reused keep improving later research on an evolving predictive frontier.

    State decomposition and agent loop

    Each run (a 'Session') is one agent in its own container and file system, built on the DeepSeek Harness runtime. The agent reads the portfolio, past experiments and platform feedback. It then forms hypotheses, writes expressions in a shared factor language and submits them to the evaluator through a shared submission interface (evermine-submit). Hist covers conversation, hypotheses, candidates, feedback, failure evidence, and working files such as memory/research/scratch. Frontier is the portfolio and the information it already covers. Cap is the .agents/skills, procedure and tools directories plus the capability-version records. The Evolving condition adds a capability taxonomy with six judgment dimensions (market mechanism, measurement/representation, current portfolio gaps, test design, belief updating, attention/budget) plus engineering support. It also gets versioned create/save/load/revise/disable interfaces. Every resource must record its applicable context, the action it is expected to change, supporting and opposing evidence, and failure conditions.

    • Fixed still has the full continuous context, history, shared skills and feedback. It can switch factor families and revise hypotheses; only the explicit Cap is frozen.
    • A status query (runtime-status) returns a read-only snapshot plus a frozen, condition-blind protocol reminder that self-defined local thresholds cannot replace platform evaluation.
    • In the checkpoint swap, both Cap_t and Cap_0 are frozen read-only after branching, while each branch grows its own Hist and Frontier.
    • Models: locally served Qwen3.8-27B (xhigh reasoning effort) and DeepSeek-V4.1-Flash via API (high), both with 262,144-token context. Runs took place September 20-24, 2026.

    Verifier grounding: how factors are scored

    Grounding is purely execution-based, with no LLM judge. Expressions run as factor tensors over OHLC, volume, turnover and VWAP, using rolling windows of 1-1024 bars, past-only Ref, and CSRank within the point-in-time universe. The evaluator follows AlphaGen. Each factor and the label are cross-sectionally standardized. On every candidate, all pool weights are jointly refit with L1-regularized least squares (lambda = 0.005). A candidate is rejected if its correlation with any existing member exceeds 0.99, and there is no minimum single-factor IC. When the pool exceeds 30 members, the smallest-|w| member is evicted. Evaluation uses deterministic CUDA in float32 on RTX 4090s. The universe is the top 60 Binance USDT spot pairs by prior-30-day turnover, rebalanced monthly. Development data cover 2025-01-01 to 2025-12-31; OOS covers 2026-01-01 to 2026-06-30. For OOS scoring, the development portfolio (members, directions, weights) is frozen and OOS labels are used only to compute IC. The agent never sees OOS results.

    • The only outcome metric is portfolio IC; single-factor IC, Rank IC and coverage are kept as diagnostics. There is no trading backtest, return, Sharpe or transaction-cost model.
    • Data: 52,560 development bars and 26,064 OOS bars, with 199 unique assets in total and about 99.78% market coverage.
    • Qlib supplies the calendar and dynamic instrument lists. The AlphaGen design is used for tensor execution and pool evaluation.

    Controlled comparisons and budgets

    The end-to-end comparison uses 18 independent trajectories: 6 Fixed and 6 Evolving for Qwen, and 3 Fixed and 3 Evolving for DeepSeek. Each run has a hard budget of USD 10 equivalent model cost, 1,000 submissions, 16 sandbox CPU core-hours, 10M output tokens, 10,000 successful responses, 100 GiB cumulative writes and 48 active wall-clock hours, and research stops when any one limit is hit. The capability swap uses the 6 Qwen Evolving runs as parents. It branches at 25% and 75% of joint-budget progress, defined as the maximum over resources of used/limit. Each branch runs with Cap_t and with Cap_0, twice each, for 48 branches. Each branch gets USD 3, 300 submissions, 4.8 CPU core-hours and 14.4 hours. A behavior analysis classifies the 8,215 post-capacity submissions as new structure, parameter tuning or exact resubmission. Separately, the authors replay screening batches from restored evaluator states.

    • The 18 runs logged 530.5 active hours and 8,774 candidate evaluations. 93.6% of submissions came after the pool first filled.
    • Qwen costs come from a frozen price card scaled to 0.6x official rates, calibrated on A800 utilization cost. DeepSeek uses its official API price.
    • Statistics: 95% bootstrap intervals over independent trajectories (end-to-end) or parent trajectories (swap), and exact permutation tests for pool geometry.

    Results

    End to end, Evolving minus Fixed IC (x1000) was +0.741 for Qwen in development and -0.095 for DeepSeek. In OOS it was -0.391 for Qwen and -1.637 for DeepSeek, and all four intervals include zero. In the capability swap, accumulated Cap_t was slightly worse than Cap_0 at 25% (-0.405 dev, -1.256 OOS) and roughly equal at 75% (+0.042 dev, -0.092 OOS), again with every interval including zero. Effects by parent trajectory were 2 positive and 4 negative at each checkpoint, and the two repetitions had opposite signs in 5 of 12 parent-checkpoint pairs. New structures supplied most post-capacity gain, while parameter tuning contributed 12.8%-40.0% of net improvement. In the screening audit, 4 of 11 screened-out candidates had positive standalone gain. Submitting all screened-out candidates in sequence still lowered final IC slightly in both batches, because 3 of the 4 positive candidates turned negative once earlier additions had changed the pool.

    • Resource use (DeepSeek Fixed vs Evolving): 5.80 vs 16.00 CPU core-hours, USD 2.34 vs 4.30, and 1,000 vs 642 evaluations. All Evolving runs stopped at the CPU limit, while all Fixed runs stopped at the submission limit.
    • Qwen runs were mostly limited by model cost (5 of 6 per condition): USD 9.45 vs 9.32, and 346.0 vs 295.3 evaluations.
    • Cap_t - Cap_0 behavioral deltas at 25%: -0.490 effective factor families, -4.192 pp share of submissions that improve IC, and +3.523 pp family switches after a rejection. All intervals include zero.
    • In pool geometry, no overall Evolving-vs-Fixed difference was significant. In an exploratory family analysis, Qwen Evolving pools moved away from short-horizon price-change signals (-0.1021 affinity, p=0.0043).

    Significance and fragility flags

    For builders of autonomous research agents, the main contribution is methodological. The checkpoint swap (same Hist and Frontier, different Cap) is a cheap counterfactual that separates 'the system got better' from 'the saved skills helped', and the replay audit evaluates what a learned rule actually pruned. The null result also warns that a mandatory, well-structured evidence protocol for capabilities does not by itself turn experience into gains. The paper raises several fragility issues itself. Samples are small: 6 and 3 trajectories per condition, and the authors caution that the DeepSeek intervals give limited support for nominal 95% coverage. Pretraining contamination means the OOS split is not evidence of post-training temporal generalization. The behavioral analyses and replay batch selection were post hoc. Marginal value is highly path-dependent, so standalone IC gain is a misleading audit signal.

    • Overfitting angle: all search, tuning and screening use the same 2025 development IC. Gains in the late portfolio are on the order of 1e-5 to 1e-4 IC, and final outputs correlate 0.97-0.995 with their own starting portfolios.
    • Of 777 matched resubmission pairs with usable gains on both submissions, 50 of 178 initially negative pairs turned positive and 79 of 311 initially positive pairs turned negative. The same formula's value moves with the pool.
    • Scope: a single asset class (crypto spot), 10-minute horizon, a fixed-capacity linear pool, and IC only. There are no transaction costs or tradable P&L.

    Key findings

    • No end-to-end gain from capability evolution. Evolving minus Fixed final IC (x1000) was +0.741 for Qwen and -0.095 for DeepSeek in development, and -0.391 and -1.637 in OOS. All four 95% intervals include zero.
    • Swapping only the capability state at matched Hist/Frontier also showed no benefit. tau_cap (x1000) was -0.405 at 25% and +0.042 at 75% in development, and -1.256 and -0.092 in OOS, with every interval spanning zero.
    • Most work happens on a full pool: 93.6% (8,215) of submissions came after the pool first reached 30 members. Of these, 5,075 were new structures, 2,318 parameter tunes and 822 exact resubmissions. Parameter tuning had a positive net contribution in 16 of 18 runs and supplied 44 of the 201 gains above 1e-4. None of the 818 known exact-resubmission outcomes cleared that threshold.
    • Self-written screening rules (for example, residual IC of at least 0.0015, or single-factor IC of at least 0.012 with the same sign in all four quarters) dropped 11 of 12 candidates, and 4 of those 11 had positive standalone gain. Submitting every screened-out candidate in sequence still lowered final IC by 1.749e-5 and 6.66e-6, and 7 of the 11 changed the sign of their marginal gain depending on position in the sequence.
    • Capability evolution can cost resources. DeepSeek Evolving used 16.0 vs 5.8 CPU core-hours and hit the CPU cap after 642 evaluations, versus 1,000 for Fixed. Under Qwen, Cap_t branches showed a non-significant -4.2 to -7.8 pp drop in the share of submissions that improve IC.

    Notable quotes

    Most research therefore takes place while an existing portfolio is already present.
    Familiar formula structures can therefore retain useful portfolio value for further research.
    Independent value at the original state and realized value under sequential submission therefore answer different questions.
    The behavioral analyses are exploratory analyses conducted after inspecting the main results.

    Limitations

    • Statistical power is small: there are 6 trajectories per condition for Qwen and only 3 for DeepSeek, and the swap uses 6 parent runs. Repetitions disagreed in sign in 5 of 12 parent-checkpoint pairs, and the authors say the DeepSeek bootstrap intervals give limited support for nominal 95% coverage.
    • The OOS window (H1 2026) is held out from the agent loop but may not be unseen by the models' pretraining, so it is not evidence of temporal generalization. The behavioral and replay analyses are post hoc and cover only 3 hand-verified batches from 2 trajectories.
    • The evaluation is narrow: IC of a fixed-capacity linear factor pool on 10-minute crypto spot data, with no transaction costs or tradable returns. Both branches of the swap can still read past evidence through Hist, so skills, tools and procedure documents are not isolated individually.

    Open questions

    • Would capability evolution pay off with stronger models, longer budgets, or capabilities tied directly to portfolio feedback? The authors propose tracking when a judgment is applied and which factors it causes the agent to continue or abandon.
    • Final OOS IC is well above development IC for both conditions (about 0.088 vs 0.061 for Qwen and 0.10 vs 0.068 for DeepSeek). How much of the measured OOS quality reflects the 2026 regime or universe rather than research skill, and would conclusions hold under a tradable, cost-aware backtest?
    • Given strong path dependence (marginal values flip sign with pool state and submission order), what screening or re-evaluation policy maximizes realized portfolio gain rather than standalone candidate gain?
